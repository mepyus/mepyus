## Core Philosophy

VectorFL should not become a generic automation wrapper.

VectorFL should behave like a space-grounded maturation system:

```text
input enters space
space preserves provenance
guards classify pressure
receipts make evidence reviewable
reviews prevent false promotion
modules emerge only from repeated bounded use
user remains permission/promotion authority
```

## Non-Negotiable Principles

1. Source before answer.
2. Shared space before private tool memory.
3. Receipt before trust.
4. HOLD before authority.
5. Review before promotion.
6. Local/no-model proof before external model execution.
7. Fixture before live DB mutation.
8. Read-only surface before write UI.
9. Candidate pattern before reusable module.
10. User approval before any promotion/authority mutation.

## Practical Checklist For Every New Function

Before a function can be treated as a module candidate, answer:

```text
what input does it accept?
which source file/space does it read?
which exact output does it write?
what receipt proves it ran?
what negative case makes it STOP?
what state did it mutate?
who reviewed it?
what is it valid for?
what is it explicitly not valid for?
what remains HOLD?
```

## Tool Role Guard

### Hermes

Allowed:

```text
bounded local execution
tests/validators
receipt/log creation
packet-bound Codex/Gemini invocation after approval
```

Must not:

```text
become VectorFL authority
promote outputs
mutate live DB without approval
mutate baseline/schema/registry/workflow
```

### Codex

Allowed:

```text
contract review
overclaim audit
candidate/component boundary classification
next-smallest-action recommendation
```

Must not:

```text
auto-promote
approve authority mutation silently
turn review into implementation permission
```

### Gemini

Allowed:

```text
broad scan
asset archaeology
gap discovery
label/user-surface suggestions
```

Must not:

```text
be treated as truth
authorize implementation
mutate repo/Obsidian files
promote candidate material
```

## Repeated-Use Evidence Requirements

For personal-program completion and module extraction, every claim should be supported by:

```text

receipt
validator/test output

read-only surface evidence
Codex review-only check when structural risk exists
Gemini scan only as candidate exploration
```
