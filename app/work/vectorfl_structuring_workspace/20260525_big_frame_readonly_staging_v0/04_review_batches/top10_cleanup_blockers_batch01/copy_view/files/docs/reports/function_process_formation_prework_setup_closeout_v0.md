## 2. Why This Exists

The core problem was not external-material processing by itself.

The core problem was that records do not mature by being stored.

Line / axis / lens / camera material does not grow merely by accumulation.

Prior records must be:

```text
retrieved
reread
compared
reused
bounded by role/purpose
returned to User judgment
```

Otherwise, records become archive.

If they are promoted automatically, they become unsafe.

The closeout preserves this core conclusion:

```text
The object is not external-material processing itself.

The object is the reusable process by which a possible material/tool/function/API/repo/agent is read inside the space, connected to prior records, turned into a process asset, given a reuse hook, and returned to the User through a decision gate.
```

Key sentence:

```text
Structure is not organizing records neatly.
Structure is making previous records reusable as material for the next judgment and execution.
```


### 3.1 Function Candidate Card

Purpose:

```text
Name what arrived, why the User brought it, what role it might play, what risk it carries, and what must not be inferred.
```

### 3.2 Prior Record Retrieval

Purpose:

```text
Retrieve enough relevant prior records to avoid starting from zero.
```

v1 adds:

```text
retrieval_scope_boundary
```

Reason:

```text
"Retrieve prior records" can otherwise become "reread the whole space."
The boundary keeps retrieval tied to the current candidate's role and purpose.
```

### 3.3 Process Asset Unit

Purpose:

```text
Record the evaluation process itself as the reusable asset, not only the final output.
```

### 3.4 Reuse Hook

Purpose:

```text
Define when this prework record should be brought back later.
```

Boundary:

```text
Reuse Hook is not a router.
```

### 3.5 User Decision Gate

Purpose:

```text
Return adoption, promotion, implementation, attachment, current-position update, and authority changes to the User.
```

## 5. Re-entry Rule

Use this prework only when a material/tool/function/process may become reusable inside the space.

Do not use it for:

```text
quick summary
one-off answer
no reuse value
unnecessary overhead
user explicitly says not to structure it
```

Minimal internal question:

```text
Is this just a one-time task,
or is this a candidate process/function/tool that should be formed inside the space for future reuse?
```

If one-time:

```text
do not invoke this prework
```

If reusable:

```text
apply the v1 prework lightly
preserve the User decision gate
```
