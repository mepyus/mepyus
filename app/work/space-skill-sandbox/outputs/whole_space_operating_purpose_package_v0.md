## 2. Core Purpose

우리는 거대한 문서 저장소를 만드는 것이 아니다.

사용자의 목적과 판단을 중심으로,
공간 안의 기록·실패·외부자료·실행흔적을 렌즈와 카메라로 다시 읽고,
Codex / Gemini / CLI 같은 worker를 역할과 권한 안에서 움직이게 하며,
그 결과를 current-position / process-memory / line-axis / reusable settings로 환류시키는
재진입 가능한 사고·작업 운영 공간을 만들고 있다.

Short purpose:

```text
공간이 기억하고,
worker가 안전하게 움직이고,
결과가 다시 방향으로 돌아오는 구조를 만든다.
```

## 5. Role Model

```text
User = 결정 담당 / 목적 설정 / 최종 통제
ChatGPT = 검증 담당 / 방향 점검 / 철학·원칙 위반 감지
Codex = 설계 담당 / 구조화 / 패키지화 / 문서화 / 정렬
Gemini = 실행 담당 / 관찰 / 읽기 / 반복 실행 / evidence 반환
```

Role boundaries:

- User owns final direction and approval.
- ChatGPT validates direction, philosophy, principle fit, and detects overreach / over-promotion / role drift.
- Codex structures the user's purpose and ChatGPT validation criteria into packets, notes, reviews, and candidate documents.
- Gemini executes bounded reading / observation / compact execution and returns evidence.

Prohibitions:

- ChatGPT is not the direct executor.
- Codex does not create baseline, policy, automation, controller, or router.
- Gemini is not designer, approver, or promoter.
- Worker confidence is not authority.

## 9. Four Candidate Axes

These are candidate reading lenses.

They are not final axes, baseline, ontology, graph, schema, workflow, architecture, or source-space policy.

### Harness-Orientation

- reading angle: before worker action, identify the operating environment, role boundary, approval gate, and stop condition.
- protects: worker capability from becoming authority.
- internal example: `current_position_handoff_package_033_candidate_evidence_v0.md`
- watch item: full-mode heaviness; handoff example becoming workflow.
- must not be mistaken for: controller, router, worker-control architecture, universal handoff rule.

### Affordance-Program

- reading angle: tools and programs are permissioned materials, not automatic solutions.
- protects: tool capability from becoming permission.
- internal example: `existing_program_affordance_trial_v0.md`
- watch item: old risk labels becoming confirmed facts; CLI/tool adoption drift.
- must not be mistaken for: tool adoption plan, MCP exposure, direct integration.

### Signal-Memory

- reading angle: failure, friction, run identity issues, and session loss are process-memory signals.
- protects: failure traces from deletion and authority confusion.
- internal example: `run_identity_correction_note_whole_space_handoff_checklist_v1_candidate.md`
- watch item: correction becoming schema/policy; quarantine becoming general rule.
- must not be mistaken for: run-ledger system, quarantine policy, automatic correction machinery.

### Provenance-Integrity

- reading angle: judgment must point back to source refs and authority status.
- protects: LLM fluency from manufacturing meaning.
- internal example: `operating_order_source_map_v0.md`
- watch item: source map becoming citation baseline or authority list.
- must not be mistaken for: source registry, graph, ontology, external source law.

## 13. CLI / External Tool Attachment Principle

We are not attaching CLI/tools by default.

Before any tool or CLI attachment, ask:

- who calls it?
- for what purpose?
- under what authority?
- which files/folders may it read?
- what must it not modify?
- where must it stop?
- where is the result recorded?
- who validates it?
- how does it reflux into the space?

This requires Affordance-Program + Harness-Orientation + Provenance-Integrity + Signal-Memory together.

Non-equivalences:

- tool capability is not permission
- CLI availability is not automation approval
- program existence is not integration target
- external reference is not adoption plan
