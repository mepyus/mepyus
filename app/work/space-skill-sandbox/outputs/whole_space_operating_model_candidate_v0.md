## 3. Core Operating Purpose

We are not building a giant document archive.

We are building a re-enterable thinking and working space where the User's purpose and judgment remain central; records, failures, external materials, and execution traces are reread through lenses and cameras; workers such as Codex, Gemini, and future CLI tools move only within role and authority boundaries; and results return into current-position, process-memory, line-axis, and reusable settings.

Short form:

```text
The space remembers.
Workers move safely.
Results return as direction.
```

## 4. Role Model

```text
User = decision / purpose / final control
ChatGPT = validation / direction check / philosophy and boundary guard
Codex = design / structure / packetization / review organization
Gemini = execution / observation / evidence return
```

Role boundaries:

- User remains final controller.
- ChatGPT validates direction and catches philosophy, role, and boundary drift.
- Codex designs structure, packets, scope definitions, reviews, and candidate records.
- Gemini executes bounded reads / observations and returns evidence.

Drift to prevent:

- ChatGPT collapsing into micro-instruction writer only.
- Codex becoming autonomous implementer.
- Gemini becoming designer, approver, or promoter.
- User approval being inferred from candidate evidence.

## 6. Space / Sandbox / Runtime / Registry Relation

### Space

Accumulated memory / philosophy / process / judgment / failure / recovery / direction layer.

The space includes reports, thought assets, current-position entries, closeouts, process-memory, line-axis materials, runtime traces, provenance records, and candidate/watch/baseline distinctions.

### Sandbox

Bounded experiment and observation layer.

It tests reading methods, lenses, cameras, worker behavior, failure recovery, and reusable settings.

Sandbox output is not source-space law.

### Runtime

Execution trace and operational residue layer.

Commands, receipts, Gemini runs, and observed outputs may support review but are not authority by themselves.

Runtime receipt does not equal approval.

### Registry / Manifest / Provenance

Source/provenance/manifest-related machinery or records.

They may support grounding, but must not be overread as official authority without bounded review.

Manifest existence does not equal authority.

Registry file does not equal universal truth.

## 9. Four-Axis Operating Position

The four axes are candidate reading lenses.

They are not final axes, baseline, ontology, graph, schema, workflow, or architecture.

### Harness-Orientation

- reading angle: worker action must be bounded by environment, role, authority, and stop condition.
- protects: model capability becoming authority.
- internal example: `current_position_handoff_package_033_candidate_evidence_v0.md`
- operating effect: puts harness before worker execution.
- watch item: handoff/example becoming workflow or controller design.

### Affordance-Program

- reading angle: tools and programs are permissioned materials, not automatic solutions.
- protects: tool capability becoming permission.
- internal example: `existing_program_affordance_trial_v0.md`
- operating effect: prepares future CLI/tool attachment through caller, permission, and forbidden-use checks.
- watch item: tool/CLI adoption drift or old risk labels becoming current confirmed facts.

### Signal-Memory

- reading angle: failure, friction, run identity problems, and session loss are process-memory signals.
- protects: records from deletion and authority confusion.
- internal example: `run_identity_correction_note_whole_space_handoff_checklist_v1_candidate.md`
- operating effect: preserves correction traces and re-entry memory.
- watch item: correction practice becoming run-ledger schema or quarantine policy.

### Provenance-Integrity

- reading angle: judgment must point to source refs and authority status before fluent synthesis.
- protects: LLM-manufactured meaning and external source authority drift.
- internal example: `operating_order_source_map_v0.md`
- operating effect: keeps external lenses as bounded support, not internal law.
- watch item: source maps becoming citation baseline, registry, graph, or ontology.

## 10. Current-Position and Process-Memory Function

Current-position entry = compact re-entry anchor.

Process-memory = preserves why decisions happened, not only what happened.

Correction / VOID / quarantine = preserve record while separating authority.

Watch items = prevent premature closure or promotion.

Core principle:

```text
Records are preserved.
Authority is separated.
```

This means failed or invalid records may remain useful as process memory, but they do not become sequence evidence or authority unless explicitly accepted.

## 12. Worker Attachment Principle

Future CLI / external tool attachment must pass these questions before use:

```text
Who calls it?
For what purpose?
With what authority?
Which files/folders may it read?
What must it not modify?
Where must it stop?
Where is the result recorded?
Who validates the result?
How does the result return to the space?
```

Non-equivalences:

- tool capability != permission
- CLI availability != automation approval
- program existence != integration target
- external reference != adoption plan

This section prepares future attachment thinking only. It does not approve tool use.
