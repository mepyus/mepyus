## 2. Reset Decision

```text
Codex should focus on structure, design, packetization, pipeline shape, result packaging, and integration-engine-oriented process design.
Gemini should handle bounded execution, repeated reading, observation, mechanical checks, test passes, and evidence return.
ChatGPT should validate direction, role drift, and philosophical alignment.
User remains final purpose setter and decision gate.
```

In this setup, "Gemini validation" means bounded observational/mechanical validation only.

It does not mean:

```text
Gemini verified truth
Gemini approval
Gemini package movement
Gemini source-space authority
Gemini autonomous next-purpose selection
```

## 3. Why This Reset Is Needed

The first Queue 001 test proved a useful thing:

```text
Gemini can process a bounded external-material task sequence without requiring manual "next" for every subtask.
```

But it also exposed a limitation:

```text
Queue 001 mostly operated outside the full space process.
It read one external material, returned evidence, and produced process-memory-light.
It did not yet drive the internal space process through intake, lenses, cameras, line/axis placement, candidate reference handling, watch-item handling, and recovery.
```

The desired direction is therefore not "Codex runs more tests."

The desired direction is:

```text
Codex designs the durable process.
Gemini executes bounded evidence passes inside that process.
Codex packages the returned evidence into space records.
User/ChatGPT judge only the points that require purpose, authority, adoption, promotion, or direction.
```

## 4. Correct Role Split

| Actor | Primary role | Can do | Must not become |
|---|---|---|---|
| User | purpose / final decision | select direction, approve promotion, stop, redirect | hidden automation delegate |
| ChatGPT | direction validation / role drift check | review meaning, preserve philosophy, help decide next purpose | executor or source-space authority |
| Codex | structure / design / packetization / packaging | design queues, packets, state models, intake pipeline, result packaging, closeouts | autonomous implementer, Gemini router, approval authority |
| Gemini | execution / observation / repeated reading / evidence return | read sources, run bounded checks, return evidence and uncertainty, test packets | verified truth source, designer, approver, autonomous agent |
| CLI | bounded command tool | execute explicit commands when approved | permission source or automatic engine owner |

## 5. What Codex Should Do From Now On

Codex should prioritize:

```text
pipeline design
durable artifact layout
queue state shape
task packet shape
result bundle shape
space intake structure
lens / camera / line-axis pass structure
recovery path rules
watch item carry-forward rules
current-position update conditions
integration engine boundary design
```

Codex should not spend its main effort on:

```text
reading full external source content when Gemini can do it
manually repeating Gemini-style source analysis
running broad tests itself
turning a successful test into workflow by habit
executing Gemini tasks without User-approved handoff
```

Codex may read enough source context to design or package safely, but the default heavy-read path should move to Gemini evidence packets.

## 6. What Gemini Should Do

Gemini should receive bounded packets for:

```text
source reading
claim extraction
term extraction
evidence mapping
uncertainty reporting
mechanical validation
repeat checks
test execution
lens-specific observations
camera-style capture summaries
line-axis candidate evidence
watch risk extraction
```

Gemini must return:

```text
evidence
uncertainty
source references if available
blocked states
watch items
next_safe_action
```

Gemini must not return:

```text
approval
verified truth
baseline promotion
policy creation
workflow creation
package movement
current-position update
implementation authority
```

## 7. Correct External-Material Space Pipeline Target

The target is not:

```text
external URL -> Gemini summary -> process-memory-light
```

That was only the first proof.

The target pipeline should be:

```text
User-provided material
-> material gate
-> space intake record
-> Gemini source evidence pass
-> lens pass
-> camera/capture pass
-> line-axis placement pass
-> role classification
-> watch item extraction
-> candidate reference / process-memory / reusable-setting decision
-> Codex packaging
-> User/ChatGPT decision gate
-> closeout or current-position update only if required
```

## 10. Integration Engine Consideration

The future integrated engine should not be an autonomous agent.

It should be considered as a controlled process surface that can help:

```text
generate queue instances from User-provided material
prepare Gemini packets from Codex-designed templates
track queue state
collect Gemini result bundles
surface blocked states
help Codex package results into process-memory / watch / candidate-reference records
```

It must not:

```text
decide User purpose
approve adoption
promote baseline
create official workflow by existing
route workers autonomously
apply Gemini results automatically
update current-position automatically
move packages
```

## 11. Stop / Decision Gates

Gemini or the future engine must stop when:

```text
source is missing
scope is ambiguous
User decision is required
authority risk appears
promotion risk appears
implementation is required
package movement is implied
current-position update is required
next purpose is needed
```

Codex should package the blocked state and return it to User/ChatGPT review.
