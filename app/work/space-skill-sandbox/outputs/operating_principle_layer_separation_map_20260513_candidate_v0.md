# Operating Principle Layer Separation Map
# 2026-05-13 Candidate v0

## 1. Status

Document:
  candidate operating layer separation map

Authority:
  orientation / implementation prep only

Not:
  baseline
  workflow
  registry
  schema
  automation
  current-position
  output_manifest
  final operating model

Placement:
  RETURN_TO_SPACE_VALUE_WITH_WATCH

## 2. Purpose

Separate the new operating principle into implementable layers so that:

- ChatGPT can keep the large frame
- Codex can implement structure
- Gemini can execute / observe
- User can remain final judge rather than relay worker

## 3. Layer Map

### L1. Meaning Layer

Question:
  What does this input / structure mean?

Owner:
  User + ChatGPT

Primary terms:
  Camera
  Lens
  Line
  Axis
  Judgment
  Thought Flow

Codex role:
  Does not decide meaning.
  Implements approved structure.

Gemini role:
  Observes and returns evidence.
  Does not become final authority.

Failure condition:
  meaning terms are treated as repo structure or execution command.

### L2. Principle Layer

Question:
  Under what operating principle should work move?

Owner:
  User + ChatGPT

Primary terms:
  original deep
  surface thin
  sandbox light
  recovery accurate
  candidate != baseline
  return != truth
  next pull != automatic task

Codex role:
  Preserves principle boundaries in structure files.

Gemini role:
  Executes within principle boundaries.

Failure condition:
  principle becomes rigid doctrine, workflow, or automation rule.

### L3. Structure Layer

Question:
  How are principles represented as files / folders / packets / cycles?

Owner:
  Codex

Primary units:
  relay board
  packet
  cycle
  work_order
  request_queue
  supervisor_checkpoint
  cycle_return
  skeleton
  recovery file

Failure condition:
  structure becomes workflow, registry, current-position, baseline, or authority.

### L4. Execution Layer

Question:
  Can the structure be used to execute / observe?

Owner:
  Gemini

Primary units:
  gemini_work_order.md
  Gemini cycle return
  evidence return
  structural gap detection
  Codex request entry

Failure condition:
  Gemini implements structure directly or treats observation as final authority.

### L5. Recovery Layer

Question:
  What from the return becomes usable space material?

Owner:
  ChatGPT + Codex + User

Primary units:
  raw return
  recovered judgment
  placement
  WATCH
  HOLD
  next pull
  recovery record

Failure condition:
  raw return becomes memory, truth, approval, or baseline.

### L6. Re-entry Layer

Question:
  What thin surface should be read next time?

Owner:
  ChatGPT + User
  Codex implements files
  Gemini tests usability

Primary units:
  active surface
  cycle board
  current owner
  next manual transfer
  supervisor checkpoint

Failure condition:
  active surface becomes current-position, manifest, registry, or routing authority.

## 4. Cross-Layer Rule

Same word may appear in multiple layers.
The layer must always be named or inferable.

Example:
  pipeline in Meaning Layer != pipeline in Structure Layer != pipeline in Recovery Layer.

## 5. Do Not Promote

- layer map != schema
- layer map != workflow
- layer map != ontology
- layer map != baseline
- layer map != current-position
- layer map != automation plan

## 6. Watch

- layer separation becoming too heavy
- Codex treating layer map as schema
- Gemini treating layer map as execution command
- ChatGPT getting pulled into local edits
- User returning to relay-worker role
