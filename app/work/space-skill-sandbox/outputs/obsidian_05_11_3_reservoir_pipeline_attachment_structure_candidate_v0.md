## 2. Core Application

The space should remain a space.

That means:

```text
do not turn the original space into a product
do not turn the original space into a fixed pipeline
do not convert every asset into a registry entry
do not make the sandbox the main body
do not let a derivative overwrite the reservoir
```

The useful structure is:

```text
Original Space stays intact.
Pipeline attaches only when a purpose appears.
Pipeline pulls only bounded assets.
Derivative is tested outside the reservoir.
Result returns as judgment, watch, or reusable candidate.
User decides whether anything is promoted.
```

## 3. Operating Shape

```text
[Original Space / Reservoir]
  contains accumulated thought, judgment, failure, LACL, anchors, worker results, feedback

        |
        v

[Reservoir Access Gate]
  asks: why are we touching the reservoir now?
  output: selected purpose + boundary

        |
        v

[Asset Family Selector]
  asks: which kind of asset is being pulled?
  output: loose asset family, not registry identity

        |
        v

[Pump Attachment Frame]
  asks: which temporary port is active?
  output: one or more ports

        |
        v

[Temporary Pipeline / Pump]
  asks: what operation is needed now?
  output: bounded extraction / transformation / packet

        |
        v

[Sandbox Frame]
  asks: where can this be tested without changing the reservoir?
  output: derivative candidate

        |
        v

[Return Channel]
  asks: what comes back and with what authority?
  output: return placement + watch + next condition

        |
        v

[Original Space Deepens]
  only after recovery; no automatic promotion
```

## 4. Reservoir Access Gate

Before attaching any pipeline, ask:

```text
1. What is the user's current purpose?
2. Why does this need the reservoir rather than a one-off answer?
3. Which original-space area is relevant?
4. What must not be pulled?
5. What return route is expected?
```

Gate outputs:

```text
ALLOW_TEMPORARY_PUMP
ASK_USER_FOR_PURPOSE
HOLD_AS_RAW_MEMORY
USE_ONE_OFF_RESPONSE_INSTEAD
```

Boundary:

This gate is not a permission system. It is a scope clarification step.

## 5. Reservoir Asset Family Map

Use this map loosely:

| Asset family | Pull when the purpose needs | Must not become |
|---|---|---|
| Core Philosophy | direction, meaning, why this matters | policy or implementation command |
| Process Trace | how judgment formed, failed, corrected, or returned | full history crawl |
| Judgment Capsule | compact recovered decision unit | capsule registry |
| LACL / Camera / Lens | observation point and reading method | ontology |
| Mission Pattern | how Codex/Gemini/CLI were tasked | automatic router |
| Return Pattern | how outputs came back into space | ledger |
| Watch / Boundary | risks, non-promotions, drift warnings | law unless User promotes |
| Implementation Artifact | code, UI, preview, concrete trial result | proof of adoption |
| External Reference | outside material read through space criteria | imported authority |


## 6. Pump Attachment Frame

Attach through ports, not through global pipelines.

| Port | Pulls from reservoir | Typical pipeline attached | Return form |
|---|---|---|---|
| Philosophy Port | Core Philosophy | framing / purpose translation | candidate principle with watch |
| Judgment Port | Judgment Capsule | decision support / comparison | return-to-space value |
| Trace Port | Process Trace | process reread / mistake recovery | process memory light |
| LACL Port | Camera / Lens / Line / Axis | observation map / reading packet | lens or camera candidate |
| Mission Port | Mission Pattern | Codex/Gemini/CLI packet setup | mission packet candidate |
| Return Port | Return Pattern | worker result packaging | return placement |
| Boundary Port | Watch / Boundary | preflight / drift check | watch or hold |
| Artifact Port | Implementation Artifact | sandbox trial / UI or code inspection | experiment result with watch |

Rules:

```text
one purpose may use multiple ports
ports are temporary handles
ports are not APIs
ports do not imply permission
ports can be detached after the run
```

## 9. Sandbox Derivation Card v0

Use this card only when a derivative is being tested.

```text
Purpose:
  What is this derivative trying to do?

Pulled Assets:
  Which reservoir asset families are being pulled?

Active Ports:
  Which temporary attachment ports are active?

Transformation:
  How are pulled assets changed into a derivative?

Output:
  What concrete artifact appears? Document, map, app, packet, table, code, UI?

Boundary:
  What will this derivative not do?

Test:
  How do we know this derivative is useful?

Return:
  What returns to original space?

Watch:
  What drift risk remains?

Next Use:
  When should this derivative be reused, held, or discarded?
```
