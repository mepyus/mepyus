It is not a new autonomous engine. It is a candidate design for how Codex should periodically interpret accumulated worker evidence and mistake-memory into structural insight.

## 2. Why This Is Needed

The space is now producing:

```text
external-material evidence
Gemini result bundles
process-memory-light records
mistake-memory records
watch items
candidate references
overrun signals
packet-design improvements
```

If these are only stored, the space becomes an archive.

If they are automatically promoted, the space becomes unsafe.

The needed middle process is:

```text
periodic structural rereading
```

This means Codex uses accumulated evidence to ask:

```text
Are new line candidates appearing?
Are existing axes being clarified or stressed?
Are lenses/cameras changing?
Are repeated mistakes showing a packet design weakness?
Are overrun signals revealing a real structural question?
Are watch items clustering into a possible future rule?
What still requires User/ChatGPT judgment?
```

## 3. Correct Role Split

```text
Gemini = bounded execution / observation / repeated reading / mechanical checks / evidence return
Codex = structure interpretation / design synthesis / packet refinement / pipeline shaping / result packaging
ChatGPT = direction validation / role drift check / philosophical alignment
User = purpose / final decision / promotion authority
```

Codex may interpret patterns across outputs.

Codex may not:

```text
promote those patterns into baseline
declare official workflow
create policy/schema
approve adoption
move packages
grant Gemini authority
update current-position automatically
```

## 4. Important Distinction

Gemini overrun has two layers:

```text
1. Boundary layer:
   If Gemini goes beyond the requested task, that is a role/scope mistake.

2. Signal layer:
   The content inside the overrun may still contain a candidate signal for Codex to interpret.
```

Policy:

```text
do not trust overrun as authority
do not discard overrun automatically
separate overrun content into candidate signal
Codex may reinterpret candidate signal structurally
User/ChatGPT decide whether the interpretation matters
```

## 7. Pipeline Stages

### Stage 0 - Purpose Gate

```text
Owner = User / ChatGPT
Input = "run space-change reading pass"
Output = bounded scope
Stop if = no User purpose
```

### Stage 1 - Evidence Inventory

```text
Owner = Codex designs; Gemini may gather evidence if assigned
Input = recent run records, process-memory, mistake-memory, next-chat summaries, external-material results
Output = evidence inventory
Forbidden = broad source-space crawl unless explicitly scoped
```

### Stage 2 - Signal Separation

```text
Owner = Codex
Input = evidence inventory
Output = separated buckets:
  valid evidence
  mistake-memory
  overrun signal
  watch items
  candidate references
  unresolved decisions
Forbidden = treating any bucket as authority
```

### Stage 3 - Cluster Detection

```text
Owner = Codex, with Gemini mechanical support if needed
Input = separated buckets
Output = clusters such as repeated watch items, recurring packet weaknesses, repeated line-axis hints
Forbidden = promoting clusters into rules automatically
```

### Stage 4 - Lens / Camera Reread

```text
Owner = Codex structures; Gemini may fill evidence tables
Input = clusters and current lens/camera definitions
Output = lens/camera fit, stress, gap, or drift notes
Forbidden = lens becoming law or camera becoming truth
```

### Stage 5 - Line / Axis Synthesis

```text
Owner = Codex
Input = lens/camera reread outputs
Output = candidate line/axis changes:
  strengthen existing axis
  split axis candidate
  new latent line signal
  hold/no change
Forbidden = graph/ontology/schema promotion
```

### Stage 6 - Design Implication

```text
Owner = Codex
Input = line/axis synthesis and mistake-memory
Output = packet-design, intake-pipeline, integrated-engine design implications
Forbidden = implementation without User direction
```

### Stage 7 - Decision Gate

```text
Owner = User / ChatGPT
Input = Codex interpretation
Output = accept as candidate memory, request wording patch, hold, or select next purpose
Forbidden = automatic adoption
```

### Stage 8 - Recovery

```text
Owner = Codex after decision
Output = run record, process-memory-light, candidate reference note, watch carry-forward, or current-position update only if explicitly required
Forbidden = automatic current-position update
```

## 9. Overrun Signal Handling

When Gemini outputs content beyond its task:

```text
1. mark it as overrun
2. separate it from the valid result
3. record the role/scope mistake
4. extract possible candidate signals
5. Codex rereads those signals structurally
6. preserve only candidate interpretation
7. require User/ChatGPT review before any movement
```

Signal statuses:

```text
DISCARD_AS_NOISE
WATCH_ONLY
CANDIDATE_SIGNAL
NEEDS_BOUNDED_REVIEW
USER_DECISION_REQUIRED
```

## 12. What This Prevents

This pipeline prevents two failures:

```text
1. Archive failure:
   Data piles up but lines, axes, lenses, and cameras do not evolve.

2. Promotion failure:
   Interesting signals are promoted too quickly into rules, workflow, automation, or authority.
```

The desired middle path:

```text
signals become candidate interpretation
candidate interpretation becomes User-reviewable design option
only User decision can promote or move it
```
