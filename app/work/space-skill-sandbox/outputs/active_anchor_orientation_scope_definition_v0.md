## 3. Definitions

### Active Anchor

A candidate active anchor is a recent or currently relevant artifact that helps a future session recover current direction, authority state, operating lens, or next safe decision.

It may include:

- current-position entries
- recent closeouts
- purpose / direction packages
- line-axis synthesis references
- reusable settings catalog
- recent gap-signal verdicts
- recent Codex review records

It must not mean:

- official index entry
- registry item
- source of authority
- baseline
- routing table item
- task queue item

### Historical Residue

Historical residue is older or less active material that may remain valuable as thought asset, provenance, or context, but is not the first entry point for the current direction.

It must not mean:

- trash
- deprecated
- delete candidate
- invalid
- unimportant

### Orientation Candidate

An orientation candidate is a small reading aid that helps future sessions know where to look first.

It must not mean:

- index
- registry
- source map
- status database
- router
- schema
- docs cleanup plan

## 6. Selection Criteria

An artifact may be considered a candidate active anchor if it helps answer at least one:

- Where are we now?
- What has been closed?
- What remains candidate / watch / hold?
- What is the next safe direction?
- What must not be inferred?
- Which operating model or lens is currently relevant?
- Which reusable setting should be used?
- Which recent decision prevents drift?

Prefer artifacts that are:

- recent
- bounded
- explicit about candidate / reference status
- role / authority aware
- current-position or closeout related
- connected to line-axis / purpose / operating model
- useful for re-entry

Exclude artifacts that are:

- old without current relevance
- raw execution output without review
- broad reports without current anchor role
- baseline / core files
- runtime traces without review context
- implementation-implying materials
- under unresolved Package 034 / 035 / 036 movement
