| Axis | Reading angle | Current contribution | Main drift prevented |

## 4. Axis Notes

### 4.1 Harness-Orientation

Reading angle:

The work should first ask what environment, boundary, and role structure contains the worker before asking what the model can do.

Signals captured:

- v1 handoff checklist as boundary harness
- Package 033 brief as scenario-evaluation aid
- Light/Full mode distinction as context-sensitive harness choice
- User approval before continuation or promotion

Guardrails maintained:

- candidate reference before engine use
- role boundary before worker action
- current-position memory before continuation
- no controller/schema/automation conversion

Current status:

Harness-Orientation is the clearest current candidate axis from Runs 152-155.

### 4.2 Affordance-Program

Reading angle:

Programs and tools are not adopted as solutions by default. They are read as materials with affordances, caller risks, and permission boundaries.

Signals captured:

- external tools remain reference material
- allowed/forbidden actions matter more than feature lists
- tool capability does not equal permission to use

Guardrails maintained:

- no direct merge
- no auto-tooling
- no MCP/tool installation by implication
- no route/controller creation from tool enthusiasm

Current status:

Affordance-Program remains active as a supporting axis for future tool or CLI attachment work.

### 4.3 Signal-Memory

### 4.4 Provenance-Integrity

Reading angle:

Judgment must point back to durable source refs and declared authority status instead of being manufactured by fluent synthesis.

Signals captured:

Current status:

Provenance-Integrity is the strongest support axis for preventing axis hardening and source-authority drift.

## 5. Interlock Without Collapse

The axes overlap around containment and boundary discipline, but they should not collapse into one law.

- Harness-Orientation asks whether the worker is bounded.
- Affordance-Program asks what the tool or program is allowed to mean.
- Signal-Memory asks how the work survives failure and re-entry.
- Provenance-Integrity asks why a judgment is grounded.

Together, they help read the current space without requiring a graph, ontology, workflow, or engine simulation.
