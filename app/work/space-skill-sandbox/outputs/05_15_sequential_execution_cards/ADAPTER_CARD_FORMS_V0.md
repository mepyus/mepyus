## 2. Company Work Review Card

Use for:
  company document, instruction, email, report, customer reply, or work-use model output.

```text
검수 결과:

핵심 판단:

주의할 점:

빠진 근거/첨부:

지금 하지 말 것:

건드리는 범위:

다음 한 동작:
```

WATCH:
  Keep it practical, not a compliance checklist.

HOLD:
  no official approval flow
  no policy automation
  no customer-data handling

## 3. External Tool Packet Draft Card

Use for:
  Codex, Gemini, CLI, API, browser, or other tool pre-use review.

```text

task:

forbidden:

risk_focus:

return_format:

mode_conflict:
```

WATCH:
  Packet draft is not dispatch approval.

HOLD:

## 4. Blog Claim Check Card

Use for:
  blog outline, draft premise, source-backed explanation, SEO-sensitive content.

```text
검수 결과:

핵심 판단:

claim_level:
  note / candidate / tested_candidate / promoted_rule

근거 강도:
  weak / medium / strong

관찰 유형:
  direct_observation / inference / candidate_lens

소스 범위:
  excerpt_only / selected_sources / broad_corpus

주의할 점:

지금 하지 말 것:

다음 한 동작:
```

WATCH:
  Do not write candidate material as promoted truth.

HOLD:
  no automatic publishing
  no SEO pipeline
  no baseline prompt

  no production automation

WATCH:
  Reading guide is not official memory.

HOLD:
  no current-position update
  no output_manifest update
  no permanent memory write
  no official onboarding promotion

## 7. Use Rule

Use the smallest card that fits the work.
If a card starts becoming ceremony, downgrade to plain chat guidance.
If a card touches approval, publishing, execution, account, credential, API, browser, memory, or file-write boundaries, stop and require a separate explicit decision.
