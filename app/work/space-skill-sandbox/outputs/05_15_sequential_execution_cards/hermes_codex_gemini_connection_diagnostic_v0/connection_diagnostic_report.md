## 9. Gemini Execution Placement

### Codex-run Gemini

Strengths:

```text
simple authority chain
Codex sees the whole process
manual bridge remains clear
```

Risks:

```text
Codex carries runtime burden
Codex waits on Gemini
Codex must re-read too much raw output
broad checks become slower
```

Best when:

```text
task is small
manual clarity matters more than runtime efficiency
Codex needs direct control over every step
```

### Hermes-run Gemini with Codex recovery

Strengths:

```text
uses Hermes as runtime
keeps Codex as space/recovery worker
reduces Codex process-management burden
creates clearer receipt/report evidence
supports Level 1.5 to cautious Level 2 pilot design
```

Risks:

```text
Hermes-run command may be mistaken for automatic bridge
Gemini output may be mistaken for truth
Codex recovery check may be skipped
model API transport may be confused with live web/source lookup
```

Best when:

```text
Codex has already authored the Gemini request
input/output scope is bounded
one exact command is declared
model API transport scope is approved
live web/source lookup is forbidden or separately approved
Codex recovery remains mandatory
```

### Hermes-directed Gemini without Codex framing

Verdict:

```text
HOLD
```

Reason:

```text
Codex boundary framing is missing.
Hermes may over-summarize into authority posture.
Gemini may over-conclude.
VectorFL recovery classification can be bypassed.
```

Recommended default:

```text
Default to Codex-authored, Hermes-run Gemini with Codex recovery only for approved pilot packets.
Otherwise remain structured manual bridge.
```

```text
Dispatch approval is not transitive.
```


## 13. Network / API Boundary

Separate these three surfaces:

```text
model API transport:
  model call transport needed for Gemini/Codex/model CLI execution.
  allowed only if explicitly declared in dispatch approval.

live web/source lookup:
  browsing, search, source fetching, remote document reading.
  no unless separately approved.

external connector side effects:
  Slack, email, CRM, DB, Obsidian, messaging, write-side browser/app action.
  no unless separately approved.
```

Receipt should split:

```text
network_used: yes/no
model_api_transport_used: yes/no
live_web_lookup_used: yes/no
external_source_fetch_used: yes/no
network_used_for_other_reason: yes/no
browser_used: yes/no
MCP_used: yes/no
external_connector_used: yes/no
```

STOP rule:

```text
If a model command requires model API transport and dispatch approval says network scope is none, STOP.
If live web/source lookup appears without separate approval, STOP.
If external connector side effects appear without separate approval, STOP.
```
