## 6. Reverse Ontology Rule

Treat "reverse ontology" as:

```text
names emerging from repeated use,
not categories imposed from above.
```

A name is better if:

```text
it points to an existing repeated behavior
it has clear boundary
it helps the user issue shorter instructions
it does not require schema/registry/policy to be useful
it can be tested with real inputs
```

A name is worse if:

```text
it sounds official but lacks evidence
it hides multiple unrelated functions
it creates a new layer just because it sounds good
it turns a WATCH item into a rule
it makes 0-9 digits into ontology
```
