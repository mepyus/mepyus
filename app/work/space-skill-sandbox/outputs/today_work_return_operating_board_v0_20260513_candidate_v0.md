## 4. Recovered Judgments

- VectorFL Operating Board v0 should not begin as an app route or automation surface.
- The first useful form is a standalone manual operating surface.
- The board should show one input moving toward recovered judgment, not expose the whole repo structure.
- Web references support trace visibility, pause / resume, and human judgment gates, but do not require building a full AgentOps dashboard.
- Design references can change perceived precision and weight, but must not change authority or create product-dashboard drift.
- The useful center is:
  input

  pause reason
  human decision point
  recovered judgment
  WATCH
  HOLD
  next small action
