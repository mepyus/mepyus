## 5. When To Use Hermes

Use Hermes candidate carrier when:

- task is bounded.
- active surfaces are explicit.
- no secret or sensitive files are involved.
- no file modification is required.
- output can be returned as Worker Return Intake.
- mission can run as one `hermes -z` packet.
- result is intended as raw trace / candidate material.
- Codex/assistant will recover afterward.
- user remains final judge.

Good candidate tasks:

- one-file reading
- 2-5 file active-surface synthesis
- handoff boundary reading
- recovery-note lineage reading
- small status synthesis
- candidate evidence collection from explicitly listed files

## 6. When Not To Use Hermes

Do not use Hermes when:

- task requires broad repo search.
- task requires full corpus indexing.
- task requires source code modification.
- task requires config/memory/skill edits.
- task involves secrets, auth, state.db, logs with credentials, sessions, .env, auth.json.
- task requires baseline decision.
- task requires promotion judgment.
- task requires interpreting entire VectorFL space.
- task would create many micro-runs.
- task should remain Gemini broad-bounded synthesis.
- task should be Codex recovery/structure-only.
