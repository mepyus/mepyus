principle: 1차=전체 / 2차=각 기능이 전체 흐름 어디에 붙는지 테스트 / 3차=2차에서 누적 확인된 전체 내용을 기준으로 수정

## S1_INTAKE User original intake
- phase1 evidence: Hermes recognized user correction and preserved raw original.
- phase2 tests: original preservation, intent classification, space-affecting vs light-task gate
- phase3 revision basis: If repeated failures appear, revise intake gate globally.

## S2_SPACE_SELECTION Space evidence selection
- phase1 evidence: Codex added stable anchors/current-position as orientation/repeatability/drift evidence.
- phase2 tests: source-selection rule, space refs max/default, changed_judgment required
- phase3 revision basis: Revise source policy only after multiple function tests show missing/ref overload/conflict patterns.

## S3_HERMES_MERGE_EXECUTION Hermes original + space + model merge execution
- phase1 evidence: Hermes merge moved from internal fixture to actual VectorFL-like processing.
- phase2 tests: merge trace, space_reference_delta, why_not_model_only, execution receipt
- phase3 revision basis: Revise merge contract based on accumulated deltas and failure classes.

## S4_CODEX_EVALUATION Codex evaluates space refs + Hermes output
- phase1 evidence: Codex evaluated spatial delta/reentry artifacts and guard matrix values.
- phase2 tests: Codex assessment field, spatial delta review, reentry effect watch
- phase3 revision basis: Revise Codex role if assessments repeatedly duplicate Hermes or miss deltas.

## S5_GEMINI_LAYER_JUDGMENT Gemini evaluates structural/layer pressure
- phase1 evidence: Gemini added layer reading and speed-vs-depth tension.
- phase2 tests: Gemini layer questions, big-frame alignment, inward-collapse watch
- phase3 revision basis: Revise Gemini role if layer questions become generic or too internal.

## S6_OPERATOR_RECEIPT_REENTRY Operator receipt/reentry and HOLD
- phase1 evidence: Receipts remained evidence only; no authority/promotion.
- phase2 tests: HOLD receipt, operator status card, mind-sized output
- phase3 revision basis: Revise operator surface if overload or unclear next lanes recur.

## S7_BUDGET_GATE Fast/heavy budget gate
- phase1 evidence: Full heavy worked but was slow; later fast-first applied.
- phase2 tests: heavy trigger detection, fast continuation, post-review skip gate
- phase3 revision basis: Revise budget thresholds after session log shows under/over-escalation.
