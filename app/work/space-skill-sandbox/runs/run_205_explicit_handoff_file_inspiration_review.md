## 2. What the Idea Means

An explicit handoff file means that when one agent or worker finishes a bounded task, it leaves a readable transfer note for the next reader.

The note should explain what was done, what was not done, what remains risky, and what the next actor should or should not assume.

In simple terms:

```text
Leave a clear transfer note.
Make the next reader's starting point easier.
Do not make the note an approval, route, command, or automatic next step.
```

## 3. Closest Concepts in Our Space

- Codex report: summarizes what Codex structured, reviewed, or recorded
- Gemini observation result: returns bounded execution or reading evidence
- run records: preserve the specific action, verdict, stop point, and boundaries
- closeout notes: record what was closed and what remains watch-only
- current-position entries: preserve the latest safe re-entry point
- next-chat re-entry summaries: help the next chat resume without re-explaining everything
- handoff packets: define what a worker may read/do/avoid before execution
- user decision gate: keeps transfer notes from becoming permission to continue
- worker role boundary: separates design, validation, observation, and final approval

No new folders, schemas, automatic routing, or handoff protocol are proposed.
