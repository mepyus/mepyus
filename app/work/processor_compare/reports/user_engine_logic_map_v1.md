# User Engine Logic Map v1

## 0. One-Line Reading
The engine being pursued is not a fast answer machine but a structure that preserves weak possibilities, unresolved connections, and process traces so they can be re-read and reconnected later.

## 1. Repeated Metaphor Clusters

### A. Container Metaphors
- bowl
- space
- sea
- holding structure

Meaning:
- the engine should receive and hold unfinished material
- early deletion is more harmful than temporary ambiguity
- first purpose is containment and preservation, not closure

### B. Formation Metaphors
- point
- cluster
- connection line
- space

Meaning:
- single outputs matter less than accumulation
- repeated relation creates clusters
- thickened clusters become space
- space can later behave like a point in a larger structure

### C. Grounded-Join Metaphors
- anchor
- bridge
- junction
- flow

Meaning:
- connections need reasons
- anchor is the grip
- bridge is traversable connection
- flow is continuity across time

### D. Field/Workbench Metaphors
- agitator
- workbench
- site

Meaning:
- the engine is not only storage
- it is a local read/reassembly field
- comparison, holding, blockage, and retry all happen there

## 2. Engine Definition Read Through Those Metaphors

### A. The engine is not graph-first
- graph is projection
- body is ledger + layer
- local workbench is the local judgment field

### B. The engine is not right/wrong-first
- output is a directional anchor
- incomplete output can still be useful
- the engine should orient later judgment, not only finish it

### C. The engine is process-preserving
- result is temporary
- process can later reconnect
- replay/revisit/re-read matter more than one-shot closure

## 3. Input Philosophy

### A. New input is material, not topic
- new technologies, ideas, philosophy, and comparisons are engine material
- the key question is where they attach and what density they add

### B. Whole conversations are less important than flow extraction
- transition
- blockage
- attempt
- repeated anchor
- unresolved state
- revisit seed

### C. Weak signals must survive
- unknown
- weak
- contrast
- unresolved

These are not waste.
They are deferred assets.

## 4. Intended Judgment Style

### A. Detection is not enough
Current weakness is not noticing possibility.
Current weakness is following and closing it through:
- join
- trace
- continuation
- scenario

### B. Connection count is not the goal
What matters is:
- why the join exists
- what anchor repeats
- what local evidence supports it
- what can be re-read later

### C. Repeated expression should be treated as externalized judgment logic
The user's repeated metaphors are not decorative.
They expose the intended evaluation grammar of the engine.

## 5. Stable Purpose Summary
- prevent weak thoughts and unresolved links from scattering
- push process traces back into the engine as material
- prioritize long-term point/cluster/space formation over isolated answers
- use output as navigational anchor, not terminal truth
- let assistant/codex/agent/cli/web dialogue all become later engine material

## 6. Current Gap Reading
- persisted spine is still strongest on the source side
- workbench core still lives mostly in derived assembly
- mixed cases still show a source-local / translated-layer gap
- repeated user metaphors are currently compensating for logic the body does not fully persist yet

## 7. Reading Rule For Future Inputs
When reading future input, prefer this order:
1. what is the anchor
2. what cluster/flow can it join
3. does it thicken a point, cluster, or space
4. is it a structure fix or engine material
5. what process trace matters more than the result
