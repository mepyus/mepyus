## 6. Pipeline Shape

This pipeline is not an execution loop.

It is a trace-recovery shape around a bounded work episode.

```text
User Purpose
-> Thin Plan
-> Space Reading Trace
-> Work Package Trace
-> Execution Trace
-> Feedback / Mismatch Trace
-> Recovery Judgment
-> Next Condition
-> Return Record
```

## 7. What To Record At Each Stage

| Stage | Record | Why it matters | Must not become |
|---|---|---|---|
| User Purpose | user wording, purpose, expected result | preserves direction before worker interpretation | prompt template law |
| Thin Plan | smallest intended move, boundary, expected output | avoids overplanning before evidence | full project plan |
| Space Reading Trace | what was read, what was not read, why | prevents fake whole-space confidence | broad crawl requirement |
| Work Package Trace | package purpose, source refs, allowed/forbidden actions | lets workers act without inventing authority | permission system |
| Execution Trace | what was done, outputs created, commands/files touched | gives recovery something concrete to inspect | automation proof |
| Feedback / Mismatch Trace | user feedback, mismatch, overrun, missing evidence | converts errors into future judgment | blame log |
| Recovery Judgment | what judgment was recovered from the result | makes the process useful next time | universal rule |
| Next Condition | what is easier or clearer now | checks compounding | task queue |
| Return Record | placement, watch, promotion status | returns output to space safely | ledger |
