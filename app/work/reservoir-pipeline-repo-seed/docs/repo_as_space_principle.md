# Repo As Referenceable Space Principle

## Core Claim

A pipeline repo should not only contain pipeline templates.

It should contain the space traces that made the pipeline intelligible:

```text
source materials read
camera/lens used
process decisions
judgment shifts
outputs created
return records
watch boundaries
next-use conditions
```

## Why

If the repo only stores the final pipeline, future workers can copy the shape but miss the intent.

If the repo stores the process trace, future workers can ask:

```text
Why was this pipeline made?
What problem was it solving?
Which source material justified it?
What was rejected or held?
What must not be inferred?
How should the result return to the original space?
```

## Rule Of Use

```text
pipeline output without process trace = incomplete
template without source reference = weak
decision without watch = unsafe
result without return record = not yet space-useful
```

## Boundary

This principle is not a registry requirement or official workflow.

Use it as a repo-seed design guard:

```text
make the pipeline understandable to a future worker
without turning the space into automation
```
