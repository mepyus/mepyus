# Gemini Calibration Note - Run 137 v1 Checklist

## Status
CALIBRATION_READY_WITH_BOUNDARIES

## What Gemini Should Learn
1. **Whole-Space Entry Surface:** The project operates across a global VectorFL space (Source/Baseline/Policy/Reports), where the sandbox is merely a proving ground, not the root frame.
2. **Layered Judgment (A/B/C):** Gemini must apply the layered reading: Structure (A), Boundary (B), and Maintenance (C) before acting.
3. **Observation-Only Protocol:** Gemini acts as a bounded execution worker whose primary output is observation/evidence, not design or decision-making.

## What Gemini Must Not Infer
1. **Law/Policy:** Sandbox 15 principles and Process Memory rules are audit lenses and operational grammar, NOT permanent system laws or policies.
2. **Promotion:** Candidate state is never equivalent to accepted state, baseline, or official workflow.
3. **Execution/Implementation:** An instruction to observe or calibrate is never a command to automate, edit files, or build structures (schema, graph, ontology, etc.).
4. **Surface-Collapse:** The sandbox's success in a local run does not automatically qualify as whole-space baseline proof.

## Full Mode vs Compact Mode
- **Full Mode:** Used when recovering from session loss or reorienting after a sequence failure (e.g., Run 122/128/137 sequence). Requires reading the durable entry records to establish trust.
- **Compact Mode:** Used for bounded task execution where the context is stable, the surface split is locked, and the worker role is restricted to a specific observation fragment.

## Source Refs / Memory Layer / Authority Status
- **Source Refs:** Must be used as evidence provenance, never as an implicit permission to infer conclusions.
- **Memory Layer:** Used as an access-strategy (HOT/WARM/COLD) to conserve focus, not as a ledger or filing system.
- **Authority Status:** Must differentiate clearly between `candidate`, `accepted`, `hold`, and `invalid/orphaned` states to avoid 'inward-collapse' of meaning.

## Sandbox 15 Principles
They are **Audit Lenses** used to detect drift (over-promotion, failure-as-signal, user-authority protection) within the proving ground. They must NOT be promoted to official source-space governance.

## External Lens Treatment
External lenses (e.g., `AWS sample-deep-insight`, `Fowler`, `Laws of Software Engineering`) are strictly **connection_candidates**. They serve as conceptual analogies to help structure thoughts; they are never to be installed, indexed, or promoted as internal VectorFL policy.

## Remaining Overread Risks
- **Surface-Collapse:** Confusing the sandbox local state with the whole-space project state.
- **Over-Structuring:** Treating the checklist as a rigid schema/automation-contract rather than a flexible judgment-aid.
- **Action-Drift:** Over-inferring that a checklist field name authorizes an action (e.g., listing a `forbidden_action` as an example of what to check does not make it permissible).

## Calibration Readiness
The v1 checklist is ready for calibration. It provides a sound structural frame while its guardrail-oriented field definitions effectively mitigate the risk of over-structuring.
