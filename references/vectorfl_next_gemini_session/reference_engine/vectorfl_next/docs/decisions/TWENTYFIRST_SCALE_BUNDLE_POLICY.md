# Twenty-first Scale Bundle Policy

## Decision

Start scale-up validation by widening the runtime with a small bundle of independent local spaces instead of more bridge-heavy pulses.

## Bundle shape

The bundle opens three independent local spaces:

- one sparse-presence space
- one reflux/report-return space
- one non-purpose reading-note space

## Why

- The runtime now has enough relation density that further pulses alone would bias the engine toward visible connection.
- Scale-up should test whether the same physical rules still hold when quiet, weakly-related, or delayed-use materials also occupy the space.
- This bundle grows the field without adding new bridge pressure.

## Constraints

- Each bundle material must form its own cell and local space.
- The bundle must not derive any new bridge traces.
- The bundle is not a verdict on sparse presence yet; it only creates the later review conditions.
- Reflux material should come from generated runtime reports so the return path is real, not symbolic.
