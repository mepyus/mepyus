# Phase 2 Memo Bundle Policy

## Purpose

This bundle brings actual memo files into the runtime under the same physical laws. It tests whether real memo text, code fragments, design notes, failure notes, and bundle structure can form space and relation without requiring a new ontology.

## What enters

- `memo1.md`
- `memo2.md`
- a relation-aware local space formed from both memo files together

## Contract

- the memo files are ingested as raw file-backed material
- the engine does not pre-normalize their mixed forms into separate schemas first
- relation is observed under the same formation rules already in use
- append-only history remains intact

## Why this matters

These memo files are closer to the intended future input universe than synthetic bootstrap material. They mix philosophy, failure residue, code fragments, domain probes, and design notes in one place. The engine should prove it can host that mixture without collapsing it too early.
