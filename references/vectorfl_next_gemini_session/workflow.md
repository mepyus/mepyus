# CODEX 기준선 — VECTORFL_NEXT 재정의 통합본 (현재 작업용 SSOT)

## 0. 지금 무엇을 하고 있는가
VECTORFL_NEXT는 지금 **점/군집/공간을 먼저 만들어내는 엔진**이 아니다.

현재 코어의 목적은 오직 하나다.

**라벨 가능한 최소 의미단(dust unit)을 공간에 뿌리고, 각 먼지에 부여된 값들이 서로 어떤 이유로 붙고/안 붙고/브릿지되고/긴장하는지를 관측하는 것.**

즉 지금 엔진은:

- meaning decider 아님
- ontology builder 아님
- point / cluster / space 확정기 아님

현재 엔진은:

**connection-maker + condensation-observer**

---

## 1. 지금 버려야 할 해석
다음 해석은 현재 단계에서 잠정 중지한다.

- 먼지 → 점 → 군집 → 공간 을 강제 승격 파이프라인으로 읽는 방식
- 점/군집/공간을 엔진이 먼저 판정하는 방식
- 물리적 좌표 거리만으로 구조를 판단하는 방식
- “예쁜 점/예쁜 군집”을 만드는 것을 목표로 두는 방식

지금은 **형태를 먼저 만들지 않는다.**
지금은 **연결과 응축 방향만 만든다.**

---

## 2. 공간의 현재 정의
현재 VECTORFL_NEXT의 공간은 좌표 덩어리가 아니다.

### 공간 정의
공간은 서로 다른 최소 의미단들이

- 각자 벡터값을 가지고 들어오고
- 서로 다른 연결 종류를 만들고
- 직접/약/브릿지/긴장 관계로 상호작용하며
- 그 연결의 방향이 누적되어 흐름과 응축을 만드는 장

이다.

즉 공간은

**같은 의미의 저장소가 아니라, 이질적인 의미도 연결 이유가 있으면 만날 수 있는 상호작용 장**이다.

---

## 3. dust unit 정의
dust unit은 문법 단위로 고정하지 않는다.

즉:

- 무조건 단어
- 무조건 문장
- 무조건 문단
- 무조건 리뷰 전체

로 자르지 않는다.

### dust unit 정의
**입력기와 라벨기가 축/방향성/장면/흐름을 일관되게 부여할 수 있는 최소 의미 단위**

따라서 dust unit은 상황에 따라 다음 중 하나가 될 수 있다.

- 단어
- 구
- 문장
- 최소 의미 문단
- 짧은 리뷰 전체

### 채택 기준
어떤 단위를 dust로 채택할지는 아래 기준으로 판단한다.

- 3축 방향이 붙을 수 있는가
- 장면 라벨이 붙을 수 있는가
- 흐름 라벨이 붙을 수 있는가
- 하나의 방향성으로 읽히는가
- 더 쪼개면 의미가 약해지는가
- 더 합치면 방향이 흐려지는가

핵심은 문법이 아니라 **labelability**다.

---

## 4. 먼지의 값 구조
먼지 하나의 값은 현재 **3개의 층위**로 본다.

### 1층. 코어 벡터층
먼지의 기본 체질이다.

- D = Direction
- I = Intensity
- S = Stability

#### 현재 임시 해석
- D: 어느 방향 성질로 붙으려 하는가
- I: 응축/압력이 얼마나 강한가
- S: 붙은 뒤 얼마나 버티는가

### 2층. 해석 라벨층
먼지의 무대와 움직임을 붙여주는 필터층이다.

- scene label
- flow label

#### 현재 해석
- scene = 이 먼지가 어느 상황권/무대에 서 있는가
- flow = 이 먼지가 어느 방향으로 움직이는가

### 3층. 시간/상태층
먼지의 숙성과 변화를 보는 층이다.

- time
- recurrence
- maturation
- interaction state

#### 현재 해석
- 언제 들어왔는가
- 다시 돌아왔는가
- 얼마나 익었는가
- 지금 어떤 상호작용 상태인가

---

## 5. D / I / S 수치 기준
현재 D/I/S는 0.0 ~ 1.0 범위로 둔다.

### 중심
- 0.5 = 중심

### 해석 구간
- 0.00 ~ 0.40 = negative pole
- 0.40 ~ 0.60 = neutral band
- 0.60 ~ 1.00 = positive pole

즉 0.5 하나로 정/반을 바로 자르지 않고,
0.4 ~ 0.6을 중립대역으로 둔다.

### 해석 예
- D가 높다 = 정방향 성향 강함
- D가 낮다 = 반대 방향 성향 강함
- I가 높다 = 응축/압력 강함
- I가 낮다 = 확산/약함 쪽
- S가 높다 = 버티는 쪽
- S가 낮다 = 누설/이탈 쪽

중요:
**낮은 값은 나쁜 값이 아니라 반대극이다.**

---

## 6. 장면(scene) / 흐름(flow)의 역할
D/I/S만으로는 먼지의 기본 체질은 보이지만,
실제 연결 방식은 충분히 설명되지 않는다.

왜냐면:

- 같은 축이어도 다른 무대일 수 있고
- 다른 축이어도 같은 장면 안에서 긴장을 만들 수 있고
- 흐름이 같거나 반대거나 브릿지가 될 수 있기 때문이다

### 가장 쉬운 이해
- 3축 = 몸체
- scene = 무대
- flow = 움직이는 방향

즉 scene/flow는 3축을 덮어쓰는 게 아니라,
**3축 위에 얹는 해석 보정 필터**다.

### 중요한 규칙
- 3축이 비슷해도 scene/flow가 다르면 덜 붙을 수 있다
- 3축이 조금 달라도 scene/flow가 잘 맞으면 더 붙을 수 있다

---

## 7. 현재 장면/흐름 라벨 최소안
지금은 정밀 체계를 만들지 않는다.
현재 scene/flow의 목적은 **정답 체계**가 아니라 **connection hint 제공**이다.

### 장면 최소안
- self: 자기평가, 감정, 내면
- work: 작업, 도구, 실행
- evidence: 코드, 로그, 기록, 결과
- meta: 비교, 철학, 해석, 관점

### 흐름 최소안
- contract: 수축, 위축, 움츠러듦
- expand: 전개, 실행, 확장
- bridge: 연결, 매개, 전환
- tension: 충돌, 반대, 경쟁, 아이러니

애매하면 `unknown` 허용.

### 현재 운영 원칙
scene/flow는 coarse label이면 충분하다.
지금은 완벽한 분류가 아니라 **붙는 이유를 만드는 임시 기준점**이면 된다.

## 8. 먼지를 공간에 던질 때의 기본값
현재 dust 하나는 최소한 아래 필드를 가진다.

- text
- origin
- D
- I
- S
- scene
- flow
- time

즉:

- 3축 기본값
- 장면 1개
- 흐름 1개
- 시간값

을 붙여 공간에 뿌린다.

## 9. 연결이 진짜 본체다
지금부터 공간의 핵심은 위치가 아니라 연결이다.

즉:

- 가까워서 붙는 것이 아니다
- **붙을 이유가 강해서 연결된다**

좌표는 시각화 보조일 뿐이고,
진짜 구조는 연결성이다.

### 연결을 구성하는 기본 요소
1. 축 정렬도
2. 장면 공명도
3. 흐름 적합도
4. 시간 공명도

이 네 개의 프로필로 연결을 읽는다.

---

## 10. 연결 종류
현재 연결은 최소 4종으로 구분한다.

### 1) direct
- 축 정렬 높음
- 장면 공명 높음
- 흐름 적합 높음

### 2) weak
- 일부만 겹치거나 약하게 공명

### 3) bridge
- 직접은 약하지만 중간 먼지를 통해 이어짐

### 4) tension
- 같은 장면권 안에서 축/흐름이 반대라 긴장으로 붙음

즉 현재 연결은:

- 직접 연결
- 약한 연결
- 브릿지 연결
- 긴장 연결

로 본다.

---

## 11. 응축의 현재 정의
지금은 point / cluster / space를 먼저 정의하지 않는다.
우선 **응축만 본다.**

### 응축 정의
먼지들이

- 반복적으로 붙고
- 다시 붙고
- 연결 방향이 두꺼워지고
- 특정 축/장면/흐름 쪽으로 몰리는 현상

즉 지금 관측 대상은:

- 뭉치느냐
- 안 뭉치느냐
- 왜 뭉치느냐
- 어디로 몰리느냐
- 어떤 연결 종류가 누적되느냐

이다.

---

## 12. point / cluster / space의 현재 위치
지금은 이 셋을 코어 산출물로 쓰지 않는다.

### point
나중에 반복 응축이 버티면 뒤에서 읽는 관측 이름

### cluster
연결 종류와 응축 방향이 누적되어 장면권이 두꺼워지면 뒤에서 읽는 관측 이름

### space
전체 연결 방향과 응축 흐름이 하나의 큰 장처럼 보일 때 뒤에서 읽는 관측 이름

즉 현재는:

- point를 만들지 않는다
- cluster를 설계하지 않는다
- space를 먼저 나누지 않는다

오직:

**연결과 응축 방향만 만든다**

---

## 13. viewer 재정의
viewer는 결과 구조 뷰어가 아니라
**dust + connection viewer** 로 본다.

먼지 하나를 클릭하면 최소한 보여줘야 하는 것:

### origin
- 원본 텍스트
- 원본 위치
- 같은 입력에서 같이 들어온 dust들

### values
- D / I / S
- scene
- flow
- time

### connections
- direct
- weak
- bridge
- tension

### interaction
- 지금 누구와 붙는지
- 과거 어디와 붙었는지
- 왜 약해졌는지
- 어디로 재부착됐는지

즉 viewer는
“이건 점이다”를 보여주는 게 아니라,

**이 먼지가 어디서 왔고, 어떤 값으로 들어왔고, 지금 누구와 어떤 이유로 연결되어 있는지**

를 보여줘야 한다.

## 14. 예시 해석

### 예시 A
`나는 바보입니다`
`나는 똑똑한 것 같애`

- 같은 장면권: 자기평가(self)
- 반대 방향성: 부정 / 긍정
- 직접 의미 동일 아님
- 긴장 연결 가능
- 이 긴장 자체가 하나의 응축 흐름을 만들 수 있음

### 예시 B
`클로드코드 스킬 논문`
`코드 기록`
`로그 기록`
`잘된 것`
`안 된 것`
`기분 메모`
`철학 메모`

- 전부 같은 물리적 거리로만 붙지 않음
- 각각 다른 종류의 연결로 붙음
- 어떤 건 direct
- 어떤 건 weak
- 어떤 건 bridge
- 어떤 건 tension
- 그 연결 방향이 누적되며 하나의 장면/흐름이 형성됨

## 15. 현재 운영 원칙
지금 코덱스는 아래 원칙으로 작업해야 한다.

### 원칙 1
엔진은 dust-scale only로 잠근다.

### 원칙 2
입력은 labelable minimum semantic unit으로 자른다.

### 원칙 3
각 dust에 time + D/I/S + scene/flow 값을 넣는다.

### 원칙 4
엔진은 연결 강도와 연결 종류만 만든다.

### 원칙 5
응축은 관측하되 point/cluster/space는 후행 해석으로 넘긴다.

### 원칙 6
viewer는 결과 구조보다 origin / values / connections / interactions 를 우선 보여준다.

---

## 16. 지금 중요한 목표
현재 목표는:

- 예쁜 점 만들기 아님
- 예쁜 군집 만들기 아님
- point/cluster/space ontology 확정 아님

오직:

- 값이 명확한 먼지를 뿌리고
- 그 값들이 어떻게 붙는지
- 왜 붙는지
- 왜 안 붙는지
- 왜 브릿지가 되는지

를 보는 것

즉 지금은:

**정확한 값 + 실제 상호작용**

이 목표다.

---

## 17. 현재 잠금 문장
### 기준 문장 1
현재 scene/flow label의 목적은 정밀 분류가 아니라 connection hint 제공이다.

### 기준 문장 2
각 dust에는 D/I/S + scene 1개 + flow 1개 + time을 붙인다.

### 기준 문장 3
scene/flow는 coarse label이면 충분하며, 애매한 경우 unknown 허용한다.

### 기준 문장 4
현재 목표는 correct ontology가 아니라 stable attachment baseline이다.

---

## 18. 코덱스에게 바로 전달할 작업 기준문
VECTORFL_NEXT는 point/cluster/space generator가 아니다.
현재 core는 labelable minimum semantic unit을 dust로 받아
time + D/I/S + scene/flow 값을 부여하고,
dust 간 direct / weak / bridge / tension connection만 생성·기록하는
dust-scale connection engine으로 운용한다.
현재 목표는 구조 미학이 아니라 연결성과 응축 방향 관측이다.
viewer는 point view보다 origin/value/connection/interactions 중심으로 재구성한다.
