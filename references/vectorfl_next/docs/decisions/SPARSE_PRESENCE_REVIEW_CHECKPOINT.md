# Sparse Presence Review Checkpoint

## Why this checkpoint exists

The engine has spent several turns proving that visible formation works:

- material can form a cell and local space
- local spaces can persist
- weak bridge exposure can emerge
- repeated pulses can rethread terrain flow

That is necessary, but not sufficient for the meaning of space in `vectorfl_next`.

If the engine only handles what becomes visible quickly, it risks drifting toward a readable relation engine instead of a true space engine.

## What must be reviewed later

When the runtime has grown enough, review whether the space also holds materials that do **not** quickly become readable through bridge-heavy flow.

The later review should ask:

- Are there materials that remain weakly related for a long time without disappearing?
- Can a sparse local space persist without quickly becoming bridge-exposed?
- Does the runtime still contain slow, thin, or barely-related presence once larger resonant spans have formed?
- Are there terrains whose value is not immediate visibility, but long, quiet staying power?

## What this is not

- This is not a demand to split the engine into "connected" and "unconnected" modes.
- This is not a reason to freeze or compress the current runtime too early.
- This is not a request to judge sparse presence at the current small runtime scale.

## Current decision

Do not force this review into the current runtime scale.

Instead:

- keep building space
- keep observing existing flow and maturation
- return to this checkpoint after more terrains have accumulated

## Review signal to look for later

The engine should eventually show that the same space can hold:

- quickly connecting material
- slowly maturing material
- material that lingers with only thin relation
- material that remains spatially present before it becomes legible

If that later review fails, the engine risks becoming storage for visible relations rather than a space that can host multiple speeds of formation.
