# WashTank Screen Roles

## 목적

이 문서는 `WashTank` 안에 흩어져 있는 화면 파일들을
기능 목록이 아니라 역할 기준으로 다시 읽기 위한 문서다.

즉 "이 파일이 무슨 UI인가"보다
"이 화면이 전체 공정 안에서 어떤 자리였는가"를 남기는 데 목적이 있다.

## 기본 분류

현재 `WashTank`의 화면들은 크게 네 묶음으로 나눌 수 있다.

1. 사무실 허브 화면
2. 현장 공정 화면
3. 장비기사 화면
4. 보드 / 래퍼 / 상위 모니터 화면

이 분류가 중요한 이유는,
파일명이 다양해 보여도 실제로는 각기 다른 운영 역할을 맡고 있기 때문이다.

## 1. 사무실 허브 화면

### Officein.jsx

이 화면은 완료 이력과 입고 기록을 다루는 사무실 허브로 읽힌다.

핵심 역할:

- 완료된 작업 조회
- 입고 관련 기록 확인
- 특정 날짜 기준 기록 보기
- 작업 이력을 문서처럼 다루기

즉 `Officein`은 "지금 현장에서 뭘 하고 있나"보다
"어떤 작업이 끝났고 어떤 기록이 남았나"에 더 가깝다.

### Officeout.jsx

이 화면은 `DONE` 상태 작업을 다음 공정으로 넘기는 전환 허브다.

핵심 역할:

- 현재 공정이 끝난 탱크를 모은다
- 다음 공정을 선택한다
- 출고 요청이나 후속 작업 생성으로 연결한다
- 다중 다음 공정 상태를 조정한다

즉 `Officeout`은 단순 종료 화면이 아니라,
현장 작업 이후의 **다음 단계 분기 허브** 역할을 한다.

## 2. 현장 공정 화면

### Eir.jsx

입고 / EIR 공정의 실제 작업 화면이다.

핵심 역할:

- 탱크 입고 입력
- 초기 상태 확인
- 이후 공정으로 넘기기 위한 기초 판정

즉 시스템 바깥의 탱크를 시스템 안의 공정 흐름으로 들이는 첫 작업 화면이다.

### WashingWaiting.jsx

세척 공정의 대기 / 진행 상태를 보는 화면이다.

핵심 역할:

- READY와 IN_PROGRESS를 구분한다
- 세척 대상을 큐처럼 본다
- 시작과 완료를 명시적으로 트리거한다

즉 세척 공정을 "대기 리스트 + 실행 리스트" 관점으로 다루는 화면이다.

### Inspection.jsx

검사 단계의 핵심 소비자 화면이다.

핵심 역할:

- 측정 시작
- 측정값 입력
- 검사 시작
- 검사 완료

이 화면은 특히 측정과 검사를 따로 떼어 다루는 점이 중요하다.

즉 검사라는 한 단어 아래에 여러 하위 행위를 구분해서 남기려 했다.

### RepairShop.jsx

수리 작업을 위한 메인 워크벤치다.

핵심 역할:

- 수리 대상 검색 및 선택
- 수리 등록
- 수리장 처리
- 수리 완료
- 부지에 따라 수리장 이동 여부 결정

즉 `RepairShop`은 카드 보드보다 실제 작업 입력형 워크벤치에 가깝다.

### Delivery.jsx

출고 준비 / 출고 처리 화면이다.

핵심 역할:

- 날짜 기준 출고 READY 리스트 조회
- 출고 우선순위 확인
- 현 위치 확인
- 출고 준비 완료 처리

즉 출고를 단순 완료가 아니라, 일정과 준비 상태가 있는 운영 큐로 본다.

### Shuttle.jsx

부지 간 이동을 처리하는 특수 공정 화면이다.

핵심 역할:

- 1부지 출발 / 2부지 출발 분리
- 이동 시작
- 이동 완료
- 이동 완료 후 승인 신호 연결

즉 단순 위치 변경이 아니라, 이동도 별도 작업 이벤트로 본다.

## 3. 장비기사 화면

### Ehandler.jsx

1부지 장비기사 페이지다.

이 파일은 공정 단계보다 **현장 역할** 중심 화면으로 읽는 것이 맞다.

즉 "어떤 작업인가"보다
"누가 그 작업을 담당하는가"가 전면에 있다.

### Fhandler.jsx

2부지 장비기사 페이지다.

`Ehandler`와 함께 보면,
이 프로그램은 공정 분리뿐 아니라
부지와 작업자 역할도 독립 화면으로 나누려 했음을 보여준다.

즉 장비기사 화면은 공정 화면의 하위가 아니라,
현장 운영 역할을 직접 반영한 별도 콘솔에 가깝다.

## 4. 보드 / 래퍼 / 상위 모니터 화면

### head.jsx

비교적 초기형 공정 보드 / 모니터 성격의 화면이다.

핵심 역할:

- 공정별 READY / ACTIVE 상태를 한 번에 본다
- 시작 / 완료를 공통 패턴으로 다룬다
- 세척, 검사, 출고 같은 단계를 보드 형태로 묶는다

즉 상세 작업 화면으로 분화되기 전,
공정 전체를 한 보드로 보려는 흔적을 담는다.

### Workspace.jsx

상위 작업 공간 래퍼다.

핵심 역할:

- 상위 컨테이너
- Office 계열 화면을 감싸는 레이어
- 에러 / 성공 메시지 같은 공통 상태 표시

이 화면은 직접 공정을 수행하는 것보다,
작업 화면들이 놓이는 공간을 만들어 주는 성격이다.

### OfficePageContainer.jsx

사무실 화면용 컨테이너 성격의 파일이다.

핵심 역할:

- 초기 데이터 로드
- 검색 디바운싱
- Office 화면으로 데이터 주입

즉 UI 본체라기보다 연결 계층의 흔적에 가깝다.

## 5. 화면 분리에서 읽히는 운영 감각

이 화면들을 함께 보면 `WashTank`는 단순 페이지 모음이 아니라,
다음과 같은 운영 감각을 갖고 있었던 것으로 보인다.

1. 사무실은 승인 / 전환 / 기록의 허브다
2. 현장은 실제 작업 입력의 허브다
3. 장비기사는 별도 역할 콘솔이 필요하다
4. 셔틀 같은 이동도 독립 작업으로 본다
5. 같은 탱크라도 공정 단계에 따라 전혀 다른 화면으로 본다

즉 화면 분리는 단순 UI 분해가 아니라,
현장 역할 분해를 UI 구조에 반영한 결과에 가깝다.

## 6. 이 문서를 어떻게 쓸 것인가

이 문서는 각 파일을 하나씩 설명하는 용도보다,
앞으로 `WashTank`를 기록할 때 아래 질문에 답하기 위한 중간 문서로 쓰기 좋다.

- 왜 이 화면이 필요했는가
- 이 화면은 현장용인가, 사무실용인가, 역할용인가
- 같은 공정을 왜 여러 화면으로 나눴는가
- 어떤 파일이 실제 작업 허브였고 어떤 파일이 실험적 보드였는가

즉 이 문서는 파일 설명서가 아니라,
화면들의 위치와 성격을 다시 배치하는 지도 역할을 한다.
