# WashTank Glossary

## 목적

이 문서는 `WashTank` 관련 md와 코드에서 반복해서 나오는 용어를
간단히 고정해두기 위한 용어집이다.

`WashTank`는 화면 수가 많고,
사무실 / 현장 / 공정 / 상태 전이 / 위치 개념이 함께 섞여 있기 때문에
같은 말을 문맥마다 다르게 읽기 쉽다.

이 문서는 그 흔들림을 줄이기 위한 기준 메모다.

## 기본 객체

### Tank

시스템의 중심 객체.

단순 자산 목록 항목이 아니라,
입고, 세척, 검사, 수리, 출고 같은 공정을 통과하는 기본 단위다.

### Tank Number

현장에서 식별하는 탱크 번호.

화면에서는 사용자가 가장 먼저 인식하는 식별자이고,
DB 구조에서는 `id`와 별도로 운영상 중요한 키처럼 쓰인다.

### Location

탱크가 실제로 놓이는 물리적 위치.

이 프로그램은 상태뿐 아니라 위치도 중요한 값으로 보기 때문에,
위치는 단순 메타데이터가 아니라 운영 축에 가깝다.

## 공정 관련 용어

### Inbound

탱크가 시스템 안으로 들어오는 시작 공정.

입고 등록, 초기 확인, 이후 공정 연결의 출발점 역할을 한다.

### EIR

입고 시점의 확인 / 기록 공정.

단순 등록보다,
초기 상태를 확인하고 시스템 공정으로 넘기기 위한 관문처럼 읽는 편이 맞다.

### Wash / Washing

세척 공정.

대기와 실행이 분리되어 보이며,
READY와 IN_PROGRESS를 명시적으로 다루는 작업 단계다.

### Inspect / Inspection

검사 공정.

특히 `WashTank` 안에서는
측정 시작, 측정 기록, 검사 시작, 검사 완료처럼
하위 단계가 분리되어 있다는 점이 중요하다.

### Repair

수리 공정.

예외 처리나 보완 작업 성격이 강하며,
별도 워크벤치가 필요할 정도로 독립된 단계로 취급된다.

### Delivery / Outbound

출고 준비와 출고 공정.

날짜, 우선순위, 준비 상태, 현 위치를 같이 보며,
단순 종료가 아니라 운영 큐처럼 다뤄진다.

### Shuttle

부지 간 이동 공정.

위치 변경을 단순 속성 수정으로 흡수하지 않고,
독립 작업 이벤트로 다루려는 개념이다.

## 역할 관련 용어

### OfficeIn

사무실 기록 허브.

완료 이력과 입고 기록을 읽고 정리하는 쪽에 가깝다.

### OfficeOut

사무실 전환 허브.

DONE 작업을 다음 공정으로 넘기거나,
후속 작업 생성을 결정하는 분기 허브에 가깝다.

### Ehandler

1부지 장비기사 페이지.

공정 단계보다 현장 역할 기준 화면으로 읽는 편이 맞다.

### Fhandler

2부지 장비기사 페이지.

`Ehandler`와 짝을 이루며,
부지와 역할 차이를 화면으로 분리한 흔적이다.

## 상태 관련 용어

### READY

작업 대기 상태.

아직 실행되지는 않았지만,
다음 작업자가 소비할 수 있는 상태를 뜻한다.

### IN_PROGRESS

작업 진행 상태.

이미 시작되었고,
현재 현장에서 처리 중인 상태를 뜻한다.

### DONE

현재 단계의 작업이 완료된 상태.

하지만 `WashTank`에서는 끝이라기보다
다음 공정 전환이 가능한 상태로 읽는 편이 더 맞다.

### CANCEL

작업 취소 상태.

단순 삭제가 아니라 취소 이벤트가 남는 상태로 이해하는 것이 맞다.

## 엔진 관련 용어

### JMS

`WashTank`의 서비스 / 상태 전이 레이어를 가리키는 중심 용어.

화면은 직접 DB를 조작하기보다,
`JMS`를 통해 조회하고 이벤트를 보낸다.

즉 `JMS`는 단순 API 유틸이 아니라,
여러 화면을 하나의 공정 질서 아래 묶는 서비스 계층이다.

### Job

탱크에 부착된 작업 단위.

예:

- INBOUND
- WASH
- INSPECT
- REPAIR
- OUTBOUND

탱크는 그냥 존재하는 것이 아니라,
어떤 job을 현재 가지고 있는가로 읽힌다.

### Event

상태를 움직이는 행위 단위.

예:

- START
- COMPLETE
- CANCEL
- CREATE

즉 화면은 필드를 조용히 수정하기보다,
이벤트를 보내는 구조를 지향한다.

### State Transition

현재 상태에서 다음 상태로 이동하는 규칙.

`WashTank`는 이를 코드에 흩뿌리기보다,
서비스 레이어와 규칙 구조로 다루려는 흔적이 있다.

### RPC

상태 전이나 위치 이동 같은 주요 작업을 처리하기 위해
백엔드 함수 호출 방식으로 연결된 메커니즘.

즉 프론트는 "무엇을 할지"를 요청하고,
실제 전이 로직은 서비스 / 백엔드가 수행하는 구조를 암시한다.

## 데이터 관련 용어

### tanks

탱크 기본 원장.

탱크 번호, 타입, 용량, 부속 정보 같은
비교적 정적인 정보를 담는 층이다.

### tank_status

현재 운영 상태 층.

화물, 날짜, 우선순위, 위치, 마지막 이벤트처럼
운영 중 계속 변하는 정보를 담는다.

### jobs

탱크에 연결된 작업 단위 테이블.

공정 흐름을 job 중심으로 추적하기 위한 층이다.

### tank_event

이벤트 기록 층.

현재 상태만이 아니라,
무슨 일이 있었는지를 연쇄로 남기는 데 의미가 있다.

### locations

야드, 블록, 슬롯 같은 물리적 위치 구조를 담는 층.

### state_transition_rule

상태 전이 규칙을 별도로 두려는 테이블.

현재 상태와 이벤트에 따라 다음 상태를 정하려는 사고를 보여준다.

## 읽을 때 주의할 점

같은 용어도 문맥마다 조금씩 무게가 다를 수 있다.

예를 들어:

- `DONE`은 진짜 종료가 아니라 다음 공정 전환 가능 상태일 수 있다
- `OfficeOut`은 출고 화면이 아니라 전환 허브에 더 가깝다
- `Shuttle`은 위치 변경이 아니라 별도 공정으로 읽는 편이 맞다

즉 이 용어집은 정답 사전이 아니라,
현재 `WashTank`를 읽을 때의 기본 해석 틀로 보는 편이 좋다.

## 한 줄 정리

`WashTank`의 용어들은 단순 UI 단어가 아니라,
탱크를 공정과 상태 전이, 역할 분리, 위치 이동 속에서 다루기 위한 운영 언어다.
