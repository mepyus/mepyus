## summary

Assistant produced a coherent ASSETS.md / asset operating model design.

The user identified that the design stood on asset management / ontology / governance layers, while the intended space philosophy required layered reading, reverse ontology, and line/axis/context retrieval.

## initial_assistant_layer

- asset management
- knowledge governance
- ontology/schema-adjacent structuring
- quality-control framing

## user_space_layer

- layered reading
- reverse ontology
- line / axis / connection / flow / context retrieval
- meaning maturation
- CLI pre-reading and post-return reflux

## what_went_wrong

The assistant designed too coherently inside one layer before checking which layer the design stood on.

Without user correction, the assistant would have treated ASSETS.md as a useful guide instead of rereading it through multiple lenses.

## what_was_learned

Asset value depends on reading lens.

A design can be useful in one lens and dangerous in another.

The space should not only judge fit/no-fit.

It should identify the layer, compare lens values, and place the asset at the right level.

## reusable_lesson

Before converting a proposed structure into a space asset, ask:

- What layer does this proposal stand on?
- Which lens makes it look valuable?
- Which lens makes it risky?
- Does it fit the user's living-space philosophy directly?
- If not, should it be kept as comparison, quarantine, future option, or lens material?

## do_not_use_as

- justification to create ASSETS.md immediately
- asset registry
- schema
- automation spec
- baseline lock
- Codex/Gemini authority expansion

## accepted_reflux

- risk_memory: coherent designs may still stand on the wrong layer
- reuse_hint: reread proposed structures through multiple lenses before adopting
- pattern_candidate: proposed structure -> layer identification -> multi-lens reading -> lowered placement
- hold_signal: if asset guide becomes registry/schema/automation/baseline, HOLD
