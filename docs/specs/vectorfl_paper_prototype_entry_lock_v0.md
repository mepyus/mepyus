# VectorFL Paper Prototype Entry Lock v0

이 문서는 현재까지 만든 mock과 route-aware shell 세트를  
`VectorFL Paper` 프로토타입의 시작점으로 어떻게 읽을지 잠근다.

목적은 mock이 흩어진 demo 묶음으로 보이지 않게 하고,
현재 단계에서 어떤 surface가 중심이며
어떤 route/state가 보조 실험면인지 한 장으로 고정하는 것이다.

## 1. Core Sentence

현재 `VectorFL Paper` 프로토타입의 시작점은  
`unified shell mock`이며,
route-aware mock set은 그 unified shell이
어떤 primary surface state로 펼쳐질 수 있는지 보여주는 보조 증명면이다.

## 2. Prototype Entry Order

현재 단계에서 entry order는 아래처럼 읽는 것이 맞다.

1. `Unified Shell Mock`
2. `Route-Aware Surface Set`
3. `Organ Detail Mock`
4. `Current Reading Mock`
5. `First Shell Mock`

## 3. Why This Order

- `Unified Shell Mock`은 현재 가장 VectorFL Paper에 가깝다
- `Route-Aware Surface Set`은 page state 전환 규칙을 보여준다
- `Organ Detail Mock`은 contextual panel 성격을 더 분명히 한다
- `Current Reading Mock`과 `First Shell Mock`은 이전 단계 기준면으로 남긴다

## 4. What Remains True

- semantic center는 여전히 `Current Reading`
- `Cases / Queue`는 entry surface
- `Inputs / Intake`는 material surface
- `History / Trace`는 carry surface
- `Programs / Connections`는 boundary surface
- `Organ Detail`은 contextual panel

## 5. Final Lock Sentence

현재 기준은 다음 문장으로 잠근다.

`VectorFL Paper 프로토타입의 첫 진입면은 Unified Shell Mock으로 두고, route-aware surface set은 그 shell의 primary surface state 확장을 보여주는 보조 세트로 읽는 것이 맞다.`
