# VectorFL Page Shell Fork Lock v0

이 문서는 `git_search/paperclip`를 단순 reference로만 보는 단계를 넘어,  
`VectorFL Page`라는 개인용 프로그램 shell로 변환해 가져오는 기준을 잠근다.  
목적은 화면 구성을 참고하되, ontology와 의미 구조는 VectorFL 쪽으로 다시 소유하는 것이다.

## 1. Core Sentence

VectorFL Page는 Paperclip를 그대로 쓰는 것이 아니라,  
`Paperclip shell composition을 가져와 VectorFL 구조에 맞게 재소유한 개인용 forked shell`로 간다.

즉:

- 화면 감각은 참고할 수 있다
- shell frame도 참고할 수 있다
- 하지만 구조, naming, canonical object, panel meaning은 VectorFL이 다시 가진다

## 2. What Stays From Paperclip

현재 단계에서 유지 가능한 것은 아래다.

- page frame composition
- queue / detail / side panel 배치 감각
- operator console 중심 레이아웃 감각
- history / governance / connection panel 분리 감각

즉 `보이는 껍데기와 운용면 감각`은 남길 수 있다.

## 3. What Must Be Reowned By VectorFL

아래는 그대로 두지 않고 VectorFL 쪽으로 재소유해야 한다.

- app name
- information architecture naming
- canonical object naming
- current-reading 중심성
- governance semantics
- trace / memory semantics
- intake / case / lane / surface meaning

즉 화면은 비슷할 수 있어도, 의미와 구조는 `VectorFL Page`로 다시 정의되어야 한다.

## 4. Fork Rule

이 shell은 `theme swap`이나 `label swap`이 아니다.

아래 기준으로 읽는다.

- Paperclip에서 가져오는 것:
  - shell composition
  - page scaffolding 감각
  - panel separation 감각
- VectorFL이 다시 정의하는 것:
  - page purpose
  - object semantics
  - panel roles
  - navigation meaning
  - queue/detail/history/governance 해석

즉 `same shell feeling, different semantic ownership`이 기준이다.

## 5. Personal Program Rule

VectorFL Page는 일반 제품 추상화보다 먼저 `개인용 프로그램`으로 읽는다.

의미:

- 나에게 필요한 current-reading이 중심이다
- 나의 VectorFL organ/lane/governance 감각이 기준이다
- 외부 프로그램 연결도 내 운용 흐름에 맞게 붙는다
- 팀/company/issue worldview보다 case/current-reading/governance/trace worldview가 우선이다

## 6. Consequence For Next Steps

이 기준이 들어오면 다음 구현 단계의 성격도 바뀐다.

### before

- Paperclip shell reference를 어떻게 참조할까

### now

- Paperclip shell을 어디까지 fork해서
- 어떤 VectorFL Page navigation과 panel semantics로 다시 덮을까

즉 다음 단계는 단순 adapter 계약만이 아니라,
`VectorFL Page shell semantics`를 같이 잡는 단계가 된다.

## 7. What This Does Not Mean

이 기준이 들어왔다고 해서 아래를 바로 뜻하지는 않는다.

- Paperclip ontology 도입
- agent/company model 도입
- heartbeat 중심 제품화
- full multi-agent shell 구현

즉 여전히 가져오는 것은 `shell composition`이고,
재정의하는 것은 `VectorFL Page semantics`다.

## 8. Final Lock Sentence

현재 기준은 다음 문장으로 잠근다.

`Paperclip는 VectorFL Page의 원형 shell로 참고하되, 최종 결과는 Paperclip를 쓰는 것이 아니라 VectorFL의 current-reading, governance, trace, intake, case, lane 의미를 중심으로 다시 소유한 개인용 forked shell이어야 한다.`
