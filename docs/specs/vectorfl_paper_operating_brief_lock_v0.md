# vectorfl paper operating brief lock v0

## purpose

This lock fixes the current operating direction for VectorFL Paper.

Paperclip is adopted for:

- host shell
- operable page grammar
- list / detail / inspector / editor / audit structure

VectorFL remains responsible for:

- core semantics
- current-reading
- governance
- trace
- handoff meaning
- packet contracts
- top / middle / bottom operating logic

## first-pass success condition

The first pass is not the full system.
It succeeds when `Cases / Case Detail / Inspector` can show, for one source:

- raw source
- segmentation basis
- generated lines
- human-readable translation
- internal recall
- linked declarations/directives/judgments
- what is missing
- next action

without reopening multiple md files manually.

## line rule

Line is not:

- a polished sentence
- a pretty summary
- a final output string

Line is:

- the entry to internal recall
- the center unit for family thickening
- the basis for search, adoption, validation, and routing

So a usable line must carry:

- source linkage
- family linkage
- declaration/directive linkage
- judgment history linkage
- human-readable gloss
- searchable form
- adoption form
- uncertainty

## gmd rule

GMD must not be used as a thin chunker.
Its job is to preserve:

- source units
- role
- order
- relation
- unresolved areas

so later translation can happen on stronger material.

## top / middle / bottom

### top fixed

- supervisor
- internal recall first
- lane execution trigger
- comparison
- validation
- final judgment
- trace append decision

### middle pluggable

- editable lanes
- provider/model
- role/task/caution md
- output schema
- timeout
- budget
- enabled flag

### bottom fixed

- Read
- Apply
- Search
- Validate
- Report

No free-form multi-agent chat.
Lanes run the same pipeline in parallel and are only compared at the top.

## visible language rule

Primary surface language must be product-readable:

- page titles
- panel titles
- buttons
- tabs
- status labels
- action names

Internal space semantics may appear as:

- metadata
- expandable sections
- inspector content
- tooltips

but must not dominate the main surface language.

## page-class rule

Paperclip should be used as host page grammar, not copied as ontology.
The first important page classes are:

- Cases
- Case Detail
- Inspector
- Routing
- External Resource Plan
- Lanes
- Lane Runs
- Organs / Teams
- Organ / Team Detail / Editor
- Trace Audit

## final sentence

VectorFL Paper uses Paperclip’s operable page grammar as host shell, but its real purpose is to make

- source
- line
- translation
- internal recall
- external resource planning
- next action

visible in one operating flow.
