# vectorfl programs connections detail drill-in lock v0

## 1. purpose

`Programs / Connections` should not remain only a boundary summary card.
If VectorFL Paper is supposed to show how external program evidence is carried into
current-reading, the operator should be able to drill into saved connections and
attention items directly.

## 2. lock

The semi-live `Programs / Connections` surface should expose detail links for:

- saved connection preview rows
- attention memory preview rows

## 3. first detail kinds

The first detail set is locked to:

- `saved_connection`
- `attention_memory`

Update events and reconstruction preview may stay summary-only for now.

## 4. semantic rule

Program detail does not become a new semantic center.

- `Programs / Connections` remains the primary boundary surface
- program detail remains drill-in
- drill-in makes relation summary and boundary conditions inspectable

## 5. inheritance reason

This continues the same structural inheritance rule already used for organs and
traces:

- visible surface
- clickable bounded row
- deeper inspectable page

What is inherited is inspectability and flow legibility, not external ontology.
