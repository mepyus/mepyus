# line reread operating loop / anti-ontology / hub-late emergence spec v0

## purpose

이 문서는 line을 taxonomy 항목이나 ontology 정의명처럼 다루지 않고,
공간 전체를 다시 읽게 만드는 동적 판독면으로 운영하기 위한 최소 규율을 고정한다.

핵심은 아래다.

- line은 정의문이 아니다
- line은 얇게 잡는다
- 재료를 더 깊게 읽는다
- line은 문서 / 코드 / runtime / reference / 사용자 언어를 다시 훑게 만든다
- hub는 늦게 드러난다

## core premise

현재 공간에서 line은:

- 개념 라벨이 아니다
- ontology 항목이 아니다
- 정의문이 아니다

line은:

- 재료를 다시 읽게 만드는 얇은 판독면
- 문서 / 코드 / trace / reference / 사용자 언어를 다시 훑게 만드는 방향선
- 반복 reread 속에서 서서히 두꺼워지는 흐름선

hub는:

- 먼저 선언하는 중심점이 아니다
- 여러 line이 반복 reread를 일으키고
- 수정선 / 합류선 / close-out / trace가 누적된 뒤에야
- 뒤늦게 드러나는 응축점이다

## mandatory operating sequence

line이 보이면 아래 순서로만 움직인다.

### 1. hold the line thin

- 임시 이름만 허용
- 정의 금지
- 우선 질문만 둔다
  - 이 line은 무엇을 다시 읽게 하는가?
  - 이 line이 없으면 지금 못 보게 되는 것은 무엇인가?
  - 어떤 재료를 다시 보게 만드는가?

### 2. reread the material deeply

line 자체보다 재료를 더 깊게 읽는다.

### 3. leave a trace

최소 아래 흔적 중 일부를 남긴다.

- source trace
- modification trace
- merge trace
- current live reading
- human-language line sentence

### 4. inspect before naming

다음을 점검한다.

- 이 line은 반복 reread에도 남는가
- 다른 층위에서도 남는가
- local pattern인가
- thick line candidate인가
- 너무 빠르게 이름을 붙이고 있지는 않은가

### 5. look at hub late

이번 턴에서 보인 것을 곧바로 hub로 선언하지 않는다.

반복 reread와 응축 흔적이 충분할 때만
hub candidate로 본다.

## mandatory reread surfaces

하나의 line이 잡히면 반드시 아래 5개 층위를 reread 대상으로 삼는다.

### A. document layer

- specs
- notes
- reports
- close-out
- directives / baselines

### B. code layer

- 관련 구조
- helper / adapter / formatter
- 실행 / 표면 / 경계 흔적

### C. runtime trace layer

- artifacts
- surfaced readout
- UI / operating surface 흔적
- handoff / parked / readiness / close-out trace

### D. reference layer

- 이미 공간 안에 들어온 외부 자료
- 현재 line과 직접 연결되는 reference 흐름

### E. user-language layer

- 사용자가 반복해 쓴 표현
- 비유
- 감각어
- “내 말로는” 계열 표현
- 구조를 받아들이는 인간 언어 흔적

## reread questions

각 층위에서 최소 아래를 본다.

### source trace

- 이 line은 어디서 처음 / 강하게 보였는가?

### modification trace

- 이 line은 어디서 수정되었는가?
- 어떤 자료 / 실패 / close-out 때문에 의미가 바뀌었는가?

### merge trace

- 이 line은 어떤 다른 선과 합류했는가?
- 어떤 운영 / 구현 / 철학 흐름과 연결되었는가?

### resistance / absence

- 이 line이 아직 약한 곳은 어디인가?
- reread가 잘 안 열리는 층위는 무엇인가?
- 현재는 parked가 맞는가?

### human-language reread

- 그래서 이 line은 내 말로는 어떤 선인가?
- 내가 다음에 다시 들어올 때 어떤 한 줄로 붙잡을 수 있어야 하는가?

## human-language requirement

매 reread의 끝에는 반드시 구조 요약과 별도로
human-language one-liner 또는 짧은 문단을 남긴다.

이건 번역 장식이 아니다.
이 human-language sentence도 line을 두껍게 만드는 흔적이다.

## premature naming and hub guard

아래를 통과하지 못하면 hub 선언 금지.

- 최소 2개 이상의 다른 자료층에서 반복 등장했는가
- 수정선이 실제로 붙었는가
- 다른 line과 합류 흔적이 있는가
- close-out / panel / artifact / note 중 둘 이상에 잔흔이 남았는가
- 이 line을 따라 다시 들어올 수 있는 재진입점이 생겼는가

하나라도 약하면:

- 아직 line trace 단계로 둔다
- hub candidate 이상으로 올리지 않는다

## material and line rule

항상 이 원칙을 지킨다.

- 재료는 깊게 읽고
- line은 얇게 잡고
- reread를 반복하게 만들고
- 반복 속에서 line이 두꺼워지게 하고
- hub는 뒤늦게 드러나게 한다

즉:

- line-first definition 금지
- material-first reread 허용
- hub-late emergence 유지

## output style

결과는 정의집이 아니라 line trace 또는 line chronicle 성격을 가져야 한다.

최소 아래가 보여야 한다.

- 이 line은 어디서 왔는가
- 어디서 수정되었는가
- 무엇과 합류했는가
- 지금 공간에서 무엇을 다시 읽게 하는가
- 내 말로는 어떤 선으로 붙잡히는가

## one-line conclusion

line은 공간을 채우는 칸이 아니라, 공간 전체를 다시 읽게 만드는 얇은 판독면이며, hub는 그런 line들이 반복 reread 끝에 뒤늦게 응결하는 면이다.
