# Space Output Surface Contract v1

## 1. Purpose

This contract defines the output surface for the space request orchestration package.

The goal is to keep the answer:

- user-facing
- structurally grounded
- usable

## 2. Output Priority

Priority order:

1. user-facing interpretation
2. structure-grounded judgment
3. usable output
4. uncertainty / reinjection judgment when needed

## 3. User-Language Surface Rule

The first visible layer should be in user language.

It should briefly state:

- what the user asked
- how the request was interpreted

## 4. Structural Judgment Surface Rule

The middle layer should explain:

- which assets were read
- what structure was found
- how the target maps into our space

This layer should remain bounded.

## 5. Usable Output Surface Rule

The answer must not stop at interpretation.

It should end in something the user can use now, such as:

- a structure proposal
- an applied mapping
- a draft
- a bounded recommendation

For reusable external-reference or merge work, add a short three-line operating close:

1. current position
2. can use now
3. should not use yet

## 6. Space / Model / External Marking Rule

The answer should keep visible when needed:

- what came from space assets
- what was model judgment
- what was externally reinforced

Do not collapse these into one opaque statement in mixed requests.

## 7. Uncertainty Rule

If uncertainty remains, state it near the end.

Uncertainty should be bounded:

- what is uncertain
- why
- what would need confirmation

## 8. Internal Explanation Limit

Do not let internal packet or route logic dominate the visible answer.

The user-facing surface should not read like an internal protocol dump.

## 9. Output Skeleton

Recommended visible order:

1. user request restatement
2. request interpretation
3. key assets used
4. structural reading result
5. usable output
6. current position / can use now / should not use yet
7. uncertainty / next confirmation
8. reinjection judgment if relevant

## 10. Contract Summary

The output surface succeeds when:

- the user can quickly see what the request became
- the structure judgment is legible
- the answer contains a usable result
- any reinjection judgment remains secondary and bounded
