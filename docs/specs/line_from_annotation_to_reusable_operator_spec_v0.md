# line from annotation to reusable operator spec v0

## verdict

- current lines are not yet fully reusable operators
- they are still closer to annotations than to transferable working units
- the next needed shift is from `marked importance` to `reusable line operator`

## why this matters

If a user changes only the object of the request, such as:

- writing
- ai paper
- presentation
- new feature
- internal structure
- script
- existing reference program

the underlying demand may still be structurally the same:

1. inspect a reference
2. inspect the space
3. recover relevant lines
4. reapply those lines to the current task
5. build something new

If lines were already reusable operators, this should become easier.

But the current space is not fully there yet.

## current problem

The space does have lines.

But many current lines are still closer to:

- “this was important here”
- “this concept was active here”
- “this notion was weak or thick here”

That is useful, but it is still too close to:

- underline
- highlight
- annotation

rather than:

- portable operator
- reusable transformation unit
- cross-task design lever

## current line state

Current lines can often do the following:

- mark recurring importance
- show local reaction
- support rereading
- support bounded human-language synthesis

But current lines still weakly do the following:

- travel cleanly from one task family to another
- tell us how they should be reapplied
- act as reusable design operators
- guide implementation transfer across changing objects

## what a reusable operator would require

A line begins to become a reusable operator only when it can answer not only:

- where did I appear?
- how strong was I?

but also:

- what kind of work do I help perform?
- what kind of target can I be applied to?
- what changes when the object changes but the structural demand stays the same?
- what transformation rule carries me from one context into another?

## difference between annotation and operator

### annotation-like line

- marks importance
- local
- retrospective
- says “look here”

### reusable operator-like line

- transferable
- task-aware
- structure-aware
- says “use me like this in the next context”

## why current space still leans annotation-like

Because current lines still mainly live as:

- local reading lenses
- reread traces
- meaning-rich commentary anchors

and not yet strongly as:

- reapplication units
- design-transfer units
- implementation-guiding operators

This is why the space can often say:

- what a concept became

but still struggles to say:

- how that line should be reused in a new build task with a different object

## practical test

A useful diagnostic question is:

If the object changes but the user’s structural intent stays the same, can the line still guide the work?

Examples:

- from ontology to harness
- from writing to code
- from paper reading to feature design
- from existing script to rebuilt program

If the line must be manually reinterpreted each time, then it is still too annotation-like.

## non-goals

- no claim that current lines are useless
- no denial of existing line thickening progress
- no immediate runtime redesign
- no forced operatorization of all lines

## current conclusion

- current lines are meaningful, but still too often behave like highlighted traces
- the next serious growth is to let lines become reusable operators
- that means a line must eventually support not just rereading, but reapplication across changing tasks and objects

## one-line summary

지금의 line은 이미 중요도를 표시하고 반복 의미를 붙잡을 수는 있지만,  
아직 다른 과업과 다른 목적어로 옮겨 쓸 수 있는 재사용 가능한 작동 단위로는 충분히 자라지 못했다.  
즉 현재 line은 operator라기보다 annotation에 더 가깝다.
