# vectorfl page local viewer entry lock v0

## 1. purpose

VectorFL Paper now has enough shell, route, organ, trace, and program drill-in
surfaces that a single runtime-facing entry page is needed for local inspection.

## 2. lock

The prototype should expose a dedicated local viewer entry page that groups:

- launchpad
- semi-live primary routes
- organ drill-in pages
- trace drill-in pages
- program drill-in pages

## 3. semantic rule

This runtime entry page is not a new semantic center.

- it is an inspection entry
- it organizes the current prototype for local viewing
- `Current Reading` remains the preferred semantic center once the operator enters

## 4. why this matters

Without a dedicated runtime entry page:

- the prototype remains scattered across generated artifacts
- local inspection order is unclear
- the operator has to remember paths manually

With a dedicated entry page:

- the prototype can be inspected as one evolving personal program
- the recommended entry order is explicit
- the shell and its drill-in surfaces are grouped coherently

## 5. current lockable outcome

At the current stage, the local viewer entry should point first to:

- launchpad
- semi-live current-reading
- semi-live cases/intake
- organ details
- trace details
- program details
