# hub centered line chronicle layer spec v0

## verdict

- this layer is not a translation layer
- this layer is not a simplified explanation layer
- this layer exists to explain a concept/hub by tracing the lines that entered it, modified it, merged into it, and thickened around it

## why this layer is different

There is a real difference between:

- explaining the space
- and writing a line chronicle around a hub

`space explanation` can stop at:

- structure summary
- operating summary
- conceptual summary

But `hub-centered line chronicle` must go further.

It must show:

1. what hub is being explained
2. what materials feed that hub
3. what lines enter that hub
4. where those lines are revised or resisted
5. what other flows merge into the hub
6. how that history becomes the hub’s current meaning in the space

So the output is not a parts manual.
It is a narrated line history.

## module identity

This layer should be understood as:

- a hub-centered rereading layer
- a line chronicle layer
- a human-language narrative layer for conceptual hubs

It is not:

- a dictionary layer
- a one-shot summary layer
- a structure-only explanatory layer

## core sequence

This layer must follow the sequence below:

1. select a concept/hub
2. recover relevant internal materials around that hub
3. trace repeated lines around the recovered materials
4. identify incoming lines
5. identify modification lines
6. identify merge lines
7. interpret how those line movements make the hub what it is now
8. narrate that chronicle in human-language prose

## minimum output contract

Every hub-centered chronicle should include the following elements.

### A. hub

- what kind of hub the concept currently is in the space
- not a general definition, but a functional hub identity

### B. source traces

- where it appears strongly
- which documents/notes/specs/close-outs reshape it
- which related streams should be included

### C. incoming lines

- which line families first bring the concept into the space
- this may include:
  - outside-definition lines
  - internal adoption lines
  - operating lines
  - philosophical lines

### D. modification lines

- where the concept gets revised, reversed, narrowed, or reframed
- examples:
  - general definition -> space-specific inversion
  - technical concept -> operating interpretation
  - structure explanation -> philosophical tension

### E. merge lines

- what other hubs, documents, or operating flows merge into this concept
- not random association, but traceable merging

### F. current meaning in this space

- what the concept currently becomes in the space after those line movements

### G. human-language chronicle

- this must be paragraph-based
- not bullet definition only
- it must narrate movement and transformation

## human-language chronicle rule

The chronicle must sound like:

- “it first appeared here as…”
- “inside this space it was revised by…”
- “then another flow merged into it through…”
- “because of that, it now lives in the space as…”

It must not sound like:

- “X means Y”
- “X is a tool for Z”

unless that sentence is part of a longer traced movement.

## line rule

This layer assumes that a concept becomes readable only after line movement is made visible.

That means:

- a concept is not explained by static definition alone
- it is explained by the lines that pass through it
- human-language prose is where that line history survives in readable form

So human language is not decorative output.
It is a survival layer for line history.

## material recovery rule

Use the closest hub and its trace first.

Priority:

- `docs/specs`
- `docs/notes`
- `docs/reports`
- `source_assets`
- related close-out / directive / baseline
- current operating / observation materials

Rule:

- do not scan the repo blindly
- start from the nearest hub documents
- expand only into connected tributaries

## non-goals

- no runtime or engine change
- no speculative new line creation
- no generic outside-knowledge explanation without trace
- no forced philosophical invention
- no broad redesign

## current conclusion

- concept explanation must now pass through hub-centered line tracing
- the correct output is not a brief definition but a line chronicle
- this layer is needed because the user does not just need what a concept is, but how it became what it is inside the space
