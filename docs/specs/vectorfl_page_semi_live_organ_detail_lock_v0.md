# vectorfl page semi-live organ detail lock v0

## 1. purpose

This lock keeps `organ detail` from remaining only a contextual summary strip.
At the semi-live stage, VectorFL Page should also expose bounded organ drill-in pages
that read the same runtime bridge through organ responsibility language.

## 2. lock

Semi-live organ detail pages are allowed as dedicated drill-in surfaces, but they do
not replace `Current Reading` as the semantic center.

They exist to make the following visible:

- organ identity
- instruction bundle preview
- accepted handoff contract
- caution profile
- recent return summary
- semi-live restriction / release / candidate status

## 3. required kinds

The first semi-live organ detail set is locked to two pages:

- `current`
- `governance`

This matches the existing route-aware shell where the current organ and the preferred
next governance candidate are the first contextual drill-in targets.

## 4. non-replacement rule

These pages do not become top-level semantic centers.

- `Current Reading` remains canonical center
- organ detail remains drill-in
- organ detail may deepen responsibility reading, but not redefine case meaning

## 5. data rule

Semi-live organ detail pages should be built from the same runtime bridge used by the
semi-live shell set.

They should not invent a separate fixture reality.

Minimum shared carries:

- current phase
- current decision or decision reason
- restriction flags
- release condition or next check trigger
- recent trace anchors

## 6. visibility rule

The dedicated organ detail page should make the following easier to inspect than the
contextual side panel:

- what this organ is supposed to do
- what it accepts
- what it must carry forward
- what it must not prematurely close
- what it most recently returned

## 7. relation to paperclip reference

This continues the Paperclip-native lesson without importing its ontology.

What is inherited is not `agent detail` naming, but the structural fact that a
runtime node may need a deeper detail surface for:

- configuration
- instructions
- recent run return
- current bounded status

VectorFL re-owns that rhythm as organ detail.

## 8. current lockable outcome

At the current stage, `semi-live organ detail` is locked as:

- a dedicated drill-in surface
- subordinate to current-reading-first semantics
- fed by the same runtime bridge as the semi-live route set
- focused first on `current` and `governance`
