# vectorfl internal recall and search surface lock v0

## purpose

VectorFL Paper must not stop at:

- line generation
- organ visibility
- routing visibility

It must surface the next meaning work:

- internal recall
- family density
- gap inspection
- external resource search
- lane comparison

## locked page classes

### internal recall

- role:
  - reopen declarations, directives, locks, and trace carry from a selected line
  - show line-family densification rather than isolated sentence output

### external resources

- role:
  - justify external search from an internal gap
  - record question set, wanted material type, excluded material type, and candidate source fit

### lane runs

- role:
  - compare read / apply / search / validate / report results across lanes
  - keep multi-lane work tied to the same internal recall basis

## principle

The sequence is:

- line
- family recall
- meaning expansion
- external search or adoption
- lane comparison
- return into internal assets

## non-goals

- no search backend wiring yet
- no lane execution backend wiring yet
- no canonical object change

These pages are surface-first operating classes that prepare the real workflow without flattening the VectorFL core.
