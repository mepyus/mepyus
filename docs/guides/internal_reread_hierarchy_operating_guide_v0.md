# internal reread hierarchy operating guide v0

## purpose

This guide explains how to use the current A / B / C layered judgment during live internal reread and closeout work.

It does not create a new axis.
It does not reopen promotion.

It gives a bounded reading order for current work.

## current layered reading

- `A = structure_before_freeform_agenting`
  - use as `higher operating principle`
- `B = bounded_surface_over_universal_agent_freedom`
  - use as `strongest provisional axis candidate`
- `C = maintenance_and_validation_discipline`
  - use as `maturation / validation governance grammar`

## default operating order

When reading a live internal work item, ask in this order:

1. `A question`
   - what must be fixed first before wider freedom or expansion is allowed?
2. `B question`
   - what bounded surface, role, slot, or attach boundary is this work trying to preserve?
3. `C question`
   - what is being held, watched, validated, logged, or kept partial instead of promoted?

This order matters.

Use A first to find the preconditions.
Use B second to find the organizing boundary.
Use C third to find the maturation state.

## what each layer is for

### A: higher operating principle

Use A when the work is really about:

- scope before expansion
- authority before action
- packet-worthiness before packet use
- expected return before implementation
- process object before panel growth

Ask:

- what is being required first?
- what is being blocked until structure is present?

Do not use A to flatten every record into one meta-axis.

### B: strongest provisional axis candidate

Use B when the work is really about:

- surface identity
- role-local density
- one-handler restraint
- attach boundary
- lower/upper object separation
- anti-universal-dashboard or anti-universal-agent pressure

Ask:

- what bounded organization is being protected here?
- what mixed-freedom reading is being refused?

Use B when you need the strongest regrouping lens.

### C: maturation / validation governance grammar

Use C when the work is really about:

- hold
- watch
- rollback
- pass-with-note
- recurrence logging
- no-promotion discipline
- reversible next action

Ask:

- what is being kept alive without being promoted?
- what evidence or recurrence is still being collected?

Do not re-describe C as the main organizing axis of the space.

## live-use entry points

### 1. reading a closeout note

Ask:

- A: what did the closeout insist had to be fixed first?
- B: what boundary or surface organization did it protect?
- C: what remained hold/watch/candidate-only after the closeout?

### 2. reading a failure or blocker note

Ask:

- A: which missing precondition caused the failure?
- B: did the failure come from boundary collapse or mixed role/surface reading?
- C: what bounded recovery or rollback state was preserved?

### 3. reading an adaptation / attachability note

Ask:

- A: what structure or bounded contract is required before adoption?
- B: what attach boundary or role split explains the decision?
- C: what still remains candidate-only or validation-only?

### 4. reading a new operating proposal

Ask:

- A: what is being proposed as a prerequisite?
- B: is there a real organizing boundary here, or only good wording?
- C: does the proposal respect hold / validation / recurrence discipline?

## quick anti-drift rules

- If the work is mainly about ordering or prerequisites, start with A.
- If the work is mainly about surfaces, roles, slots, or attach boundaries, start with B.
- If the work is mainly about hold, pass-with-note, rollback, logging, or delayed promotion, start with C.

- If two layers seem to overlap, do not flatten them immediately.
- First ask whether one is explaining organization and the other is explaining maturation.

## what not to do

- do not use B to promote an axis from one live note
- do not use C as a synonym for generic caution
- do not use A to explain every decision in the space
- do not reopen synthetic rounds just because one live note looks strong

## one-line summary

Use:

- `A` for what must come first
- `B` for how bounded organization is being protected
- `C` for how non-promoted material is being matured
