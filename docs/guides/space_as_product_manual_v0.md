# Space As Product Manual v0

## Purpose

This manual explains the current space as a product-like operating system, not as a loose document archive.

The goal is to answer:

- what this space actually is
- what kinds of work it supports
- how its major parts relate

## Product Definition

This space is best read as a memory-first operating engine.

It is not only:

- a report folder
- a prompt archive
- a UI shell
- a runtime log bucket

It is a layered product that turns:

- source material
- interpreted request
- bounded reading
- work packet / return / report
- reusable operating knowledge

into a continuing working space.

## The Five Main Product Layers

### 1. Source Layer

Primary zones:

- `inputs/`
- `source_assets/`
- `references/`

Role:

- raw input
- declarations / baselines / directives / handoffs
- imported external reference repos

### 2. Intake And Structuring Layer

Primary zones:

- `app/input_layer/`
- `app/work/observer_ingest_min/`
- `scripts/process_structured_doc_with_routing.py`

Role:

- load
- label
- split
- trace
- produce readable source-side artifacts

### 3. Operating / Packet Layer

Primary zones:

- `app/runtime/vectorfl_integrated_engine_api.py`
- `runtime/manifests/vectorfl_integrated_engine_*`
- `runtime/contracts/`

Role:

- interpret the current task
- form packets
- carry assignment / return / supervisor state

### 4. Surface Layer

Primary zones:

- `app/ui/integrated_engine/`
- `runtime/views/`
- `docs/guides/`

Role:

- show what the system is doing
- expose current readable operating surfaces
- give operators a bounded entry

### 5. Record And Reuse Layer

Primary zones:

- `runtime/manifests/`
- `runtime/events/`
- `runtime/receipts/`
- `docs/reports/`

Role:

- preserve what happened
- preserve latest pointers
- preserve reusable notes and bounded closeouts

## What This Product Is Good At

It is strong at:

- reading internal materials as structured operating assets
- turning mixed source material into readable support artifacts
- carrying bounded packet / return / reread loops
- comparing external structures against our own space
- preserving operating memory instead of forcing one-shot answers

## What It Is Not

It is not yet:

- a fully automatic runtime
- a canonical self-updating product database
- a single unified engine with all historical layers removed
- a user-friendly consumer app

It still contains overlapping historical layers.

## The Product Reading Rule

Do not start by asking:

- what folder is important?

Start by asking:

- what kind of work are we trying to do?

Then choose the right layer:

- source / intake
- packet / runtime
- surface
- reports / receipts
