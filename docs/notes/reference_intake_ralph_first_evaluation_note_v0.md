# reference intake / ralph first evaluation note v0

## 0. verdict

`references/ralph`는 도입 대상이 아니라
`selective adoption + deferred memory` 대상으로 남기는 것이 맞다.

즉 Ralph 전체를 가져오지 않는다.
하지만 Ralph가 선명하게 보여준 line은 지금 바로 calibration memory로 쓸 수 있다.

---

## 1. what Ralph actually brought in

이번 first evaluation에서 Ralph가 강하게 들고 온 line은 아래다.

- fresh-context iteration
- externalized working memory
- task atomization before autonomy
- pattern consolidation as reusable memory
- binary closure discipline

이 중 현재 우리 공간에 바로 유효한 것은
`memory outside session`, `pattern carryover`, `repeatable loop discipline` 쪽이다.

---

## 2. what is worth bringing now

지금 가져올 만한 것은 아래다.

- 세션 안이 아니라 바깥 파일에 기억을 둔다는 감각
- reusable pattern을 별도 축으로 끌어올린다는 감각
- 큰 과업을 실행 하네스에 맞게 자를 수 있다는 감각

이것들은 현재 공간의
`trace / receipt / calibration memory / feature-change reason material`
방향과 잘 닿는다.

이번 재독해에서 더 분명해진 것은
Ralph의 핵심이 단순 반복이 아니라
`기억을 세션 안에 두지 않고 파일/기록 바깥으로 밀어내는 운영 감각`
에 있다는 점이다.

즉 우리에게 지금 더 유효한 것은
무한 루프 그 자체보다
`외부화된 working memory + 반복 가능한 task slicing`
감각이다.

---

## 3. what should stay in references for now

지금은 `references/`에 두고 바로 가져오지 않을 것은 아래다.

- `passes: true/false` 중심 이진 닫힘
- PRD-first front door
- one-story-per-iteration completion discipline

이건 지금 공간의
`hold / calibration / reread / delayed condensation`
보다 closure를 너무 앞당길 위험이 있다.

즉 지금은 useful하되, 아직 timing이 이르다.

---

## 4. why not-needed reasons must be remembered

지금 안 쓰는 이유를 남기는 게 중요하다.

왜냐하면 Ralph가 쓸모없어서가 아니라,
우리 공간의 현재 성숙 단계와 맞지 않기 때문에 미루는 것이기 때문이다.

따라서 비채택 이유는 아래처럼 기억돼야 한다.

- 지금은 line 숙성보다 execution closure가 빠르다
- 지금은 PRD 분해보다 reread가 먼저다
- 지금은 binary pass보다 meaning thickening이 먼저다

이 이유를 남겨야,
나중에 공간이 커졌을 때
Ralph의 어떤 조각을 다시 열 수 있는지 보인다.

---

## 5. future reopen condition

아래 조건이 오면 Ralph 계열을 다시 읽을 수 있다.

- line thickening 결과가 실제 구현 branch로 자주 이어질 때
- feature-change reason material이 반복적으로 쌓일 때
- reread-first가 유지된 상태에서 bounded execution harness가 필요할 때

즉 reopen 조건은
“Ralph가 좋아 보여서”가 아니라
“우리 공간이 그 레일을 받아도 premature closure로 무너지지 않을 만큼 두꺼워졌는가”
여야 한다.

또 하나의 기준은
현재처럼 `session 바깥 기록` 중심으로 갈지,
아니면 나중에 `session 안 self-loop`도 받아들일지의 차이를
명시적으로 판단할 수 있을 만큼 inspection 축이 자랐는가이다.

---

## 6. one-line conclusion

Ralph는 지금 우리 공간이 당장 채택할 운영 본체는 아니다.
하지만 나중에 execution harness를 얹을 때 다시 열어볼 가치가 큰 calibration reference이며,
그 이유와 보류 이유를 처음 평가 시점부터 함께 기억해야 한다.
