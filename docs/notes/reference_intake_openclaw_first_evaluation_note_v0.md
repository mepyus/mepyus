# Reference Intake — OpenClaw First Evaluation Note v0

## Current reading

`openclaw-main` should not be treated as a ready-made system to copy.

It should be treated as a **high-density runtime organ reference**.

The useful shift is this:

- Ralph shows a later execution memory rail
- Claude Code main shows later hook/plugin workflow surfaces
- autoresearch shows later bounded experiment rails
- OpenClaw shows what happens when many of those lines become an actual runtime body

## What it brings now

- context as a managed engine surface
- approval as typed runtime classification
- lane-aware orchestration
- plugin growth under strict runtime/loader boundary
- assistant embodiment across channels/apps/tools

## Why it is not "adopt now"

Our current space is still reread-first and maturation-first.

OpenClaw is valuable precisely because it reveals later embodiment possibilities, but that also means:

- its organ density is too rich to become our current front door
- importing that body now would likely outrun our internal line thickening
- we need the line first, then the organ

## Current role

For now OpenClaw should remain:

- a calibration reference
- a later component shelf
- a mirror for runtime embodiment possibilities

not:

- the next architecture to imitate
- the current operating front door
- a substitute for our own line maturation work

## Reopen direction

OpenClaw becomes more directly useful later if one or more of our own lines become thick enough that they clearly deserve:

- a context engine organ
- an approval organ
- a lane/scope organ
- a guarded loader/runtime organ

Until then, it remains a high-value reference for later embodiment rather than current adoption.
