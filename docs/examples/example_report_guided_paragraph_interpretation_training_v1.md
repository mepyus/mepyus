# 예시서 — 리포트 기준 단락 해석 훈련 예시

## 0. 왜 이 예시가 필요한가

Codex는 이 작업을 쉽게
“문단별 주석 달기”
혹은
“문단 요약”
으로 오해할 수 있다.

하지만 이번 훈련의 목적은 다르다.

목적은
**단락을 전체 그림 속 역할 단위로 읽는 연습**
을 하게 하는 것이다.

---

## 1. 잘못된 접근 예시

### 잘못된 방식
- 문단 1: 무슨 내용인지 요약
- 문단 2: 무슨 내용인지 요약
- 문단 3: 무슨 내용인지 요약

이건 정보 정리일 뿐이다.
이번 훈련이 아니다.

왜냐하면 여기엔
- 전체 흐름
- 전환점
- 객체 성장
- 질문 유도
- 비교 맥락 차이
가 없다.

---

## 2. 올바른 접근 예시

예를 들어 `Bundle-Unbundle` 관련 블록을 본다고 하자.

### A. 특정 맥락 안에서 읽기
이 블록은
- `에이전트 애플리케이션`
- `전략/방향성`
- `구현/자동화`
를 같이 붙여 준다.

따라서 이 단락은 단순 설명이 아니라
**question_seed_block**
또는
**strategy_pivot_block**
처럼 읽힌다.

### B. 전체 페이지 안에서 읽기
전체 페이지 흐름 안에 놓으면
이 단락은 단순 사례 설명이 아니라,
기술 전망을 사업 구조 재편 문제로 끌어내리는
**전환점**처럼 보인다.

즉 단독으로는 사례,
전체에선 pivot이다.

### C. 다른 맥락과 비교하기
`future_of_work_supervisor_unit` 쪽 단락과 비교하면
이 단락은 노동 역할 변화가 아니라
앱 구조와 moat 변화 쪽에 더 강하게 기운다.

즉 둘은 둘 다 “AI 시대 변화”를 말하지만,
여는 층위와 역할이 다르다.

---

## 3. 이 예시가 주는 학습

이 예시는 아래를 보여준다.

- 같은 단락도 맥락 안에서 역할이 생긴다
- 전체 흐름 속에 놓이면 전환 의미가 더 강해진다
- 다른 맥락과 비교하면 차이가 더 선명해진다
- 따라서 단락 해석은 내용 요약이 아니라 역할 판독이어야 한다

---

## 4. 한 줄 예시 잠금

> **단락 해석 훈련의 목적은 문단별 내용을 더 잘 정리하는 것이 아니라, 같은 단락이 특정 맥락, 전체 흐름, 비교 맥락 속에서 어떤 다른 역할과 의미를 가지는지 보는 눈을 Codex에게 익히게 하는 것이다.**
