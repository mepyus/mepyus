# order structure baseline v0

## 0. One-line definition

This baseline fixes the minimum operating order of the space:
latent line first, then reread, then record, then evaluate, then place, then refine.

It prevents the project from collapsing into content-first scanning or structure-first freezing.

## 1. Purpose

This baseline exists to keep the current order readable and stable without hard-freezing still-forming lines.

It answers:

1. What must be read first.
2. What must be recorded next.
3. What must be judged by evaluator.
4. Where each artifact should live.
5. What stays latent until the evidence is strong enough.

Core sentence:

**The space must preserve order of reading, order of recording, order of evaluation, and order of placement without merging them into one layer.**

## 2. The minimum order

### 2.1 Read order

The reading order is:

1. latent line appears
2. reread follows the latent line
3. related material is inspected
4. the reread trace is recorded

This prevents content-first scanning.

### 2.2 Record order

The record order is:

1. event occurs
2. breadcrumb / decision / rejection / hold is appended
3. summary surface is derived
4. current state is refreshed

This prevents current-state summaries from becoming the truth archive.

### 2.3 Evaluation order

The evaluation order is:

1. concept-to-implementation map
2. build drift anchor
3. implementation eval criteria
4. implementation placement
5. minimal auto checks

This prevents implementation from drifting before the build is anchored.

### 2.4 Placement order

The placement order is:

1. baseline surface
2. append-only log surface
3. runtime summary surface
4. evaluator surface
5. latent / observation surface

This prevents definitions, logs, summaries, and evaluators from being mixed.

## 3. The five layers

### 3.1 Baseline layer

Role:

- philosophy
- rules
- forbidden mappings
- classification criteria
- higher-order judgment principles

### 3.2 Current-state layer

Role:

- summary of the latest decision
- fast reading surface

This layer is not the truth archive.

### 3.3 Event-record layer

Role:

- append-only trace of what happened
- why it happened
- why it did not happen

### 3.4 Decision / implementation layer

Role:

- evaluator
- state decision
- minimal auto checks
- implementation functions

### 3.5 Latent / observation layer

Role:

- still-unconfirmed lines
- watchpoints
- possible branches
- weak but repeated signals

## 4. Order constraints

### 4.1 Do not collapse order into one file type

Do not store rules, events, state, and evaluations in one mixed surface.

### 4.2 Do not promote latent signals too early

Latent lines remain observations until evidence is strong enough.

### 4.3 Do not let summary surfaces replace logs

Current state is a summary.
The append-only logs are the record.

### 4.4 Do not let evaluators own truth archives

Evaluators compute decisions.
They do not become the archive.

### 4.5 Do not hard-freeze still-forming lines

Soft separation comes first.
Hard freeze comes later.

## 5. Conceptual chain

The canonical chain is:

1. raw / source material
2. pre-read gate
3. latent line selection
4. reread target selection
5. breadcrumb / decision record
6. current-state summary
7. implementation descent or rejection / hold
8. review / reopen / next-check trigger

## 6. What this baseline protects

- order of reading
- order of recording
- order of evaluation
- order of placement
- order of promotion

## 7. One-line conclusion

> order structure baseline keeps reading, recording, evaluation, placement, and latent observation in a stable sequence so the space can remain rereadable without hard-freezing emergent lines too early.
