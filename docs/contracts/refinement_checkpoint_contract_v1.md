# refinement_checkpoint_contract_v1

## purpose
엔진이 풍부해지더라도 코어가 비대해지지 않도록
주기적 정련 패스에서 무엇을 점검해야 하는지 고정한다.

## refinement reading
- 참조 점검기는 상시 통제 장치가 아니다.
- 선언문 / 기준문 / 지시서는 주기적 정련용 참조 거울이다.
- 정련의 목적은 삭제가 아니라 재배치에 의한 경량화다.

## core keep candidates
- 값
- 라벨
- 앵커
- 기본 관계 축
- 기록의 버팀 구조
- session / run / pointer 회수 구조
- 반복해서 살아남는 최소 판단 슬롯

## outer keep candidates
- 긴 해석 문장
- 풍부한 비교 설명
- 외부 기술 사례 상세 분석
- observer 장문 결과
- 참조 재료를 통한 의미 강화 상세 로그

## refinement questions
- 최근 쌓인 것 중 무엇이 코어에 남을 만큼 반복되었는가
- 무엇은 아직 가능성은 있지만 코어에 넣기엔 이른가
- 무엇은 observation layer로 빼는 것이 맞는가
- 무엇은 선언문/기준문과 충돌하는가
- 무엇이 구조를 또렷하게 하고 무엇이 구조를 흐리게 하는가
- 이번 정련 후 코어는 더 작아졌는가

## operation rule
- 평소에는 공간이 자라게 둔다.
- 기록과 기억은 계속 append 한다.
- 일정 시점마다 참조 점검기를 흘려보낸다.
- 정련 결과는 코어 축소와 외곽 재배치로 반영한다.

## current recommendation
- LLM 답변 구조 슬롯은 먼저 report / sidecar / observation 레이어에 붙인다.
- 반복성이 확인된 최소 슬롯만 코어 후보로 올린다.
- 정련 전에는 풍부함을 코어로 오인하지 않는다.
