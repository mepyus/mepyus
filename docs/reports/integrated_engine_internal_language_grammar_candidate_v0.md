# Integrated Engine Internal Language Grammar Candidate v0

Date: 2026-04-15

## 0. verdict

PASS_WITH_NOTE

This document records current candidate grammar rules for internal integrated-engine language.

It is not a final SSOT, schema, enum set, workflow engine, UI wording plan, translation guide, or glossary replacement. It only describes how meaning appears to move in the current records.

## 1. grammar boundary

These rules are candidates because they are repeated across:

- v1 candidate lexicon / protocol / interface
- manual S1/S2/S3 observations
- use-state and wording-watch closeouts
- translation friction records
- Gemini/Codex collaboration boundary notes

They should be tested against at least one more real use or handoff trial before external style harvest or user-facing bridge wording.

## 2. route grammar

Rule:

- A meaningful route begins when a packet, signal, or state change has a source, target, purpose, and reason for movement.

Starting points:

- user-origin request
- VectorFL maturation signal
- engine return material
- anchor drift signal
- Gemini proposal material

Transition conditions:

- request enters VectorFL review before execution
- VectorFL review attaches directionality, anchor context, related objects, validation points, and route judgment
- engine processing creates return material, not final completion
- return validation decides user decision, reflux, or reprocess
- reflux preserves maturation-worthy material for future reread
- proposal material moves only after Codex translation and user/scoped permission

Brake or hold criteria:

- anti-bypass violation
- anchor drift
- missing route reason
- unsupported promotion
- fixture or trace expectation leaking into core

Ownership / authority change:

- user intent becomes request packet through user-surface organization
- engine output becomes return packet through processing
- return material becomes validation subject on VectorFL surface
- Gemini material becomes usable only after Codex translation/classification and user decision if promotion is needed

Operational signal:

- `request`, `return`, `reflux`, `follow-up`, `reprocess`, and `rewind` are not just labels. They indicate allowed movement and required reading order.

## 3. authority grammar

Rule:

- Authority is surface- and workspace-scoped; it does not transfer by visual strength, file existence, or agent confidence.

Starting points:

- user surface organizes operating work
- VectorFL validates and mediates meaning route
- engine processes shaped input
- Gemini produces proposal material
- Codex translates against baseline and writes canonical artifacts when scoped

Transition conditions:

- operating decision stays on user surface unless routed through validation
- validation stays on VectorFL surface unless user decision is explicitly requested
- execution stays on engine surface and returns material for validation
- Gemini output stays proposal-only until translated, classified, and explicitly used

Brake or hold criteria:

- engine begins to look like judgment authority
- user surface becomes team/role governance console
- VectorFL becomes engine executor or line browser as center
- Gemini output requires core edits or runtime/read-map changes to make sense

Ownership / authority change:

- promotion requires user decision or explicitly scoped package
- canonical docs/scaffold changes are Codex-owned unless separately opened
- Gemini writes under `gemini/` and remains proposal or review evidence

Operational signal:

- `proposal-only / needs Codex translation`, `workspace ownership`, and `no direct Gemini-to-core path` are authority controls, not process decoration.

## 4. hold / watch grammar

Rule:

- Hold and watch states keep material visible while preventing premature action.

Starting points:

- recoverable wording ambiguity
- fixture-scope limitation
- core-support trace thinness
- selected-object expectation
- future extension candidate

Transition conditions:

- `not promoted` means no patch planning is active
- `watch keep` means observe during use, do not implement
- `hold` means keep out of current core unless a gate opens
- `closeout` records the current lockback state

Brake or hold criteria:

- S2-only blind ambiguity
- supported reread recovers intended route
- no scenario reading blockage
- issue is fixture scope, trace density, selected-object absence, or runtime binding absence

Ownership / authority change:

- watch can move toward gate review only through official re-entry evidence
- gate review does not itself create patch wording
- patch planning remains closed until explicitly opened

Operational signal:

- `not promoted`, `watch keep`, `hold`, and `closeout` are active operating states. They are not passive notes.

## 5. validation grammar

Rule:

- Validation is the point where output, route, and anchor fit are checked before closure or next movement.

Starting points:

- engine return packet
- follow-up return
- anchor comparison result
- Gemini handoff material

Transition conditions:

- engine output goes to VectorFL validation before user decision, reflux, or reprocess
- anchor drift can prevent user decision and rewind to reprocess
- Gemini output must be classified before any canonical use

Brake or hold criteria:

- return looks complete but lacks validation
- anchor mismatch appears
- proposal material needs baseline translation
- supported reread fails to recover route or authority separation

Ownership / authority change:

- engine owns processing output
- VectorFL owns return validation and drift mediation
- user owns promotion and decision opening
- Codex owns canonical translation when scoped

Operational signal:

- `return validation`, `anchor drift`, `recheck`, and `reprocess` are route-control signals, not descriptive afterthoughts.

## 6. reread / support grammar

Rule:

- First-pass thinness can be acceptable when supported reread restores the intended route without changing structure.

Starting points:

- blind first-pass ambiguity
- compact trace
- first-fixture-centered read map
- support panel with operational meaning

Transition conditions:

- read central panel first
- read mapped packet/object next
- read support panels after center
- read connection records for route reconstruction
- classify confusion before patch consideration

Brake or hold criteria:

- support reread fails
- request / return / reflux remain confused after support
- support panel becomes central body
- trace expectation turns into selected-object or runtime-binding demand

Ownership / authority change:

- if reread recovers, item remains watch or non-issue
- if reread fails across scenarios, gate review may reopen

Operational signal:

- `support reread recovery` is a use-mode mechanism. It is not a replacement for future UI design, and it is not proof that every wording is final.

## 7. bridge-before-flatten grammar

Rule:

- Human-facing bridge work must preserve route, authority, state, boundary, and support relationships before simplifying terms.

Starting points:

- friction terms such as `reflux`, `anchor drift`, `return validation`, `proposal-only`, and `workspace ownership`

Transition conditions:

- collect internal phrase and context
- identify what the phrase protects
- identify what flattening would lose
- only then attempt bridge wording in a later package

Brake or hold criteria:

- easy phrase erases authority ownership
- easy phrase erases route reason
- easy phrase turns hold/watch into action
- easy phrase turns support trace into full runtime truth

Ownership / authority change:

- bridge wording does not change core baseline
- translation does not promote features
- bridge candidates require later use evidence and scoped package

Operational signal:

- Bridge work is a layer after internal grammar harvest. It must not replace the internal grammar before the grammar is tested.

## 8. candidate closeout

The strongest grammar candidates to carry forward are:

1. route must carry reason and validation status
2. authority is scoped by surface, workspace, and promotion gate
3. hold/watch keeps material visible without opening build mode
4. validation can brake or rewind a route
5. supported reread can recover thin first-pass meaning
6. bridge work must preserve internal movement before simplifying language

These are current candidates only. They should be tested against one more real use or Gemini/Codex handoff trial before being promoted into a stronger language guide.
