## 4. Why The Direction Is Structurally Correct

The recent Queue 001 and Space Intake tests showed a real pattern:

```text
Gemini can execute bounded evidence work quickly.
Codex can package Gemini evidence into process-memory and mistake-memory.
Gemini can overrun scope, and those overruns can contain both mistake and signal.
Codex needs a formal place to separate mistake from signal and turn repeated process residue into reusable structure.
```

This means the target is not "read more external materials."

The target is:

```text
form the place where a future function/tool/process can attach.
```

That place must exist before function attachment, otherwise external functions become direct tool adoption, ad hoc automation, or archive-only notes.

Key sentence confirmed:

```text
Structure is not organizing records neatly.
Structure is making previous records reusable as material for the next judgment and execution.
```

## 5. What Is The Real Object Being Structured

The real object is not a specific function, API, agent, or external material.

The real object is:

```text
a repeatable prework unit that transforms a possible function/tool/material into a space-readable process asset before attachment.
```

This object should preserve:

```text
why the User brought it in
what it is

what prior records are relevant

```

Therefore every prework result needs a discard/hold path, not only a maturation path.

## 7. Minimum Viable Structure

Do not build all proposed components as separate systems yet.

Minimum viable structure should be one compact record with five sections:

```text
1. Function Candidate Card
2. Prior Record Retrieval
3. Process Asset Unit
4. Reuse Hook
5. User Decision Gate
```

### 7.1 Function Candidate Card

Purpose:

```text
identify what arrived before deciding what to do with it.
```

Minimum fields:

```text
candidate_id
source_or_material
user_purpose
candidate_type = external_material / function / tool / API / agent / workflow_claim / unknown
possible_role = worker / lens / camera / validation tool / memory helper / packetizer / process aid / reject / unknown
authority_status = candidate only
what_must_not_be_inferred
```

### 7.2 Prior Record Retrieval

Purpose:

```text
prevent the new candidate from being read in isolation.
```

Minimum fields:

```text
relevant_current_position
related_process_memory
related_mistake_memory
related_watch_items
related_line_axis_lens_camera_records
related_package_or_external_reference_records
retrieval_uncertainty
```

### 7.3 Process Asset Unit

Purpose:

```text
capture the process used to evaluate the candidate, not only the candidate itself.
```

Minimum fields:

```text
evaluation_steps
Gemini_evidence_used
Codex_structural_reread
mistake_events
watch_items
line_axis_lens_camera_effects
recovery_decision
discard_or_hold_reason_if_any
```

### 7.4 Reuse Hook

Purpose:

```text
make the result findable as process material later without turning it into authority.
```

Minimum fields:

```text
reuse_when
reuse_for
do_not_reuse_for
proposal_trigger_candidate
required_user_decision
repeat_risk
```

### 7.5 User Decision Gate

Purpose:

```text
keep formation separate from adoption.
```

Minimum fields:

```text
decision_needed_now = yes/no
safe_default = hold / process_memory_light / candidate_reference_only / watch_only
what_User_may_choose_later
what_Codex_may_propose_later
what_Gemini_may_execute_later
```
