# second-order object lift hold basis v1

## 1. purpose

- 이 문서의 목적은 `object lift hold`를 막연한 보수성이나 감각이 아니라, 실험 기반 구조 판정이자 아직 열어둘 상태의 공식 기록으로 명문화하는 것이다.

## 2. current hold basis

- direct grounded evidence가 아직 부족하다
- question-inducing candidate가 비교 도메인에서 안정적으로 회복되지 않는다
- pivot / compression은 weak or absent 수준이다
- context unit은 fallback grounding 중심이다
- role 계열은 heading-independent probe 이후에도 weak_medium 수준이다
- object naming은 여전히 AI dialogue carryover 위험을 가진다

## 3. why this is structural, not emotional

- segmentation은 필요조건을 복구했지만 충분조건이 아니었다
- pointer는 grounding coverage를 늘렸지만 대부분 fallback 수준이었다
- heading은 hard failure를 줄였지만 role institution을 generalized system으로 복구하지 못했다

즉 hold 이유는
- 아직 좀 불안함
- 더 보고 싶음
이 아니라,

**현재 회복이 대부분 weak / fallback / partial 수준에 머물러 있기 때문**이다.

동시에 이 hold는 탈락 판정이 아니라,
현재 흔적들을 더 오래 열어 두기 위한 deferred openness 기록이다.

## 4. current hold dimensions

- `segmentation_hold`
  - 다양성은 회복됐지만 question-inducing / pivot recovery는 미약함
- `grounding_hold`
  - direct grounded support가 부족하고 fallback 의존이 큼
- `role_hold`
  - role-like reading은 보이나 generalized paragraph-role recovery는 없음
- `naming_hold`
  - naming carryover / overfire 위험이 남아 있음
- `evidence_hold`
  - cross-domain evidence가 아직 약함

## 5. minimum release-discussion conditions

- direct-grounded context unit이 반복적으로 확보될 것
- question-inducing candidate가 비교 도메인에서도 `0`이 아닐 것
- pivot / compression 또는 role shift 계열 중 일부라도 weak를 넘어 반복 회복될 것
- unsupported naming 없이 evidence-linked candidate가 누적될 것
- scaffold-bound failure가 눈에 띄게 줄어들 것

## 6. why release discussion is still premature

- 현재는 `better-supported hold`, `fallback-grounded hold`, `weak role-like hold` 정도의 상태만 확인됐다
- 이것은 object lift를 논의할 최소 출발점은 될 수 있어도, 해제 근거는 아니다

## 7. one-line summary

> object lift hold는 rejection이 아니라 deferred openness다. 현재 회복된 항목 대부분이 아직 weak / fallback / partial 수준이라 상위 객체 승격의 직접 근거로 쓰기 어렵기 때문에, 더 많은 시간과 재료를 위해 열어 둔 채 유지된다.
