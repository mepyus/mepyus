# youtube_03_29 claude_code latent lines reread v1

## 1. 이 문서의 목적

이 문서는 `youtube_03_29.md`를 단순 요약하기 위한 문서가 아니다.

목적은 `claude_code`에서 추출한 3개 잠복 선을 이 입력에 대입해,
이 문서가 우리 공간의 하네스 / 흡수 / 정렬 선을 어떻게 다시 드러내는지 읽는 것이다.

즉 이 문서는 `claude_code latent lines bridge v1`의 적용 읽기다.

## 2. 입력의 현재 위치

- input: `inputs/external_cases/youtube_03_29.md`
- doc_id: `doc_youtube_03_29`
- receipt: `runtime/receipts/doc_youtube_03_29_operation_receipt.md`
- origin map: `runtime/manifests/origin_maps/doc_youtube_03_29_receipt_seed_origin_map.json`
- operator summary: `app/work/observer_ingest_min/generated/operator_summary_youtube_03_29_20260401_205101.md`

이 입력은 structured intake를 통과했고, `note` 성격의 mixed input으로 읽혔다.
분해 결과는 heading 기반 26개 unit이다.

## 3. claude_code에서 가져온 3개 잠복 선을 이 입력에 대입하면

### 3.1 harness_over_model

- 적용 이유:
  - 이 입력은 Andrej Karpathy / Claude Code / Codex / Anthropic / 오토리서치 / 하네스 비교를 중심으로 읽히기 때문이다.
- 이 입력에서 보이는 evidence:
  - `manifest의 시대`, `program.md가 manifest`
  - `Claude Code와 Codex를 8개씩 띄워놓고 일을 시킨다`
  - `AI 과학 블로그`, `vibe physics`, `대학원생으로서의 Claude`
  - `GAN에서 영감받은 Anthropic의 멀티 에이전트 하네스 설계 가이드`
  - `Claude Code의 바닐라 하네스 철학 비교`
- 읽기:
  - 모델보다 manifest / harness / loop / evaluator가 앞에 선다.
  - 이 입력은 모델 능력 자체보다, 그것을 감싸는 작업 설계가 본체가 된다는 쪽으로 읽힌다.

### 3.2 work_absorption_harness

- 적용 이유:
  - 이 입력은 작업을 시스템 안으로 빨아들이는 장치, 즉 program / manifest / loop / agent / evaluator 설계를 반복적으로 말하기 때문이다.
- 이 입력에서 보이는 evidence:
  - `program.md` 하나와 `train.py`, `prepare.py`를 묶어 자기 자신을 갱신하는 구조
  - 오토리서치가 문서 / 연구 / GitHub repo / 모델을 토큰 투입으로 최적화하는 루프
  - Claude를 대학원생처럼 지도하면서 논문을 만들고, 프롬프트와 피드백으로 작업을 흡수하는 설명
  - `에이전트가 못하는 것이 당신의 일이다`
  - `현재 수요가 늘고, 사람이 직접 안 하는 일과 도구가 맡는 일이 재배치된다`
- 읽기:
  - 결과물보다 작업을 시스템이 흡수하는 구조가 더 중요하다.
  - 이 입력은 생성물 자체보다, 생성 구조를 만들고 그 구조가 다시 사람의 일을 흡수하는 방향을 강하게 보여준다.

### 3.3 alignment_before_autonomy

- 적용 이유:
  - 이 입력은 plan mode, evaluation, semi-formal language, controllability, teacher/student style guidance를 계속 강조한다.
- 이 입력에서 보이는 evidence:
  - `plan mode`를 먼저 세우고 `accept/edit`를 나눈다
  - 검증 가능해야 자동화된다
  - 오토리서치도 목표와 evaluation이 분명해야 한다
  - `semi-formal language`가 필요하다
  - 인간-AI 하이브리드가 더 오래 지배할 수 있다
  - `vibe physics`에서 Claude를 대학원생처럼 매니징한다
- 읽기:
  - 완전 자동화보다 먼저 정렬과 제어 가능성이 선행된다.
  - 이 입력은 autonomy보다 alignment, uncontrolled generation보다 gate/plan/evaluation을 더 앞에 둔다.

## 4. 우리 공간의 기존 잠복 선과 연결하면

### 4.1 harness_over_model -> pre_read_eye / transition_over_surface

- 이 입력은 모델 소개보다 하네스/manifest/loop가 본체라는 점을 강조한다.
- 우리 공간에서는 이것이 preflight / mode-first / transition-first reading과 맞닿는다.
- 즉 페이지나 표면보다, 읽기 전에 무엇을 세팅할 것인가가 먼저다.

### 4.2 work_absorption_harness -> input_to_reading_organ

- 이 입력은 command / manifest / skill / multi-agent harness로 작업을 흡수한다.
- 우리 공간에서는 입력 / 기록 / 관찰이 단순 보관이 아니라 읽기 기관의 재료가 되는 방향과 같다.
- `raw -> first-pass -> report -> observation` 경로를 기관화하는 쪽으로 읽힌다.

### 4.3 alignment_before_autonomy -> pre_read_eye

- 이 입력은 plan-first, verify-first, gate-first를 강하게 말한다.
- 우리 공간의 preflight gate, drift guard, selected_mode-first reading과 같은 방향이다.

## 5. 이 입력에서 특히 강하게 읽히는 문장들

- `program.md가 manifest`
- `모든 것은 검증 가능해야 자동화된다`
- `Claude를 대학원생처럼 지도한다`
- `plan mode를 먼저 시작한다`
- `class of tasks를 command / skill / trigger로 흡수한다`
- `에이전트가 못하는 것이 당신의 일이다`

이 문장들은 단순한 AI 활용 팁이 아니라,
작업을 하네스로 감싸고 정렬과 제어를 먼저 둬야 한다는 구조를 드러낸다.

## 6. 이 입력을 통해 우리 공간에서 다시 확인되는 것

- 읽기 전에 먼저 mode / phase / drift를 정해야 한다.
- raw, first-pass, report, provenance를 분리해야 한다.
- command / skill / trigger는 작업을 흡수하는 구조로 읽어야 한다.
- plan / evaluate / observe가 autonomy보다 먼저 와야 한다.

즉 `youtube_03_29.md`는 `claude_code`에서 뽑은 잠복 선이 다른 데이터형 입력에서도 살아나는지 확인해주는 대입면이다.

## 7. 현재 가장 강한 선

- 가장 강한 선:
  - `alignment_before_autonomy`

이유:
  - 이 입력은 반복적으로 plan-first / evaluation-first / controllability-first를 말한다.
  - 단순히 하네스를 칭찬하는 데서 끝나지 않고, 자동화 전에 정렬을 먼저 세우라고 계속 밀어준다.

## 8. 그다음으로 강한 선

- `harness_over_model`

이유:
  - manifest, program.md, harness, multi-agent, evaluator, agent-as-student 같은 표현이 매우 직접적이다.
  - 모델보다 바깥 레이어가 본체라는 읽기가 강하다.

## 9. 아직 상대적으로 약한 선

- `work_absorption_harness`

이유:
  - 분명히 강하지만, 이 입력은 result absorb보다는 research/manifests/autonomy framing이 더 중심이다.
  - 작업 흡수는 보이지만, `claude_code.txt`만큼 command/skill/trigger 구조가 전면적이지는 않다.

## 10. 앞으로 새 observation에서 무엇을 보면 이 선이 짙어진다고 볼 수 있는가

- harness_over_model:
  - manifest / harness / eval / outer loop가 model description보다 먼저 서술되면 짙어진다.

- work_absorption_harness:
  - 작업이 command / skill / template / agent loop로 시스템 내부에 흡수되면 짙어진다.

- alignment_before_autonomy:
  - plan / verify / gate / semi-formal / controllability가 autonomy보다 앞서면 짙어진다.
