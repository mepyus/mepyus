## What The Loop Actually Found

The 10-loop did not produce final Korean UI wording. It produced repeated internal-language material that can be read as line / connection / axis evidence.

The strongest repeated finding is that the next language step is not "translate every engine term into Korean." The stronger pattern is:

1. First make the operating state readable.
2. Preserve route / authority / state / boundary.
3. Let repeated lines become connections.
4. Let repeated connections become axes.
5. Only then decide what belongs in a fixed interface or visible wording.

## Main Axes Found

### 1. Readable Report Before Visible Translation

The loop repeatedly found that Codex needs a stable report grammar before visible Korean UI wording is patched. The user needs a readable explanation of what happened and what decision is open, but that is not the same as replacing all internal language with polished Korean copy.

Meaning: build a repeatable "what this means now" readout before final UI wording.

### 2. Surface Gravity

The loop repeated the same surface split:

- User surface operates, organizes, assigns, and decides.
- VectorFL surface mediates, rereads, validates, and catches drift.
- Engine surface executes, returns, and prepares material for deposition.

This is why the language loop belongs on the User surface as an internal team/language 담당 task, not as a VectorFL core panel.

### 3. Bridge Preservation

Human-readable explanation must preserve route, authority, state, boundary, and support context before simplifying. If a phrase becomes easy but loses who has authority, where the route is, or what remains closed, it has failed.

Meaning: easy wording is allowed only after the protected structure is still visible.

### 4. Boundary-First Terms

Some internal terms must show their boundary before they are made convenient. Examples include `hold`, `carry-forward`, `watch keep`, `reject/conflict`, `workspace ownership`, and `collision stop condition`.

Meaning: these are not generic project-management labels. They are operational states or authority boundaries.

### 5. Axis-Derived Interface

The loop found that fixed interface structure should come from repeated axes, not from imported templates. A single line or single connection is not enough to become a fixed UI element.

Meaning: "그릇/고정장치" should grow from repeated internal evidence, not be imposed first.

## What This Means For The UI

The immediate UI lesson is not "translate everything." The immediate lesson is to add or improve a thin operating readout when needed:

- What is running or already returned?
- What route is this on?
- What is open, closed, held, or watch-only?
- Who can decide the next move?
- What must not be inferred from this result?

This supports the user's judgment without forcing the user to learn all engine-language details.

## What This Means For Surface Placement

The language loop is a user-surface internal team job because it is an assigned work loop: "collect language material repeatedly and prepare it for interpretation." VectorFL should receive and reread the harvest, but the work assignment itself belongs to the user surface.

The corrected split is:

- User surface: internal language 담당 loop, work assignment, decision support.
- VectorFL surface: CLI direct operation, mediation, reread of loop outputs, drift/axis judgment.
- Engine surface: output material, return/deposit candidate, execution evidence.
