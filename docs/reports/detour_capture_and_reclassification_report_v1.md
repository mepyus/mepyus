# detour capture and reclassification report v1

## verdict

record the detour as a useful memory asset, but return the upper frame to page composition now

## where we drifted

The original work was page composition:

- what pages exist
- what each page does
- how pages differ
- how the operator moves between them

The drift began when the history/time-axis pressure was discussed in `surface`, `phase`, and `adjacent candidate` terms rather than being kept inside a page-composition frame from the start.

That drift was understandable because the history surface needed:

- role lock
- boundary lock
- handoff contract
- anti-drift guard

But the language gradually elevated:

- `phase1`
- `phase2`
- `adjacent surface`
- `freeze`

into an upper organizing frame, when the upper organizing frame should have stayed:

- current page set
- companion page
- parked candidate page

## what remains useful

The detour did produce useful assets.

### 유지 자산

- phase1 boundary lock materials
  - still useful as page-internal role contracts
- history/reread/trace baseline and handoff materials
  - still useful as companion-page boundary contracts
- invariant probes
  - still useful as drift guards
- freeze/handoff notes
  - still useful as maintenance rules

These are not discarded.

### 재분류 자산

- `phase1` documents
  - reclassify as core-page implementation/boundary assets
- `phase2` history/reread/trace documents
  - reclassify as companion-page implementation/boundary assets
- surface atlas / transition materials
  - reclassify as page-system map assets

These remain useful, but their place is below the page-composition frame, not above it.

### 승격 금지 자산

- phase progression language as upper product map
- roadmap-like reading of history page as “next stage”
- adjacent-surface language when used as the main organizing frame

These can remain as implementation-era traces, but they should not govern current page composition as the top frame.

## what should move down one level

The following should be treated as lower-level implementation/support material, not upper baseline:

- freeze contracts
- probe scripts
- route-specific handoff details
- source-binding maintenance notes
- internal `phase1 / phase2` naming

They still matter, but only after page composition answers:

- what page is this
- is it core, companion, or parked
- what reading job does it do
