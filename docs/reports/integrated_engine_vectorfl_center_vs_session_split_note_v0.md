# Integrated Engine VectorFL Center vs Session Split Note v0

## 1. Verdict

PASS_WITH_NOTE

The VectorFL surface should no longer be read as a CLI host-control center. It should be read as a selected-object mediation surface with a compact session layer above it.

## 2. What Is The Center

The VectorFL center is:

```text
selected object/package + interpreted state + evidence + blocker + next route
```

For the current one-handler pilot, that center is:

```text
language_handler_loop_pkg_v0
```

The package is read as mediation material, not as a worker dashboard.

## 3. What Is The Session Layer

The session layer is:

- instruction input
- lens/task selector
- send control
- revise latest control
- stop/hold control
- refresh control
- compact latest event summary

It supports VectorFL mediation, but does not define the object being mediated.

## 4. Why The Dense CliHost Reading Was Only Partially Correct

CliHost matters because Codex turns are part of the operating loop.

But when CliHost carries evidence gates, packet fields, recent turns, latest return, marks, and route controls on the front surface, VectorFL starts reading as a console. That is wrong for operating mode.

The corrected placement keeps the command loop visible while moving x-ray details into support.

## 5. Front / Support / Modal Split

Front:

- compact session strip
- current VectorFL local focus
- single-handler package projection
- mediation process map

Support:

- evidence gate
- packet formation fields
- recent turns
- latest return detail
- validation queue
- line/intervention summaries

Modal / inspector direction:

- full provenance
- lower-input residue
- bridge dependency-heavy explanation
- packet-origin text

## 6. One-Handler Preservation

The one-handler package remains coherent:

```text
User purpose -> VectorFL classification -> Engine processing -> VectorFL return review -> User next action
```

The correction changes VectorFL reading density, not the package lifecycle.

## 7. Validation

- VectorFL first question: clearer.
- Session vs center: separated.
- One-handler flow: preserved.
- Bridge maturity boundary: preserved as dependency-heavy and non-automatic.
