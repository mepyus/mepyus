## 1. Why Round 010
Round 009 established that "Lightweight Maturation Vocabulary" (e.g., `Provisional`, `Maturing`, `Canonical`) is necessary to prevent the "Dark Room" effect. However, these status terms must not become a rigid, schema-based UI. This round investigates how external systems display maturity and risk *ambiently*—using peripheral awareness and non-interruptive cues—to ensure the Human Sovereign Observer remains informed without being overwhelmed by alert/review fatigue.

## 2. External Case Harvest

### A. Calm Technology (Ambient Awareness)
- **Key Concepts:** Glanceable interfaces, peripheral awareness, ambient displays.
- **External View:** Information should be "backgrounded" and only rise to the foreground when a threshold is met (e.g., a color-coded status bar that is usually gray).
- **Borrowable Asset:** **"Peripheral Status Indicators."** A simple, non-intrusive way to signal that a "Layer" is "Maturing" (e.g., a subtle visual indicator in the CLI output).
- **Dangerous Assumption:** "Calm" tech can be ignored too easily, leading to "automation surprise" when a backgrounded error becomes critical.

### B. Aviation / Industrial Status Indicators
- **Key Concepts:** Warning-Caution-Advisory (WCA), Abnormal Situation Management.
- **External View:** The "Dark Room" concept (or "Quiet Cockpit"). If all indicators are dark/gray, the system is nominal. Anomalies light up.
- **Borrowable Asset:** **"Off-Nominal Surface."** Surfaces information only when it deviates from the "Canonical" baseline established in the layer.
- **Dangerous Assumption:** "No alert = No problem." A system can have "Normal" metrics while having a "Catastrophic" underlying trend.

### C. GitHub Collaboration UI
- **Key Concepts:** Pull request draft/review/approved/changes-requested labels.
- **External View:** Status is attached to the lifecycle, not the object. The UI signals the *workflow state*, not just the file type.
- **Borrowable Asset:** **"Workflow Lifecycle Signals."** Small visual cues indicating if a document is `[Draft]`, `[Review]`, or `[Approved]` without using a formal database schema.
- **Dangerous Assumption:** Over-relying on GitHub labels to convey "Process Truth" when they are just text labels.

### D. ADR / RFC Lifecycle Display
- **Key Concepts:** Proposed, Accepted, Superseded, Deprecated.
- **External View:** Status reflects the *decision's temporal validity*, not the *document's content*.
- **Borrowable Asset:** **"Temporal Status Markers."** Simple headers indicating the status of the *decision* represented by the document.
- **Dangerous Assumption:** Assuming one document status applies to the entire "Layer" it might reside in.

### E. Product Discovery / Confidence Mapping
- **Key Concepts:** Assumption mapping, discovery stages, hypothesis validation boards.
- **External View:** Using "Confidence" (0-100%) to triage which assumptions are ripe for human review.
- **Borrowable Asset:** **"Confidence-Triage Tiers."** Categorizing thoughts into `Low-Confidence/High-Impact` (Review Required) vs. `High-Confidence/Low-Impact` (Auto-suppress).
- **Dangerous Assumption:** Using a numeric score as a surrogate for "Truth."

### 4. User Space Seen Through Ambient Signal Design Lens
- **The "Dark Room" problem:** Our space is a dark room because we lack "Background Status Indicators." A simple visual signal (e.g., `(M)aturing`) would show that the chaos is *intentional*.
- **Ambient Maturation:** We don't need a status *dashboard*. We need "Glanceable Indicators" that let the user know, at a glance, which layers of the cosmology are currently "Hot" (Maturing) vs. "Cold" (Canonical/Stable).

### 5. External Critique

#### Strengths
- **Sovereign Authority:** We don't automate "Locking," we only automate the *visibility* of what needs to be locked.

#### Weaknesses
- **Status Opacity:** Observers cannot distinguish between a "Stable" system layer and an "Experimental" one.

#### Misunderstanding Risk
- Outsiders mistake the "Ambiguity-Preserving" nature of our cosmology for lack of engineering rigour.

#### Differentiation
- We treat **Ambiguity as a Design Resource**, whereas others treat it as a **Bug to be Fixed**.

#### Borrowable Assets
- **"Ambient Indicators":** Visual cues (e.g., subtle text markers) indicating maturity level.
- **"Actionable Triage":** Only surfacing information that crosses the threshold of "Review Required."

#### Dangerous Assumptions
- **"Status = Truth":** The belief that `Status: Canonical` means the concept is finished forever.
