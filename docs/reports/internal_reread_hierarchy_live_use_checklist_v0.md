# internal reread hierarchy live use checklist v0

## verdict

`READY`

## purpose

This checklist is for applying the current A / B / C layered judgment to one live internal reread or closeout target.

It does not create a new axis.
It does not reopen promotion.

## checklist

### step 1. identify the target

- what is the live target?
  - closeout note
  - failure note
  - blocker note
  - attachability note
  - operating proposal
- keep the target bounded
- do not open repo-wide reread

### step 2. run the A question

- what had to be fixed first?
- what structure, scope, authority, or packet-worthiness was treated as a precondition?
- was wider freedom blocked until this was in place?

Record:

- `A signal: strong / moderate / weak`

### step 3. run the B question

- what bounded surface, role, slot, or attach boundary is being protected?
- what mixed or universal reading is being refused?
- does this record regroup with other B-family material?

Record:

- `B signal: strong / moderate / weak`

### step 4. run the C question

- what is being held, watched, validated, logged, or kept candidate-only?
- what remains deliberately unpromoted?
- what reversible next step is preserved?

Record:

- `C signal: strong / moderate / weak`

### step 5. separate function, do not flatten

Answer:

- what A explains that B does not
- what B organizes that A does not
- what C governs that B does not

If you cannot separate them, mark:

- `needs caution`

### step 6. close conservatively

Allowed outcomes:

- `A-dominant read`
- `B-dominant read`
- `C-dominant read`
- `mixed but still layered`

Not allowed:

- new axis naming
- operating rule promotion
- flattening A / B / C into one category from one live target
