## 2. trial summary

The selected case was the stored `gemini/mock_test` design-material flow:

1. Gemini-side mock material existed under `gemini/mock_test`.
2. Codex read it as proposal/design clay.
3. Codex wrote structural analysis and visual translation briefs.
4. User later opened bounded implementation packages.
5. Codex applied only selected visual rhythm and recorded patch closeouts.

This case was useful because it contained:

- real proposal material
- clear baseline translation
- explicit held/conflicting elements
- later scoped implementation
- visible authority risks

## 3. grammar that survived well

### authority grammar

This survived strongly.

The case kept separate:

- Gemini proposal authority
- Codex baseline translation and canonical recording authority
- User promotion/package-opening authority
- workspace ownership boundaries

### validation grammar

This survived strongly.

Codex validation operated as a route selector:

- usable visual token
- needs translation
- carry-forward
- reject / conflict
- needs user decision

### route grammar

This survived adequately.

The case could be read as:

```text
user direction
-> Gemini proposal material
-> Codex baseline translation
-> user-scoped implementation opening
-> Codex bounded patch / closeout
```

The note is that this was reconstructed from stored artifacts, not a new formal `gemini/handoffs/*` output.

## 4. grammar that weakened in the human explanation layer

### bridge-before-flatten grammar

This stayed usable but showed pressure.

The easiest explanation risks flattening:

- `proposal-only` into "draft"
- `needs Codex translation` into "Codex passes it along"
- `workspace ownership` into "folder assignment"
- `collision stop condition` into "error handling"

### hold / watch grammar

This stayed usable but needs care.

Held Gemini material can sound like discarded material unless the explanation says:

- held means not core now
- carry-forward preserves future value
- reject/conflict is different from extension-later

### reread / support grammar

This stayed usable but is evidence-thin.

Because no new formal handoff artifact was produced in this round, support reread was reconstructed through existing reports rather than a single handoff record.

## 5. is final human-facing lexicon ready?

No.

Reason:

- the grammar candidates survived this trial, but the case was a stored handoff-like flow
- no newly executed Gemini CLI handoff artifact was tested
- human bridge explanation still carries flattening risk around authority and ownership
- final wording would prematurely harden terms that still need one real handoff observation
