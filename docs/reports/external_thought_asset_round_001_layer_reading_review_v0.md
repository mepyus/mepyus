## 2. What Needs Lowering (Correction of Over-promotion)
Several candidates were promoted too quickly to `core-fit` and need to be repositioned based on the project's risk-memory and layer-reading principles.

- **Context Injection:** Previously `core-fit`, now lowered to `conditional-gated`.
  - **reason:** The risk of context hallucination or outdated/irrelevant prompt-stuffing outweighs the immediate utility. It requires a specific "layer-check gate" before use.
- **MCP / Layer-Reading Adapter:** Previously `lens`, now lowered to `future-option` / `lens tool`.
  - **reason:** MCP is a tool connection standard, not a space philosophy. It should not be treated as part of the core engine yet.
- **Candidate Residue Promotion:** Previously `future-option`, now clarified as `future-option with strict human lock gate`.
  - **reason:** To avoid the risk of AI self-editing facts (violating the Sovereign Observer pillar).

## 5. Main Risk Memory
- **Recall vs. Resolution:** External memory products optimize for *recall* (finding), but the user space needs *resolution* (meaning).
- **Prompt Stuffing:** Context injection without a layer-check gate becomes noisy "prompt stuffing" that leads to hallucination.
- **Schema Suffocation:** Schema-first or Tag-first structures (like Tana's) can suffocate the natural "stratification" and "maturation" of the space.
- **Agent Autonomy Risk:** Self-editing agent memory (like Letta) can violate the "Human Lock Authority" if the agent is allowed to finalize facts.

## 6. Recommended Round 002: Residue Reingestion without Noise
The next focus must be the mechanism for "Recursive Observation" (Pillar 4). Before building UI or connectors (MCP), we must define how CLI interaction residues (logs, hints, patterns) are filtered and reingested as Stage 0 Events without polluting the universe with noise.
