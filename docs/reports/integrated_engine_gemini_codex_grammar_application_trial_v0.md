# Integrated Engine Gemini/Codex Grammar Application Trial v0

Date: 2026-04-15

## 0. verdict

PASS_WITH_NOTE

This trial applies the current internal grammar candidates to one stored Gemini/Codex handoff-like case.

It does not run Gemini CLI, create UI wording, patch scaffold files, change manifests, change read maps, quote external style guides, reopen runtime binding, selected-object behavior, trace UI, or promote extensions.

## 1. chosen handoff case

Chosen case:

- `gemini/mock_test` visual/design material generated as Gemini-side proposal material
- Codex structural analysis in `docs/reports/gemini_mock_test_structural_analysis_v0.md`
- Codex visual translation briefs for engine, user, and VectorFL surfaces
- later bounded scaffold visual patches and closeout notes, already completed under earlier scoped packages

Why this case:

- It contains actual Gemini-produced design material.
- It forced Codex to translate proposal material through the current integrated-engine baseline.
- It exposed authority and ownership boundaries clearly:
  - Gemini material was useful but not canonical.
  - Codex classified what could be translated.
  - User-scoped packages opened later implementation.
- It includes visible collision risks:
  - supervisor queue
  - bridge panel
  - watcher / live manifest language
  - control room framing
  - user team/role console drift

Boundary note:

- This is a stored handoff-like case, not a newly executed Gemini CLI run.
- It is sufficient for grammar application trial because the route from proposal material to Codex translation and bounded core use is documented.

## 3. route grammar application

### What is request

The initiating request is the user's instruction to use Gemini for design material and then have Codex structurally analyze it.

Route grammar:

- source: user direction
- target: Gemini proposal workspace first, then Codex translation workspace
- purpose: produce design material and test whether it can be translated into current baseline
- route reason: integrated-engine design needed more visual material, but baseline structure had to remain higher than mock structure

### What is proposal

The proposal is `gemini/mock_test`.

It includes:

- visual surface layouts
- panel concepts
- status badges and dense card rhythms
- engine ingest / pipeline / return patterns
- risky governance, supervisor, watcher, bridge, and control-room elements

Route grammar:

- proposal material is not a packet entering core directly
- it becomes a translation subject for Codex
- it remains under `gemini/` provenance

### What is Codex translation target

Codex translation target is not "copy the mock."

The translation target is:

- identify what maps to existing baseline panels
- classify usable / needs translation / conflicting
- keep `operating_flow_panel`, `maturation_canvas_panel`, and `execution_state_panel` gravity
- preserve request / return / reflux separation
- hold or reject visual structures that require new core panels, runtime binding, trace UI, or governance authority

### What is return or decision material

Return / decision material appears as:

- structural analysis verdict: `translate-with-selection`
- surface visual translation briefs
- consolidation note
- patch notes and closeout notes after scoped implementation

These artifacts are not Gemini returns. They are Codex return material to the user and to the workspace, showing what can be used, held, or rejected.

## 4. authority grammar application

| authority point | Gemini authority | Codex authority | User authority | boundary preserved? |
|---|---|---|---|---|
| Design material creation | may generate proposal material under `gemini/` | may later read and classify | opens or requests the design-material task | yes |
| Structural interpretation | no canonical authority | primary baseline translator | receives and decides whether to continue | yes |
| Canonical reports | no direct write authority under `docs/reports` | writes when package allows | scopes the package | yes |
| Scaffold patches | no direct implementation authority | patches only under explicit bounded task | opens patch package | yes |
| Promotion / final decision | cannot promote | can recommend/classify | decides promotion or continued hold | yes |

Authority grammar finding:

- The handoff case preserved the difference between "Gemini produced something useful" and "the useful part entered baseline."
- Codex did not treat visual strength as authority.
- User task scope controlled when analysis moved into implementation.

## 5. hold / watch grammar application

Items that stayed proposal-only or held:

| item | held state | reason |
|---|---|---|
| supervisor queue | hold / reject for core | adds standing assignment or governance layer |
| bridge panel as core | hold | too broad; risks bypassing packet separation |
| watcher recommendations | hold | implies watcher/supervisor authority and live runtime truth |
| live manifest / script attachment claims | hold | runtime binding and manifest truth are closed |
| team/role console center | hold / extension later | user center must remain `operating_flow_panel` |
| line atlas as VectorFL center | hold / support-only | VectorFL center must remain `maturation_canvas_panel` |
| engine control room authority | hold | engine must remain processing / return surface |

Hold/watch grammar finding:

- Proposal material was not discarded.
- It was split into usable visual tokens, future carry-forward, and conflict/hold items.
- Hold preserved future design value without promotion.

## 6. validation grammar application

Validation conditions used by Codex:

- central panel gravity preserved?
- request / return / reflux separation preserved?
- read map unchanged?
- manifest shape unchanged?
- selected-object behavior avoided?
- trace UI avoided?
- runtime binding avoided?
- extension promotion avoided?
- user surface not turned into team console?
- VectorFL not turned into line browser?
- engine not turned into control room or judgment authority?

Stop / collision / reject / carry-forward triggers:

| trigger | resulting classification |
|---|---|
| Gemini output requires core panel addition | reject / conflict or carry-forward |
| Gemini output requires runtime binding | reject / conflict |
| Gemini output implies live manifest truth | reject / conflict |
| Gemini output is visually useful but structurally broad | needs translation |
| Gemini output provides reusable card rhythm without semantic drift | usable now if package allows |
| Gemini output suggests future axis/tool layer | carry-forward |

Validation grammar finding:

- Validation worked as a route selector.
- It did not merely say "good mock" or "bad mock."
- It split material into usable, translated, held, or rejected parts.

## 7. reread / support grammar application

First-pass thin or risky reading:

- The mock could look like a ready integrated-engine UI.
- Engine surface could look like an authority/control room.
- VectorFL surface could look like a line browser.
- User surface could look like team/role management.
- Watcher/supervisor/bridge elements could look like active system features.

Support reread recovery:

- Reading the v1 baseline restored central panel gravity.
- Reading structural analysis separated visual token from structure.
- Reading visual translation briefs showed which mock elements could be translated without changing read mapping.
- Reading patch notes and closeouts confirmed that only bounded visual rhythm entered scaffold files.

Reread grammar finding:

- First-pass visual appeal was not enough.
- Supported reread through baseline docs and Codex analysis recovered the intended authority and route boundaries.

## 8. trial summary

The selected handoff case retained the internal grammar well enough for trial use:

- route grammar held because mock material moved through proposal -> translation -> scoped implementation
- authority grammar held because Gemini did not become canonical
- hold/watch grammar held because risky material stayed held without being lost
- validation grammar held because Codex classified material before use
- reread/support grammar held because baseline reread corrected first-pass mock drift

Main note:

- The case still lacks a freshly executed Gemini CLI handoff artifact with the required `proposal-only / needs Codex translation` final label. This weakens evidence slightly, but does not invalidate the grammar trial.
