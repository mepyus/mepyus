# VectorFL Paper Weekend Live Bundle Selection v0

## Purpose
This note selects the first live scenario-bearing bundle for the weekend pilot.

The goal is not to choose the biggest bundle.
The goal is to choose the smallest bundle that still preserves:
- operating philosophy
- line formation pressure
- human-readable supervision requirement
- Paperclip-to-VectorFL translation grammar

## Selection Rule
The first live bundle should include materials that jointly answer:
- Why internal reading must come first
- How the surface becomes human-readable work language
- How Paperclip should be translated structurally rather than copied
- What the first thin overlay target should be

## Chosen Live Bundle

### 1. `vectorfl_host_coupled_maturation_strategy_v0`
- Why chosen:
  - fixes the internal-first and host-coupled maturation posture
  - keeps the loop from drifting into broad expansion too early

### 2. `human_language_work_surface_readiness_reread_v0`
- Why chosen:
  - fixes the requirement that line must rise as work-facing human language
  - keeps the supervisor surface from collapsing into internal jargon

### 3. `vectorfl_paper_operating_brief_lock_v0`
- Why chosen:
  - defines the first-pass operating success condition
  - keeps line, recall, search, routing, and next action in one flow

### 4. `vectorfl_paper_surface_as_reading_organs_lock_v0`
- Why chosen:
  - fixes the surface as reading organ and translator layer
  - protects against dashboard-only interpretation

### 5. `paperclip_absorption_overlay_v1`
- Why chosen:
  - reframes Paperclip as operational memory source instead of copied ontology
  - introduces task/run/decision/artifact/pattern as ingestable traces

### 6. `paperclip_to_vectorfl_overlay_requirements_v0`
- Why chosen:
  - gives the thinnest realistic overlay target
  - narrows the first test to `issue -> run -> result -> trace`

### 7. `current conversation bundle`
- Why chosen:
  - carries the correction flow itself
  - contains the strongest current pressure around cells, CLI, supervision, and scenario-bearing material

## Why This Bundle Wins
This bundle is chosen because it contains one complete pressure chain:

`maturation posture -> supervision language -> operating brief -> reading-organ surface -> Paperclip overlay grammar -> first test target`

That chain is enough to run a first real loop without overloading the pilot.

## What Was Not Chosen First
- broad dialogue-loop condensation material
- larger compare families
- plugin-market or multi-company expansion material

Why not:
- they increase breadth before the first loop is proven
- they are useful later, but not necessary for the first closed loop

## Selected External Comparison Target
The first live external comparison target should be:

`Paperclip issue / heartbeat run / result / governance event -> VectorFL intake grammar`

Why:
- it is the thinnest realistic overlay
- it preserves the control-plane reference without dragging in company ontology
- it directly supports the first weekend success condition:
  `one scenario-bearing loop closes and returns into internal memory`

## Working Verdict
The first live bundle should be built around:
- maturation strategy
- human-language work surface
- operating brief
- reading-organ surface
- Paperclip absorption overlay
- Paperclip overlay requirements
- the current conversation bundle

The first live comparison target should be:
- `issue -> run -> result -> governance event`

This is the smallest live bundle that still preserves the real direction.
