## 1. Why Round 008
Round 007 confirmed that ambiguity is a resource but "dark rooms" (lack of state visibility) create chaos for observers. We need to distinguish between *provisional/maturing* states and *formalized* states without imposing rigid schemas. This round investigates how external systems signal "maturation" and "readiness" ambiently, allowing the User Space to mature naturally while keeping the human observer informed.

## 2. External Case Harvest

### A. Calm Technology (Ambient Awareness)
- **Key Concepts:** Glanceable interfaces, peripheral awareness, ambient displays.
- **External View:** Information should be "backgrounded" and only rise to the foreground (interruptive) when a threshold is met.
- **Borrowable Asset:** **"Peripheral Status Indicators."** A simple, non-intrusive way to signal that a "Layer" is "Maturing" (e.g., a subtle visual indicator in the CLI or header).
- **Dangerous Assumption:** Making the system "too calm" can lead to "automation bias" where the user stops checking the "state" altogether.

### B. Technology Readiness Levels (TRL) / Research Maturity
- **Key Concepts:** TRL 1-9 (Conceptual -> Deployed).
- **External View:** Readiness is a spectrum, not a binary "Done" state.
- **Borrowable Asset:** **"Maturation Levels."** Using a 3-tier status for thought assets (e.g., `Provisional`, `Maturing`, `Canonical`) without requiring a formal schema.
- **Dangerous Assumption:** Treating "Maturity" as a strictly linear path; research often loops back to "Provisional."

### C. Research Lab Process Signals
- **Key Concepts:** Process memory, hypothesis tracking, experimental evidence levels.
- **External View:** A notebook record is a "Process," not a "Result." Failure is part of the process memory.
- **Borrowable Asset:** **"Status-by-Provenance."** The "State" of a residue is derived from the number of "Verification Gates" it has passed.
- **Dangerous Assumption:** Creating a complex "tracking system" that takes more time than the research itself.

### D. Product Discovery Status
- **Key Concepts:** Confidence levels, hypothesis board, assumption mapping.
- **External View:** Confidence scores allow the system to triage human attention to high-risk assumptions.
- **Borrowable Asset:** **"Risk-weighted Review."** Only candidates with "High-Risk + Low-Confidence" status trigger a Sovereign Lock request.
- **Dangerous Assumption:** Using a "Score" (e.g., 8/10) as an excuse to auto-promote without human lock.

### E. RFC / ADR Lifecycle (Software Engineering)
- **Key Concepts:** Draft, Review, Approved, Superseded, Deprecated.
- **External View:** The "Status" is attached to the document lifecycle.
- **Borrowable Asset:** **"Lifecycle Status Tags."** Using light-weight tags (`draft`, `verified`, `superseded`) to signal the state of a "Thought Asset" without a full database.
- **Dangerous Assumption:** Assuming every thought asset has a lifecycle; some thought assets (like "failure traces") are "always open."

### F. Knowledge Management Maturity
- **Key Concepts:** Evergreen Notes, Progressive Summarization, Atomic Notes.
- **External View:** Maturity is signaled by how much the note has been "refined" (linked, summarized, aggregated).
- **Borrowable Asset:** **"Maturation-by-Refinement."** A residue becomes "Mature" when it is linked to 3+ different layers.
- **Dangerous Assumption:** "Linking is Maturity." A linked note is not necessarily a mature note.

### 4. User Space Seen Through Ambient Maturation Signal Lens
- **Entry Chaos:** Is not "Chaos," it is a **"High-Entropy Maturation Phase."** Observers need an *Ambient Signal* (e.g., "Space is warming up") to know it's *supposed* to be in this state.
- **Dark Room:** Our space is a dark room because we lack "Background Status Indicators." A simple visual indicator (e.g., `[Phase: Maturing]`) would clarify that entropy is part of the design.
- **Sovereign Tray:** Currently an interruptive inbox. It should be an "Actionable Triage," where only `Canonical-Lock` items interrupt, while others remain "Backgrounded."

### 5. External Critique

#### Strengths
- **Provenance-First:** External systems struggle with linking state back to the original evidence; our `provenance_anchor` is superior.

#### Weaknesses
- **Status Opacity:** Observers cannot distinguish between a "Stable" system layer and an "Experimental" one.

#### Misunderstanding Risk
- **"Lack of progress":** Outsiders interpret the "Ambiguity-Preserving" state as "lack of feature delivery." We need to clarify that *resolution gain* is the goal.

#### Differentiation
- We separate **State** (status signal) from **Ontology** (schema).

#### Borrowable Assets
- **"Visual Status Tags" (Lifecycle/Confidence):** Signals like `[Draft]`, `[Review]`, or `[Canonical]` (used non-intrusively).
- **"Ambiguity Indicators":** Ambient signals showing "Maturation in Progress."

#### Dangerous Assumptions
- **"Status = Truth":** The belief that `Status: Locked` means the concept is finished forever (Cosmology must remain open).
