# Whole Space Deep Reread Pipeline Setup v0

## 1. Purpose

Set up a bounded pipeline for rereading the whole space more deeply.

This is not a full-space crawl.

This is not automation.

This is a structure-design setup for:

```text
Codex = pipeline / packet / synthesis design
Gemini = bounded reading / evidence return / repeated validation
ChatGPT = direction and role-drift review
User = purpose and final decision gate
```

The goal is to make accumulated records reusable as material for the next structural judgment.

This setup follows the core principle from Function/Process Formation Prework:

```text
Structure is not organizing records neatly.
Structure is making previous records reusable as material for the next judgment and execution.
```

## 3. Why This Is Needed

The space now contains many records:

```text
current-position entries
next-chat summaries
role references
operating model candidates
line / axis / lens / camera reports
external-material intake records
Gemini evidence records
mistake-memory
package preflight notes
function/process formation prework records
integrated-engine and CLI-side reports
long-arc reread maps
```

If these records are only stored, they become archive.

If they are reread without boundary, the reread becomes a broad token sink.

If they are promoted automatically, the space becomes unsafe.

The needed middle process is:

```text
bounded deep reread
```

Meaning:

```text
read enough across the whole space to detect active structure,
but use retrieval_scope_boundary so "whole space" does not mean "everything forever."
```

## 4. Real Object Being Structured

The object is not a single report.

The object is:

```text
Whole Space Deep Reread Pipeline
```

Definition:

```text
A bounded, staged process for rereading representative anchors, long-arc records, current operating records, worker/process records, and line/lens/camera materials so that accumulated space records can be turned into structural evidence for User-gated judgment.
```

This pipeline should reveal:

```text
what is currently active

```

## 5. Retrieval Scope Boundary

This reread uses `retrieval_scope_boundary`.

### Purpose

```text
Reread the whole space as a formation structure, not as an exhaustive archive crawl.
```

### Include

Use representative anchors from these strata:

```text
1. current re-entry / anchor state
2. role and authority boundary
3. long-arc formation maps
4. operating model / whole-space orientation
5. line / axis / lens / camera references
6. external-material and worker evidence process records
7. function/process formation prework records
8. package / candidate reference closeouts
9. integrated-engine / CLI-side process records if needed for current structure
```

### Exclude

Do not read by default:

```text
raw logs
large JSON worker outputs
node_modules / build artifacts
unbounded package folders
all historical run records
all docs/reports
all source code
external web sources
anything not referenced by the bounded worklist
```

### Stop Condition

Stop if:

```text
source file is missing and no bounded replacement is listed
reading requires broad search beyond the worklist
Gemini starts proposing implementation, adoption, package movement, or current-position update
Gemini cannot distinguish evidence from interpretation
Gemini reaches the final STATUS line
```

### Caution

```text
"Whole space" means representative structural reread.
It does not mean exhaustive search.
```

## 6. Pipeline Stages

### Stage 0 - User Purpose Gate

```text
Owner = User / ChatGPT
Input = request to reread the whole space more deeply
Output = bounded reread purpose
Stop if = no User purpose
```

### Stage 1 - Codex Structure Setup

```text
Owner = Codex
Input = current setup documents and recent closeouts
Output = pipeline setup and Gemini worklist
Allowed = choose representative files, define scope, set stop conditions
Forbidden = run Gemini autonomously, create automation, update current-position
```

### Stage 2 - Gemini Evidence Inventory

```text
Owner = Gemini, when User manually provides the worklist
Input = bounded file list
Output = evidence table by stratum
Allowed = read, summarize, mark uncertainty, identify missing files
Forbidden = implementation, promotion, broad search, authority decisions
```

### Stage 3 - Gemini Structural Observation Pass

```text
Owner = Gemini
Input = evidence inventory
Output = observations on active structures, closed structures, candidate references, watch items
Allowed = evidence-backed comparison
Forbidden = verified-truth claims, new doctrine, automatic next direction
```

### Stage 4 - Gemini Lens / Camera / Line-Axis Pass

```text
Owner = Gemini
Input = bounded line / axis / lens / camera records
Output = fit / stress / gap / uncertainty table
Allowed = evidence return
Forbidden = making lenses law, cameras truth, axes ontology
```

### Stage 5 - Gemini Mistake / Drift / Missing-Structure Pass

```text
Owner = Gemini
Input = prior observations
Output = mistake risks, role drift risks, missing links, unclear boundaries
Allowed = mark uncertainty and blocked states
Forbidden = fixing or patching documents
```

### Stage 6 - Codex Structural Synthesis

```text
Owner = Codex after User returns Gemini result
Input = Gemini evidence bundle
Output = structural synthesis, candidate process assets, watch carry-forward, next choices
Allowed = interpret patterns and propose options
Forbidden = final authority, implementation, promotion, current-position update by implication
```

### Stage 7 - ChatGPT / User Judgment

```text
Owner = ChatGPT / User
Input = Codex synthesis
Output = accept, hold, request another bounded read, select next purpose, or stop
Forbidden = hidden automatic movement
```

### Stage 8 - Recovery

```text
Owner = Codex only after User decision
Output = process-memory-light, candidate reference, closeout, or current-position update only if explicitly required
Forbidden = automatic registry/index/ledger creation
```
