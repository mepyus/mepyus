# Phase 1.23 Flow-Aware Unresolved Hold Note v0

## Purpose

This note records what remains intentionally open after the current heuristic consolidation.

Unresolved hold is not a broad reopen permission.
It is a bounded reminder of what should remain unfinalized.

## Unresolved Hold Items

- `general_line_vs_flow`
- `conditional-only` bucket
- `raw_intake_gap` long-term placement

## Why `general_line_vs_flow` Is Not Fully Locked

Current reading:

- default already captures the useful slice
- thin independent flow still survives
- bounded flow-aware does not improve enough to justify a mode switch now

So:

- it is not allow-list
- it is not block-list
- it stays default-sufficient for current operation
- but it still holds the strongest pressure toward a possible future `conditional-only` case

That is why it remains under unresolved hold.

## Why `conditional-only` Stays Structurally Open

Current bucket state:

- empty in current operating rule

Current interpretation:

- not permanently empty
- not populated by current evidence
- structurally open because middle-bucket pressure has not disappeared

So the correct wording is:

- provisionally empty
- structurally open

## Why `raw_intake_gap` Still Has Long-Term Reclassification Risk

Current operational stance:

- keep default-sufficient

Why it is not fully final:

- current value stays almost entirely in boundary reread
- flow-aware adds no real gain
- future evidence could still show that this family is closer to block-list than to a stable default-sufficient class

That is a long-term reclassification possibility, not a current move.

## Reopen Conditions

Reopen unresolved hold only when one of the following is true.

1. `general_line_vs_flow` begins to show bounded local conditions that justify a real `conditional-only` entry
2. `raw_intake_gap` shows repeated overreach risk such that default should no longer be described as honest enough
3. a future family creates a clean middle-bucket case that current structure cannot place honestly

Do not reopen because:

- flow exists somewhere
- a filename looks flow-like
- one thin sample suggests possible middle pressure

## Why Unresolved Hold Must Not Trigger Broad Reopening

The unresolved set is deliberately narrow.

It should not be used to justify:

- broad tuning continuation
- emitter reopening
- family-wide reclassification
- global flow-aware expansion

The current lock remains intact outside these bounded hold items.
