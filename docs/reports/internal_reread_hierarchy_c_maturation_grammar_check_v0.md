1. recovery sequencing pressure
2. confusion logging pressure

5. transition-versus-hold pressure
6. current hold/watch registry pressure

## reading

### 1. recovery is explicitly staged, reversible, and status-first

The process recovery checklist starts from status lock, target-shape gate, rollback signal check, and next valid action.

That means the system does not treat progress as:

```text
probe -> success -> promote
```

It treats progress as:

```text
status -> gate -> probe -> separation -> rollback check -> gate update -> next valid action
```

This is strong C material.

### 2. confusion is converted into repeatable evidence, not immediate redesign

The wording confusion log template is explicit:

- log only during manual use
- classify first
- separate wording confusion from fixture limitation and held extension desire
- patch only after recurrence and lane checks

That is a governance grammar, not just a template.

It turns irritation into bounded evidence.

### 3. repeated language harvest stays as harvest, not final wording

The language loop round 10 readout says the loop does not produce final copy.

Instead it produces:

- repeated internal-language material
- line / connection / axis evidence
- readable report before visible translation

It also says:

- do not flatten hold / carry-forward / reject-conflict / watch keep into generic labels
- do not jump from repeated material to fixed interface too early

This is C acting on harvested process material.

### 4. explanation trial closes external harvest and keeps order-dependent safety

The translation bridge usage trial closeout is especially strong C evidence.

Even after the lexicon works in controlled explanation, the result is:

- no final glossary
- no UI copy
- no wording patch
- no external harvest

The safe use depends on explanation order and anti-flattening checks.

That is maturation control, not mere caution.

### 5. hold is structurally protected over forced transition

The phase transition and hold rule says:

- phase is a result, not a declaration
- hold is protected before forced transition
- single signals do not justify movement
- transition and hold reasons must both be recorded

This is one of the clearest C statements in the space.

### 6. the registry formalizes what remains held without reopening build mode

The current hold and watch registry keeps:

- active watch items
- held features
- boundary limitations
- reopen conditions

It also says none of this opens build mode now.

This means the system has a stable way to keep things present, bounded, and unpromoted.
