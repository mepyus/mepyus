## 8. Internal Working Questions

### Find Questions

- Which repos are actual tool/runtime candidates versus supporting references?
- Which repos expose importable function units instead of full runtime replacement pressure?

### Structure Questions

- What is each tool actually for?
- What are the smallest reusable surfaces inside each tool?

### Connection Questions

- Where would each candidate attach in our current space?
- Which attach points belong to intake, packetization, retrieval, workflow, permission, or follow-up loops?

### Boundary Questions

- Which tools would overreplace the current engine if imported wholesale?
- Which candidates violate current bridge / lower-organ / bounded-runtime discipline?

### Output Questions

- What should be reported first?
- What should be left as structure-feasibility analysis second?

### Reinjection Questions

- Should the result remain a report only?
- Or should it be kept as a reusable candidate operating note?

## 9. Expected Guardrails

- do not treat external repos as direct replacement authority
- prefer feature-level borrowing over repo-level import
- keep lower-organ / bridge / current operating surface boundaries intact
- do not claim automation or immediate implementation from a structure-read alone
