## 2. Core Correction

Previous necessary boundary:

```text
Do not let a lens become ontology.
Do not let an axis become law.
Do not let a reference become architecture.
```

Corrected framing:

```text
Do not fix an axis too early.
Do help lower-level materials, connections, and repeated lines form axis candidates when the evidence supports it.
```

Core distinction:

```text
The problem is not that axes form.
The problem is naming or stabilizing an axis before the materials have spoken.
```

Safe principle:

```text
Axes are not blocked.
Premature axis fixation is blocked.
Evidence-bounded axis formation is encouraged.
```

## 3. Candidate Axis Formation Rules

### Rule 1. Material-first

```text
An axis should not be declared from above.
It should have material, records, events, mistakes, external comparisons, or repeated judgments underneath it.
```

### Rule 2. Connection-before-Line

```text
One case is not a line.
A line candidate begins when meaningful connections recur across multiple materials.
```

### Rule 3. Line-before-Axis

```text
A line becomes an axis candidate only when it repeats across situations and helps reread other materials.
```

### Rule 4. Axis-as-Reading-Tool

```text
An axis is a reading tool, not law or ontology.
It should make materials more visible, not govern them.
```

### Rule 5. Axis-can-move

```text
An axis can thicken, split, merge, weaken, or move back down into lens/watch/hold.
```

### Rule 6. Evidence-bounded Naming

```text
When naming an axis, keep the evidence bundle, repeated connections, counterexamples, uncertainty, and watch items beside it.
```

### Rule 7. User-gated Stabilization

```text
Even a useful axis candidate requires User judgment before becoming baseline, official workflow, ontology, current-position, or implementation direction.
```

### Rule 8. Productive Formation over Defensive Prevention

```text
The space does not exist to suppress axes.
It exists to observe and help good axes form from materials with enough evidence.
```

## 4. Candidate State Model

Use these states as review labels, not registry states:

```text
MATERIAL
Individual material such as external source, execution result, mistake, closeout, watch item, re-entry summary, or worker evidence.

CONNECTION_SEED
A meaningful connection begins to appear between two or more materials.

LINE_CANDIDATE
A repeated direction appears, but it is not yet confirmed.

LINE_CONFIRMED
The line repeats across multiple cases and can be reused in later reading.

AXIS_CANDIDATE
Several lines begin to converge into a larger question that can reread the space.

ORIENTATION_AXIS
A high-level map candidate useful for re-entry and judgment. Still not baseline.

REUSABLE_READING_AXIS
An axis repeatedly proves useful as a reading tool. Still not ontology or law.

WATCH / HOLD
Signal exists, but evidence is insufficient, direction is unclear, or fixation risk is high.
```

Important boundary:

```text
AXIS_CANDIDATE != final axis
ORIENTATION_AXIS != ontology
REUSABLE_READING_AXIS != baseline
```


Status:

### 5.1 Trigger

Start when:

```text
the space feels scattered
a phrase / problem / mistake repeats
an external material connects to several prior records
a process asset seems reusable but not yet named
a lens is being over-defended instead of formed productively
```

### 5.2 Bounded Retrieval

```text
Do not crawl the whole space.
Use retrieval_scope_boundary.
Retrieve only the material bundle relevant to the suspected line / axis formation.
```

### 5.3 Material Grouping

Group by role:

```text
external reference
process asset
mistake-memory
worker evidence
watch item
closeout
re-entry summary
user expression
```

### 5.4 Connection Extraction

Extract repeated connections, for example:

```text
context flooding <-> output containment
worker overrun <-> mistake-memory
plan/execution confusion <-> User gate
tool adoption pressure <-> Formation Prework
```

### 5.5 Line Candidate Naming

```text
Give the repeated connection a temporary line candidate name.
Do not name it as an axis yet.
```

### 5.6 Line Test

Ask:

```text
Does this line help read another case?
If not, keep it as local note.
```

### 5.7 Axis Candidate Test

Ask:

```text
Do several lines converge into one larger question?
Can that question reread multiple parts of the space?
```

### 5.8 Camera / Lens Assignment

```text
Camera = what to observe.
Lens = what question to read it through.
Line = repeated flow.
Axis = larger question that rereads several lines.
```

### 5.9 Drift / Overhardening Check

Check whether the axis candidate is becoming:

```text
ontology
workflow
baseline
law
registry/index/ledger
architecture
```

The goal is not to block the axis.

The goal is to block premature hardening.

### 5.10 User-facing Return

Return lightly:

```text
What line is visible?
Can it be an axis candidate?
What is the evidence?
What is still missing?
What should be watched?
What natural trigger would test it next?
```

### 5.11 Record as Process Asset

```text
Record the result as a line/axis candidate reading record.
Do not record it as registry or official state.
```

## 7. Camera / Lens Clarification

```text
Camera = what is being observed.
Lens = the question or distinction used to read it.
Line = a repeated flow seen across materials.
Axis = a larger question that helps reread several lines.
```

Example:

```text

Lens: output containment / evidence vs authority

```

