# Integrated Engine Surface Exposure Budget Audit v0

## 1. Verdict

PASS_WITH_NOTE

The current shell preserves the fixed User / VectorFL / Engine body, but recent continuity patches pushed too much packet and evidence language into shared and surface-first layers.

The immediate correction is not a new feature. It is a density correction:

```text
shared spine = orientation only
User = assignment / decision density
VectorFL = evidence / mediation density
Engine = process / return density
```

## 2. Fixed Body Reading

The fixed body remains valid:

- User Surface: purpose, assignment, decision, internal team operation.
- VectorFL Surface: reread, internal evidence, mediation, packet formation, route sorting, CLI on-top control.
- Engine Surface: request material, processing state, return material, validation/extraction/deposit candidates.

The body is not three copies of the same information. It is three role-specific readings of the same work package.

## 3. Current Exposure Drift

### Shared Spine

Current issue:

- The shared spine shows identity, purpose, packet state, route, authority, role/next, evidence gate, evidence bundle reading, packet lens/return, and manual fields.
- This is more than orientation. It starts to read like a compact global dashboard.

Correction:

- Keep only identity, purpose, route, authority, evidence readiness summary, and local next action.
- Move detailed evidence summary and packet lens to VectorFL.

### User Surface

Current issue:

- User local focus says evidence readiness and references evidence-aware packet directly.
- This is useful, but it risks making User read like a light VectorFL evidence surface.

Correction:

- User should see whether the object is ready enough for assignment/decision.
- User should not inspect evidence details in the first layer.

### VectorFL Surface

Current issue:

- VectorFL has the right density area: evidence gate, packet formation, guard, route, CLI send.
- This is where detailed evidence belongs.

Correction:

- Keep VectorFL as the dense mediation surface.
- Ensure shared/user/engine layers point to VectorFL for evidence details instead of duplicating them.

### Engine Surface

Current issue:

- Engine local focus says processing should read evidence bundle before request.
- That is conceptually correct, but it may pull VectorFL evidence work into Engine.

Correction:

- Engine should see whether request material is evidence-ready at a high level.
- Detailed evidence remains VectorFL-side.

## 4. Exposure Budget

| layer | expose now | keep out |
| --- | --- | --- |
| shared spine | current object, short purpose, route/mark, authority state, evidence readiness, next action | full evidence bundle, packet lens detail, refs, prompt, return body, manual field list |
| User Surface | assignment relevance, decision state, candidate authority, team/role target, hold/return-to-VectorFL option | full packet formation, full evidence bundle, raw CLI logs, engine internals |
| VectorFL Surface | internal search gate, evidence bundle, packet formation, guard, expected return, route candidate, CLI send, reread/validation | user team configuration details, engine full process body |
| Engine Surface | request material, process status, latest return, validation/extraction/deposit candidate, not-canonical boundary | user team detail, VectorFL evidence atlas, route final authority |

## 5. Single Correction To Execute

Slim the shared spine and surface-local first focus:

- turn the shared spine evidence row into a compact orientation badge
- remove detailed evidence bundle reading from shared layer
- remove packet lens / return from shared layer
- make User evidence wording decision-oriented
- make Engine evidence wording request-readiness-oriented
- keep full evidence details only in VectorFL packet area

## 6. Watchpoints

1. Do not remove authority state from shared view.
2. Do not hide evidence readiness completely.
3. Do not expose full evidence details outside VectorFL by default.
4. Do not make User Surface responsible for packet assembly.
5. Do not make Engine Surface responsible for route mediation.
6. Do not start multi-work board until this single-work exposure budget is stable.

## 7. Validation Standard

Pass if:

- shared spine reads as a thin orientation strip
- User first layer reads as assignment/decision, not evidence inspection
- VectorFL remains the detailed evidence/packet surface
- Engine first layer reads as process/return material, not mediation workspace
- no new surface or new feature is added
