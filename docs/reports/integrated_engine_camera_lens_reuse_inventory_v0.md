## 2. Current Lock

The fixed body remains:

- User surface
- VectorFL surface
- Engine surface

The body is not the growth surface. It is the stable organism.

Growth happens in two places:

- space grows by lines, connections, axes, traces, records, and sedimented memory
- engine grows by cameras, camera variations, lenses, and lens-to-surface projection rules

## 3. Working Terms

### Body

The fixed three-surface engine body.

### Camera

A process frame that decides how material passes through the engine. A camera is not just a screen frame. It is a reusable operating sequence.

### Lens

The interpretive purpose applied to a camera. A lens determines what object is being read.

### Space

The maturation field where records, documents, generated artifacts, misreads, lines, connections, axes, and traces accumulate.

## 6. Reuse Rule

Before making a new camera:

1. Search existing reports/specs/patch notes for a camera with the same process shape.
2. If the camera exists, reuse it.
3. If the process is mostly the same but object differs, keep the camera and change the lens.
4. If only one stage differs, make a camera variation.
5. If no existing process frame fits, create a new camera candidate and mark it as candidate, not baseline.

Before making a new lens:

1. Search existing language/line/validation/implementation/feedback docs.
2. If a lens exists, reuse it.
3. If the lens is too broad, narrow its object.
4. If a new object of reading appears, create a lens candidate.
5. Do not promote a lens until it survives at least one real use loop.

## 7. Relation To Token Economy

Reusing cameras and lenses saves tokens because the engine does not need to restate every process from scratch.

It also strengthens structure:

- repeated cameras become stable operating grammar
- repeated lenses become shared interpretation grammar
- generated artifacts become evidence for variation instead of waste

## 8. What Must Not Happen

- Do not treat every new task as a new panel.
- Do not treat every new loop as a new feature.
- Do not turn a lens into a surface.
- Do not hard-code the language-owner loop as the only meaning of the loop slot.
- Do not create new cameras without first reading existing camera candidates.
- Do not flatten space growth into UI content.

## 9. One-Line Lock

The engine body is fixed, space grows by lines and axes, and the engine grows by reusable cameras and lenses that must be found, varied, or lens-swapped before anything new is invented.
