# jump2 cross reread with jump, Claude Code, and OpenClaw v0

## 0. Why This Pass Matters

`jump2.txt`는 단순 업데이트 소개가 아니다.

이번 자료는 특히 아래를 강하게 말한다.

- `1M context`
- `max effort`
- plugin marketplace
- official vs unofficial trust boundary
- selective plugin intake
- skill / command / agent separation
- CLI preference over heavy MCP

즉 `jump_cleaned.txt`가
`하네스 + 훅 + 역할 + business pipeline`
쪽을 더 강하게 말했다면,

`jump2`는
`확장된 Claude Code operating surface를 어떻게 다뤄야 하는가`
를 더 강하게 말한다.

그래서 이 자료는 `jump_cleaned`, `claude-code-main`, `openclaw`와 함께 보면 의미가 훨씬 선명해진다.

---

## 1. What `jump2` Is Really About

표면에서는:

- 최신 업데이트 소개
- 플러그인 설치 실습
- 추천 플러그인 안내

처럼 보인다.

하지만 깊게 읽으면 중심은 다르다.

### A. Claude Code is getting more internal capacity

`1M context`, `max effort` 이야기는
그냥 성능 자랑이 아니다.

이 자료는 이걸:

- 더 많이 읽고
- 더 오래 기억하고
- 더 많이 추론하고
- 여러 단계 프로세스를 감당하는 능력

으로 해석한다.

즉 여기서 `Claude Code`는
기능이 많아진 도구가 아니라,
`더 긴 프로세스를 내부에서 감당할 수 있는 작업 기관`
으로 다시 읽힌다.

### B. plugin marketplace becomes controlled growth surface

플러그인 이야기도 단순 설치법이 아니다.

핵심은:

- marketplace를 먼저 가져온다
- 공식/비공식 마켓을 구분한다
- 아무거나 다 받지 않는다
- 필요한 것만 선택한다

이다.

즉 여기서 플러그인 마켓은
`기능 확장 면`
인 동시에
`통제된 intake boundary`
가 된다.

### C. Selection is more important than abundance

이 자료는 계속 말한다.

- 많이 있다고 다 깔지 말 것
- 필요한 것만 골라 넣을 것
- 조합을 잘못하면 탈 난다

즉 여기서 중요한 line은
`more tools`
가 아니라
`curated growth`
다.

### D. operational units are being separated

`skill`, `command`, `agent`, `plugin`, `CLI`, `MCP`
를 분리해서 설명하는 것도 중요하다.

이건 기능 목록이 아니라,
도구들을 `operating unit` 단위로 나누는 것이다.

특히:

- command는 직접 실행
- skill은 AI가 자율 활용
- agent는 역할화된 실행 주체

로 말하는 부분은
운영 계층을 정리하는 line이다.

### E. CLI is framed as lighter operational rail

`MCP는 트럭, CLI는 세단`
이라는 비유는 단순 설명이 아니다.

여기서 하고 싶은 말은:

- 모든 연결면이 같은 무게를 가지지 않는다
- 더 가벼운 rail이 실전 운영에는 더 유리할 수 있다
- 따라서 통합 방식도 선택적으로 가져가야 한다

는 것이다.

즉 이 자료는 integration 방식 자체를
운영 효율 line으로 읽는다.

## 2. Deep Lines Found In `jump2`

이번 pass에서 최소 아래 line들이 강하게 드러났다.

### 1. `capacity expansion changes what can be operationalized`

컨텍스트와 추론 확장은 단순 성능 향상이 아니라,
예전엔 구조로 보완해야 했던 걸 일부는 모델 안으로 끌어들일 수 있게 만든다.

이건 앞서 우리가 확인한
`좋은 모델이 나올수록 하네스는 더 단순해져야 한다`
는 `jump_cleaned`의 line과 직접 연결된다.

### 2. `plugin marketplace as controlled intake boundary`

플러그인 마켓은 기능 창고가 아니라
선택적 intake 구조다.

이건 우리 공간의
`reference selective adoption + deferred memory`
와 굉장히 잘 닿는다.

### 3. `official recognition as trust filter`

이 자료는 반복해서
공식 마켓/공식 플러그인만 우선하라고 말한다.

즉 확장성보다 먼저
`trust boundary`
가 온다.

이건 `openclaw`에서 보였던
approval, permission, risk surface와도 닿는다.

### 4. `tool abundance requires curation logic`

많은 plugin/skill이 있다고 좋은 게 아니라,
잘못 섞이면 탈이 난다고 말한다.

즉 line은
`tool expansion`
이 아니라
`curated composability`
에 있다.

### 5. `operational abstraction before use`

skill / command / agent / CLI / MCP를 구분해서 설명하는 방식은,
도구를 그냥 쓰는 게 아니라
먼저 운영 추상화 단위로 재해석하고 있다는 뜻이다.

이건 우리 공간에서 line을 operator/unit으로 자라게 하려는 방향과 연결된다.

### 6. `Claude Code as terminal-centered work substrate`

GWS CLI, 각종 CLI, terminal에서 더 많은 작업을 하게 될 것이라는 말은
Claude Code를 단순 코딩도구가 아니라
`terminal-centered work substrate`
로 읽고 있다는 뜻이다.

이건 `jump_cleaned`에서 보였던
`Claude Code as work substrate`
line의 더 기술적인 버전이다.

## 3. Comparison With `jump_cleaned`

둘은 겹치지만 초점이 다르다.

### `jump_cleaned`

더 강한 면:

- harness
- self-deception correction
- hook as conscience
- role embodiment
- business pipeline

즉 조직과 business 쪽이 더 강하다.

### `jump2`

더 강한 면:

- plugin market intake discipline
- curated extension
- skill/command/agent differentiation
- CLI-first practical integration

즉 확장 표면과 intake 규율이 더 강하다.

한 줄로 말하면:

- `jump_cleaned` = 회사 운영과 하네스 언어
- `jump2` = 확장 표면과 선택적 intake 언어

둘은 합쳐져야 한다.

## 4. Comparison With `claude-code-main`

`claude-code-main`에서 우리가 강하게 읽은 건:

- pluginized operating surface
- hook-mediated behavior shaping
- agent/command packaging

이었다.

`jump2`는 이걸 사용자/운영 언어로 다시 말해 준다.

즉 `claude-code-main`이
구조를 코드와 surface packaging으로 보여줬다면,

`jump2`는

- 어떤 plugin은 왜 가져와야 하는지

를 사람이 이해할 수 있는 운영 말로 풀어준다.

그래서 `jump2`는
`claude-code-main`의 practical reading guide처럼도 읽힌다.

## 5. Comparison With `openclaw`

`openclaw`는 더 깊은 runtime organ body를 보여준다.

하지만 `jump2`는

왜냐하면 이 자료는 이미:

- plugin intake risk
- trust boundary
- integration weight
- tool selection pressure

를 반복해서 말하고 있기 때문이다.

즉 `openclaw`가
이 문제를 code body로 만든 사례라면,

`jump2`는
그 문제를 사용/운영 차원에서 느끼게 만드는 사례다.

## 6. What This Reveals About Our Space

`jump2`를 우리 공간 기준으로 보면 중요한 게 세 가지다.

### A. our reference intake philosophy is directionally right

우리는 이미:

- reference 전체를 복제하지 않고
- 필요한 것만 가져오고
- not needed가 아니라 not yet로 기억하고
- deferred reason memory를 남기자

고 정리했다.

이건 `jump2`의
`아무거나 다 설치하지 말고 필요한 것만`
과 강하게 닿는다.

즉 이 자료는 우리 reference philosophy가 맞는 방향이라는 걸 더 강화해 준다.

### B. our space still lacks a strong public operating surface

우리는 이런 분별력은 꽤 자라고 있는데,
그걸 실제 사용자/조직 언어로 보여주는 operating surface는 아직 얇다.

`jump2`는 그 얇음을 드러낸다.

즉 우리는 안쪽 철학은 강하지만,
`설치/선택/활용/운영 판단`을 실제 작업 표면으로 보여주는 면은 아직 약하다.

### C. our future growth will need both maturity and selective packaging

`jump_cleaned`가 보여준 건
하네스와 business pipeline이었다.

`jump2`가 보여준 건
capacity-aware selection and packaging이다.

즉 나중에 우리 공간이 몸체화되려면:

- line 숙성
- hook/inspection
- role embodiment

뿐 아니라

- selective plugin/component packaging
- trust-filtered intake
- light-vs-heavy integration choice

도 같이 자라야 한다.

## 7. Human-Language Meaning Reread

`jump2`를 내 말로 다시 잡으면 이렇다.

이 자료는 최신 기능 소개를 하는 것처럼 보이지만, 실제로는 Claude Code라는 작업면이 점점 더 커질 때 사람은 그것을 어떻게 다뤄야 하는지를 말하고 있다. 컨텍스트가 커지고 추론이 세지면 더 많은 걸 맡길 수 있게 되지만, 그만큼 아무 기능이나 덕지덕지 붙이면 오히려 탈이 난다. 그래서 이 자료는 “많이 붙여라”가 아니라 “무엇을, 어떤 경계 안에서, 어떤 신뢰 기준으로, 얼마나 가볍게 붙일 것인가”를 계속 말한다. 즉 plugin marketplace도 자유 시장이 아니라 선택적 intake의 경계면이 되고, skill/command/agent 차이도 단순 기능 구분이 아니라 운영 단위의 차이로 읽힌다.

이 점에서 `jump2`는 `jump_cleaned`와 짝을 이룬다. `jump_cleaned`가 AI를 회사의 일과 역할과 파이프라인으로 내려보내는 언어였다면, `jump2`는 그 일을 가능하게 만드는 확장 표면을 어떻게 선택적으로 관리해야 하는지를 말하는 언어다. 그리고 이 둘을 `claude-code-main`, `openclaw`와 함께 놓고 보면 더 분명해진다. 우리는 결국 line이 충분히 숙성된 뒤에야 body와 surface를 가져야 하지만, 그때도 무한 확장이 아니라 신뢰 경계, 조합 규율, 가벼운 rail 선택 같은 기준이 같이 붙어야 한다는 것이다. 그래서 `jump2`는 단순 업데이트 자막이 아니라, 우리 공간이 나중에 어떤 방식으로 부품을 받아들여야 하는지 미리 보여주는 꽤 중요한 selective growth reference다.

---

## 8. One-Line Conclusion

`jump2`는 최신 Claude Code 소개가 아니라, 확장된 AI work surface를 `공식성`, `선택적 intake`, `operating unit 분리`, `가벼운 integration rail` 기준으로 관리해야 한다는 점을 드러내는 자료이며, 그 점에서 `jump_cleaned`, `claude-code-main`, `openclaw`를 연결해 우리 공간의 future selective embodiment 방향을 비추는 강한 reread 재료다.
