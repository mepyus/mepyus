# Space-CLI Lightweight Attachment Reflux Package v0

## 1. package purpose

This package is not a CLI execution setup.

It does not design a bridge, JSON return system, automation script, runtime structure, verification packet store, or controller.

This package is a structured thought-experiment for testing what changes when the space is lightly attached before and after a CLI.

Core question:

```text
Can the space provide only the needed line, axis, relation, flow, guardrail, and memory before CLI work,
then reread the CLI result and reflux useful differences back into future space behavior?
```

The space should not become a device that reads everything.

The space should become a device that retrieves the smallest useful memory for the current input.

## 2. basic structure

```text
user input
-> space input surface
-> space reading surface
-> line / axis / relation / flow / guardrail search
-> lightweight work packet
-> CLI answer / execution / implementation
-> result recovery
-> native CLI result vs space-referenced result comparison
-> diff / merge / missing / overreach reading
-> reflux memory formation
-> user-facing return
```

This is not a new automatic pipeline.

It is a thought structure for reading how space context changes CLI behavior and how the resulting difference becomes future material.

## 3. role of the space

The space does this:

- reads the character of the user input
- judges the source surface
- finds relevant lines, axes, relations, flows, and guardrails
- retrieves memory cards and pointers before full source reading
- forms a lightweight task packet for the CLI
- rereads CLI output as `worker_return`, `generated_report`, `runtime_event`, or another source surface
- compares CLI native output against space-referenced output
- refluxes useful difference into maturation material
- returns a short user-facing judgment card

The space should prefer:

```text
small memory card
specific pointer
short guardrail
bounded expected output
```

over:

```text
whole repository
full onboarding
all related documents
long philosophy replay
previous conversation dump
```

## 4. role of the CLI

The CLI does not replace the space.

The CLI may do:

- answer
- execute
- implement
- verify
- draft
- summarize
- file-level work
- test execution

The CLI must not:

- become the final judge of the space
- lock the baseline
- change the space structure by itself
- finalize reflux memory
- treat its own PASS as proof of completion
- convert a lightweight packet into broad architecture work

## 5. core difference

Plain CLI:

```text
question
-> answer / execution
-> end
```

Space-attached CLI:

```text
question
-> space reading
-> lightweight work packet
-> CLI execution
-> result recovery
-> difference reading
-> reflux memory
-> changed next-space behavior
```

The important output is not only the CLI answer.

The important output is:

```text
answer + difference + reflux candidate
```

## 6. success criteria

This structure succeeds when:

- the space does not reread everything every time
- only needed lines, axes, and memory cards are retrieved
- the CLI receives a minimal task packet
- the result is not read as a simple completion report
- difference becomes maturation material
- user-facing output stays compact
- internal source surface and reflux labels remain internal by default

## 7. default user-facing return

```text
쓸 수 있나?
왜?
다음엔?
조심할 점은?
```

This card is the user return surface.

The internal reflux labels are not the default user language.
