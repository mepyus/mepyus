## Shared reading frame

이 세 문서는 서로 다른 주제를 다루지만 같은 순서로 읽어야 한다.

1. 공간은 단순 저장소가 아니라 이해 기반 추론 공간이다.
2. active asset 판정은 `binding closed -> semantic fidelity -> output-worthiness -> meaning-context sufficiency -> detector -> widening trigger` 순서로 읽는다.
3. `narrow mechanism closure detector + widening trigger v1.1`은 broad rule이 아니라 감독 기준 후보다.
4. 첫 실행물로 control plane, current phase, breadcrumbs, ChatGPT tendency profile의 바닥을 만들었다.
5. 이어서 interpretation packets, decision lineage, multi-lens views의 첫 뼈대를 세웠다.
6. 이어서 implementation placement로 정의 / 로그 / 요약 / evaluator의 표면을 분리했다.
7. 그 위에 minimal soft layer separation과 order structure로 역할과 순서를 소프트 분리했다.

## Why this matters

이 세 문서를 따로 보면 각각:

- 공간 철학
- active asset 재판독
- detector contract 채택

처럼 보인다.

하지만 함께 보면 다음이 하나의 흐름으로 묶인다.

- 어떤 공간을 만들고 있는가
- 그 공간을 어떤 기준으로 읽는가
- 그 기준을 어떤 사례로 검증했는가

즉 오늘의 작업은 구현 자체보다, 이후 모든 active asset 판정과 saved_connection reread를 같은 감독 렌즈로 읽기 위한 기준 고정이었다.
