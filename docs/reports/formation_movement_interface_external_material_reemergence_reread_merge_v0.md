## 4. what was found

The user-facing feeling was:

```text
오늘 입력한 재료 2개도 다시 안 찾아짐.
```

The actual repository state is:

- the materials are present as source folders, external case notes, Gemini analysis, and reports
- several materials already have validation or comparison notes
- some materials are already merged into clusters
- there is no single small re-emergence index that says “when this kind of question appears, reread these materials first”

So the usability problem is real:

```text
자료 보존은 됐지만, 재부상 경로가 약함.
```

## 5. process-first reread

The correct order is not:

```text
external material
→ classify from scratch
→ decide later whether it applies
```

The healthier order is:

```text
external material
→ check existing internal line / axis / lens
→ identify first process-stage contact
→ assign safe provisional state
→ compare or hold
→ return to space
```

Existing internal lines that should be checked first:

1. Codex prepare / execution gate
2. external ingest / comparison-frame line
3. validation gate / return line
4. workflow controller / worker-role elevation line
5. formation-side accumulation / movement-side execution line
6. A/B/C/T/X/R/L overlap line

## 9. what this says about the current bottleneck

The current bottleneck is not only “how to ingest external material.”

It is:

```text
how external material re-emerges at the right later moment without the user manually remembering the file, source, previous judgment, line, lens, and safe next move.
```

The previous package works as a safety device.

But for daily usability, it needs a lighter operational habit:

```text
when a new material or question appears,
first check whether it touches an existing re-emergence pack.
```

This does not require a new schema yet.

It requires a small retrieval habit:

```text
alias
source path
current state
line / lens
safe next move
do-not-cross line
```
