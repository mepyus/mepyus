# 선언문 — question-inducing block candidate와 summary priority shift 현재 잠금

## 0. 목적

이 문서는 다음 단계로 바로 넘어가기 전에,
`youtube_03_22.md` 반복 실험에서 확인된 현재 읽기를 짧게 잠그기 위한 선언문이다.

목적은 새 구조를 설계하거나 일반 법칙으로 승격하는 것이 아니다.

이번 선언은 아래 두 점만 정리한다.

1. `youtube_03_22.md`에는 실제로 다음 질문을 여는 block candidate가 존재한다
2. residue 문제는 hard suppression이 아니라 summary-stage priority shift로 다루는 것이 맞다

---

## 1. 현재 잠금

### 1-1. question-inducing block candidate

아래 구간은 단순 high-score summary block이 아니라
**다음 탐색을 여는 응축핵 후보**로 읽는다.

- `84_91`, `80_87`
  - bundle-unbundle
  - 기존 앱 대체
  - moat
  - workflow 전환
- `21_26`, `20_27`
  - 일의 미래
  - 감독자형 노동
  - 생산성/코딩 전환
- `32_39`
  - RLVR / CUA
  - 모델 경쟁
  - 평가/환경 이동

즉 현재 읽기는 아래다.

> `youtube_03_22.md` 안에는 단순 정보 밀도가 높은 문단이 아니라,
> 객체 성장과 다음 질문 발생을 동시에 수행하는 block candidate가 실제로 존재한다.

### 1-2. residue handling

현재 residue는 아래처럼 읽는다.

- `discourse_connective_residue`
  - 예: `그래서`
- `speaker_or_source_residue`
  - 예: `노정석`, `Benedict`
- `conversational_filler_residue`
  - 예: `저희가`

하지만 이 값들은 지금 단계에서 삭제 대상이 아니다.

현재 운영 판정:

- hard suppression: `NO`
- axis change: `NO`
- broad probe disturbance: `NO`
- summary-stage priority shift: `YES`

즉 지금 해야 할 일은
문서 전체에서 residue를 지우는 것이 아니라,
**opening summary 선두에서만 뒤로 미는 bounded surface adjustment**다.

## 2. 지금 당장 하지 않는 것

이번 선언은 아래를 열지 않는다.

- axis refactor
- scene / flow / role 개편
- question-inducing 체계 일반화 잠금
- residue hard suppression
- 사전류 / 백과사전류 투입
- broad concept probe 구조 변경
