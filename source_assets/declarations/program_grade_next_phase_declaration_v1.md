## 0. 선언 목적

이 선언문은
현재 엔진을 프로그램 단으로 승격시키는 시작선 위에서,
앞으로 무엇을 우선하고 무엇을 보류할지에 대한
**운용 방향 선언**이다.

이 문서는 당장 실행 지시를 내리기 위한 문서가 아니다.
우리가 앞으로 어떤 질서로 움직일 것인지,
무엇을 먼저 단단히 만들고 무엇을 나중으로 미룰 것인지를
Codex와 공유하기 위한 **상위 학습/방향 선언문**이다.

## 1. 현재 위치 선언

우리는 아직 완성 단계에 있지 않다.
지금은 **프로그램 단으로 승격해도 될 만큼의 외곽 질서가 보이기 시작한 상태**다.

즉 현재 상태는 다음과 같이 선언한다.

- 임시 파이프라인 묶음에서 벗어나기 시작했다
- 입력 / 기준 / 표면 / 배치 / 기록의 역할이 보이기 시작했다
- 내부 코어를 크게 개조하지 않고도 운용 가능한 외곽 제어력이 생기기 시작했다
- shared reality를 위한 최소 문서 세트가 보이기 시작했다

그러나 동시에 다음도 분명히 선언한다.

- 이것은 완성이 아니다
- 이것은 시작선이다
- 프로그램 단 승격은 도착이 아니라 바닥 확보다
- OS 베이스나 더 큰 운영구조로 가기 위해서는 아직 많은 층위가 남아 있다

## 2. 핵심 운영 철학 선언

### 2-1. 내부 코어는 당분간 보존한다
현재 단계에서 엔진 내부 구조를 대대적으로 변경하지 않는다.
내부 기관은 쉽게 흔들지 않는다.

우리는 아직 내부에서 어떤 값들이 어떻게 생겨나는지
완전히 해부하지 못했다.
따라서 지금 단계의 기본 태도는
**코어 개조보다 코어 보존**이다.

### 2-2. 입구와 표면을 먼저 정리한다
지금 우리가 우선적으로 다루는 것은
입력 레인, 표준문서, 외부자료 intake, current map, delta log,
read surface, shared reality pack 같은
**입구와 표면과 바깥 골조**다.

현재 우리의 제어력은
코어 내부보다 이 외곽 구조에서 먼저 확보된다.

### 2-3. 조정은 처리된 값을 근거로 한다
우리는 내부 구조를 추측으로 바꾸지 않는다.
먼저 처리된 값이 표면에서 어떻게 드러나는지 본다.
그 결과를 보고 어디가 부족한지 판단한다.

즉 우리의 조정은:

- 느낌 기반 조정이 아니라
- 처리 결과 기반 조정이며
- 관찰된 부족을 입구와 표면에서 먼저 흡수하는 방식이다

### 2-4. 기록은 미래 미세 조정의 근거다
intake 기준, current map, delta log, shared reality 문서들은
단순 정리문이 아니다.

이 문서들은 나중에 다음 질문에 답하기 위한 근거층이다.

- 왜 이 조정이 필요했는가
- 어떤 입력에서 혼선이 반복되었는가
- 어떤 표면이 현실을 충분히 보여주지 못했는가
- 어떤 변화가 구조 차원의 문제였고 어떤 변화가 외곽 조정이었는가

즉 지금의 기록은
**미래의 미세 조정을 위한 관측 근거**로 선언한다.

## 3. 표준문서와 외부자료의 역할 선언

### 3-1. 표준문서는 기준 근거다
표준문서는 단순 설명문이 아니다.
그 안에는 의미, 맥락, 의도, 과정, 결과, 목적이 압축되어 있다.

따라서 표준문서는
엔진 운용의 기준과 근거를 잡는 재료로 선언한다.

즉 표준문서는:

- 방향을 붙잡는 문서
- 기준을 세우는 문서
- 반복 운용의 고정축이 되는 문서
- Codex가 구조를 이해할 때 우선 학습해야 하는 문서

로 취급한다.

### 3-2. 외부자료는 조정 근거다
외부자료는 바로 코어를 흔들기 위한 것이 아니다.
외부자료는 현재 기준이 실제 운용에서 어떻게 드러나는지 보고,
어디를 미세 조정해야 하는지 알려주는 사례 재료다.

즉 외부자료는:

- 기준을 세우는 재료가 아니라
- 기준을 시험하고
- 표면과 intake의 부족함을 드러내고
- 조정 포인트를 관찰하게 하는 사례 재료

로 선언한다.

### 3-3. 기준과 조정을 분리한다
우리는 다음을 분명히 분리한다.

- **기준 근거는 표준문서에서 잡는다**
- **조정 근거는 외부사례에서 얻는다**

이 분리를 통해
외부사례의 유행이나 수사에 기준이 끌려가지 않도록 한다.

## 4. 현재 단계의 최우선 과제 선언

현재 우리의 최우선 과제는
기능을 급히 늘리는 것이 아니다.
또한 내부 코어를 개조하는 것도 아니다.

현재 단계의 최우선 과제는 아래와 같이 선언한다.

### 4-1. intake 반복 안정화
AI 관련 외부자료와 표준문서를 계속 넣으면서
현재 intake 구조가 반복 운용에서 버티는지 확인한다.

### 4-2. shared reality 문서의 실운용화
current_asset_map, repo_delta_log, pack index는
문서가 아니라 실제 운영 표면이 되어야 한다.

### 4-3. latest / raw / work 경계 강화
정돈되지 않은 구조는 확장이 아니라 증식으로 간다.

## 5. 앞으로의 단계적 전개 선언

### 1단계 — intake와 shared reality의 반복 운용
먼저 외부자료와 표준문서를 계속 투입하며
현재 프로그램 단 외곽 구조를 반복적으로 사용한다.

### 2단계 — read-only 운용화면 v0
shared reality와 intake가 일정 수준 안정되면,
그 위에 사람이 빠르게 현재 상태를 읽을 수 있는
**read-only 운용화면 v0**를 만든다.

### 3단계 — 페이지 단 진입
운용화면 v0가 반복 운용에서 유효하다고 확인된 뒤에야
페이지 단으로 넘어간다.

## 6. 금지 및 보류 선언

- 내부 코어를 충분한 관찰 근거 없이 대대적으로 개조하는 것
- 외부사례를 곧바로 기준으로 승격하는 것
- 페이지를 너무 빨리 제품처럼 만드는 것
- shared reality 문서를 형식 문서로만 두고 실제 갱신하지 않는 것
- read surface가 raw를 대체하게 두는 것
- 입력이 늘어난다는 이유로 lane이나 기준문을 무분별하게 증설하는 것

## 7. 구조 정돈에 대한 선언

우리는 정돈된 구조를 단순 미관으로 보지 않는다.
정돈된 구조는 제어력이며, 수정 범위를 제한하는 경계이며,
프로그램 단 승격의 전제조건이다.

즉 우리는
**구조 정돈을 프로그램 단 승격의 최소 조건으로 선언한다.**

## 8. Codex 학습을 위한 핵심 선언 문장

- 현재 엔진은 내부 코어 개조보다 외곽 안정화가 우선이다.
- 표준문서는 기준 근거이며, 외부자료는 조정 근거다.
- 입력 증가를 버티기 위해 intake lane과 shared reality를 먼저 단단히 만든다.
- current map과 delta log는 형식 문서가 아니라 실제 현재 현실면과 변화면이다.
- 운용화면은 페이지보다 먼저 오며, 페이지는 안정된 운용면 위에 세워진다.
- 지금의 목표는 새 기능 남발이 아니라 프로그램 단 구조의 안정화다.

## 9. 최종 선언

우리는 현재 엔진을
“완성된 프로그램”으로 선언하지 않는다.
대신
**프로그램 단으로 승격시켜도 될 만큼의 외곽 질서가 생긴 상태**로 선언한다.

그리고 앞으로의 방향을 다음과 같이 최종 선언한다.

**내부 코어는 당분간 보존하고,
표준문서를 기준 근거로, 외부자료를 조정 근거로 삼아,
intake와 shared reality를 반복 운용으로 단단히 만들고,
그 위에 read-only 운용화면을 세운 뒤,
충분한 안정성이 확인되면 페이지 단으로 넘어간다.**

이 선언은
지금 당장 실행하라는 지시가 아니라,
앞으로 Codex와 함께 엔진을 학습시키고 운용할 때
흔들리지 않을 상위 방향으로 사용한다.
