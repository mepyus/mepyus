# CODEx 지시서 — 2차 보정 스크립트 축적 구조 정비 / 비교 도메인 투입 / object lift 전단 준비

## 0. 목적

이번 턴의 목적은 2차 보정 스크립트를 더 똑똑한 판정기로 만드는 것이 아니다.

이번 턴의 목적은 아래 3가지를 준비하는 것이다.

1. 현재 2차 보정 스크립트를 **잘 읽는 기계보다 잘 모으는 기계** 로 재정렬한다.
2. 비교용 새 도메인 1개를 준비해 **도메인 특화 신호와 반복 가능한 보정 태도** 를 분리할 준비를 한다.
3. 미래 `second_order_object_lift` 직전 단계에 필요한 **중간 정리판** 들을 설계한다.

즉 이번 작업은
**2차 보정 결과를 축적 가능 / 비교 가능 / 보류 가능 / 승격 준비 가능 구조로 정리하는 것** 이다.

---

## 1. 핵심 원칙

- 지금 2차 스크립트의 성공 기준은 “무엇을 맞혔는가”가 아니라 “무엇이 어떤 조건에서 나왔는가를 얼마나 잘 남겼는가”다.
- 지금은 object lift 본 구현을 하지 않는다.
- `business_power_shift`, `orchestration`, `domain_to_component_reframing` 같은 이름은 보편 객체로 잠그지 않는다.
- 반복 패턴, 도메인 특화 의심, 재사용 가능한 보정 태도를 먼저 분리한다.

---

## 2. 이번 턴 산출물 방향

- 2차 보정 스크립트 출력의 공통 축적 필드 강화
- 비교 도메인 실험 준비 노트
- repeated second-order pattern table 초안
- domain-specific vs reusable split note 초안
- object-lift candidate registry 초안
- 숙성 상태를 감독하는 운용화면 표면 정의 노트

---

## 3. 한 줄 최종 지시

> 현재 2차 보정 스크립트는 일반화 판정기로 밀지 말고, 2차 보정 사례를 구조적으로 잘 남기는 축적기로 재정렬하라. 그 위에서 비교 도메인 1개를 준비하고, repeated second-order pattern table / domain-specific vs reusable split note / object-lift candidate registry / 운용화면 표면 정의를 object lift 직전 전단으로 설계하라.
