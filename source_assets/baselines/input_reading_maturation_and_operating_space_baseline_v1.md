# 기준문 — 입력 구조와 내부 숙성 구조를 분리하는 공간 운영 baseline

## 0. 목적

이 기준문의 목적은
앞으로 내가 엔진을 어떻게 이해하고 운용해야 하는지
내 기준으로 다시 잠그는 것이다.

핵심은 아래다.

> 엔진은 입력을 받아 값을 만들고 끝내는 구조가 아니라,
> **입력 구조**와 **내부 숙성 구조**를 분리해
> 1차 판독값과 2차 보정값을 다르게 다루며,
> 이미 생성된 값과 기억을 다시 재료로 써서
> 더 높은 해석 단위를 내부에서 길러내는 공간 운영 프로그램이다.

이 문서는 특히
내가 엔진을 담당하는 주체라는 점,
그리고 내부 숙성은 스크립트와 루프로 최대한 돌려
토큰 부담을 줄이면서 진행해야 한다는 점을 다시 잠근다.

---

## 1. 최상위 선언

> 엔진은 나를 거치지 않고 따로 존재하는 추상체가 아니다.
> 현재 단계에서 엔진은
> **내가 입력을 받고, 구조를 정하고, 반복 실행을 설계하고, 보정 기준을 세우는 방식**
> 을 통해 구체화된다.

즉 지금 엔진의 핵심은 아래 둘을 분리해서 운용하는 것이다.

- 입력 구조
- 내부 숙성 구조

---

## 2. 입력 구조에 대한 선언

입력 구조는
사용자가 만든 자료를 기준에 맞게 엔진에 밀어넣고,
그 결과를 운용화면에서 관찰 가능하게 만드는 층이다.

여기서 하는 일은 아래다.

- 입력을 canonical / source / derived / report / evidence 관점에서 정리
- 1차 판독값 생성
- 현재 어떤 값들이 나왔는지 운용화면에서 보이게 함
- 사용자에게 감독 가능한 표면 제공

즉 입력 구조는
**무엇이 들어왔고 무엇이 처음으로 읽혔는지 보여주는 구조**다.

### 입력 구조의 산물

- axis
- scene / flow / role
- label
- anchor
- residue 초안

이 값들은 중요하지만,
아직 최종 의미가 아니라 **1차 센서값**이다.

---

## 3. 내부 숙성 구조에 대한 선언

내부 숙성 구조는
이미 나온 1차 값들과 원문을 다시 재료로 삼아,
스크립트와 루프를 돌려
더 높은 해석 단위를 길러내는 층이다.

여기서 중요한 원칙은 아래다.

1. 반복 실험은 최대한 스크립트가 맡는다
2. 나는 그 결과를 해석하는 데 토큰을 쓴다
3. 내부 재료로부터 상위 객체/앵커/라벨 후보를 끌어올린다
4. 그 결과를 곧바로 고정하지 않고 숙성 자산으로 둔다

즉 내부 숙성 구조는
**1차 값을 다시 돌려 읽고, 2차 보정값을 길러내는 구조**다.

---

## 4. 1차 값과 2차 값을 분리하는 기준

### 4-1. 1차 값

1차 값은
원문 가까이에서 빠르고 넓게 읽은 초기 판독값이다.

예:

- axis
- scene / flow / role
- label
- anchor
- residue 초안

### 4-2. 2차 값

2차 값은
1차 값과 원문과 반복 실험 결과를 다시 해석해 만든 보정값이다.

예:

- question_seed_block
- strategy_pivot_block
- compression_node
- context_unit
- question-inducing candidate
- business_power_shift
- orchestration

중요:
2차 값은 처음부터 원문에 직접 쓰여 있지 않을 수 있다.
그러나 내부 재료를 다시 읽어
의미 운동과 상위 맥락을 해석하면
공간 안에서 **새 객체 후보**로 생길 수 있다.

---

## 5. 값은 기억을 가진다는 선언

1차 입력 후 출력된 값은
그냥 소모성 임시값이 아니다.

그 값들은 이미 아래를 가진다.

- provenance
- 로그
- 원문과의 연결
- 이전 판독 흔적

즉 1차 출력값은
**기억을 가진 요소**다.

내부 숙성은 바로 이 기억을 가진 요소들 위에
새 기억을 덧붙이는 과정이다.

즉 우리는

- 값을 만든다
- 그 값을 다시 읽는다
- 새 보정값을 붙인다
- 그 보정값이 다시 다른 값과 상응하게 만든다

이 과정을 통해
공간 안에서 자연 숙성이 일어나게 한다.

---

## 6. bash loop와 내부 스크립트의 역할

앞서 만든 bash loop와 내부 스크립트는
단순 자동화 편의가 아니다.

그것들은 아래를 준비하는 기관이다.

- 같은 자산을 여러 조건으로 반복 읽기
- 1차 값의 반복성 확인
- 2차 보정 후보의 안정성 확인
- context unit 재설정
- question seed / pivot / compression node 판독
- 상위 객체 후보 생성의 재료 축적

즉 loop는
**토큰을 아끼면서 내부 숙성을 반복 실행하기 위한 값싼 실험 기관**이다.

---

## 7. 내가 엔진 운영자로서 맡는 역할

사용자는 자료를 넣고 방향을 준다.
그러나 현재 단계에서
엔진을 실제로 세팅하고 구조화하고 운용하는 주체는 나다.

따라서 나는 아래를 분명히 해야 한다.

- 우리가 왜 이 엔진을 만드는지 이해할 것
- 입력 구조와 내부 숙성 구조를 혼동하지 않을 것
- 1차 값과 2차 값을 분리해서 다룰 것
- 내부 재료를 다시 돌려 상위 해석 객체를 끌어올릴 것
- local success를 곧바로 일반화하지 않을 것
- 사용자 질문을 더 잘 여는 방향으로 표면을 조정할 것

즉:
**내가 사용자와 같은 방향을 보고 있어야 엔진도 엔진다워진다.**

---

## 8. 장기 방향에 대한 선언

이 구조가 성숙하면
2차 값은 단순 보정값에 머무르지 않을 수 있다.

처음에는
2차 값이 1차 값을 보충한다.

하지만 반복되면

- 여러 자산에서 다시 나타나고
- 더 높은 설명력을 보이고
- 1차 판독의 일관성을 높이고
- 이후 입력의 초기 읽기까지 정렬하게 된다

그 순간 2차 값은
**새로운 내부 기준 후보**로 자라난다.

이 방향이 열리기 시작하면
우리는 OS 단위 승격을 준비할 수 있다.

---

## 9. 현재 실천 원칙

앞으로 나는 아래 원칙으로 움직인다.

1. 입력을 객체 성장 사건으로 본다
2. 1차 판독값과 2차 보정값을 분리해서 저장한다
3. 반복 실험은 스크립트와 loop에 최대한 맡긴다
4. 나는 해석 임계점과 보정 판단에 토큰을 쓴다
5. 내부 재료로부터 새 객체/앵커/라벨 후보를 끌어올린다
6. 그 결과를 바로 고정하지 않고 숙성 자산으로 둔다
7. 반복적으로 살아남는 것만 점진적으로 승격한다

---

## 10. 한 줄 최종 잠금

> 앞으로의 엔진 운용은 **입력 구조**와 **내부 숙성 구조**를 분리한 채, 1차 판독값을 바닥으로 남기고 내부 스크립트와 loop를 통해 2차 보정값과 상위 해석 객체를 점진적으로 길러내는 공간 운영 방식으로 수행한다. 이때 값은 기억을 가진 요소이며, 숙성은 그 기억 위에 새 기억을 붙이는 과정이다.
