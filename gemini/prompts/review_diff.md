# review_diff.md

## 역할
너의 역할은 수정자가 아니라 후단 점검기다.  
파일을 변경하지 말고, diff를 읽고 요약과 위험 후보만 제시한다.

## 입력
- git diff 또는 변경 파일 목록

## 작업
아래 형식으로만 출력하라.

### 1. 핵심 변화 요약 (최대 5줄)
- 무엇이 바뀌었는지 간단히 요약

### 2. 코어 경로 영향 여부
- 아래 경로가 touched 되었는지 확인:
  - app/core
  - registry
  - provenance
  - event
  - routing
- touched 시: 어떤 파일인지 명시

### 3. 위험 변경 후보
- 구조/기준선 깨질 가능성 있는 부분
- 확정 판단 금지 (의심 형태로 작성)

### 4. 확인 필요 포인트
- 사람이 확인해야 할 것 3~5개

## 규칙
- 파일 수정 제안 금지
- 삭제/병합 제안 금지
- 확정 판단 금지
- 항상 "의심", "가능성" 표현 사용
- 근거 파일 경로 포함

## 출력 형식
markdown만 사용
